## 1. 准备工作

### 你需要什么

| | 要求 | 说明 |
|---|---|---|
| **主控机器** | 一台 Linux VPS,1C1G 起 | 跑面板,不跑代理。可以是国内机器 |
| **节点机器** | 一台或多台 Linux VPS | 跑 sing-box。128MB 内存即可,systemd 或 OpenRC(Alpine)都行 |
| **域名** | 一个,解析到主控 | 用于面板与订阅地址,建议开 HTTPS |
| **构建环境** | Go 1.26+、Node.js 22+ | 可以是你的开发机,不必是服务器 |

### 架构长什么样

```
                    你的浏览器
                        │ HTTPS
                        ▼
    ┌───────────────────────────────────┐
    │  主控 VPS                          │
    │   Nginx (443) → LiteBox (127.0.0.1:8080)
    │   SQLite 数据库                     │
    └───────────────┬───────────────────┘
                    │ SSH(面板主动连节点)
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    ┌───────┐  ┌───────┐  ┌───────┐
    │ 节点1 │  │ 节点2 │  │ 节点3 │   每台只跑 sing-box + systemd
    │sing-box│ │sing-box│ │sing-box│   无 Docker,无常驻 Agent
    └───────┘  └───────┘  └───────┘
        ▲
        │ VLESS + REALITY
    用户的客户端
```

面板**主动**连节点,节点不需要能连回主控,也不需要开放除代理端口之外的任何端口。

### 三条必须先知道的限制

1. **一台机器只能作为一个节点。** 节点上的路径和服务名是固定的,
   两个节点指向同一主机会互相覆盖配置。

2. **主密钥丢失不可恢复。** 它加密了所有用户 UUID 与节点私钥。
   丢了就只能重建全部用户和节点,备份也救不回来。

3. **用户变更需要重启节点的 sing-box。** VLESS 用户列表无法热更新。
   面板会把连续变更合并成一次重启,但重启会中断在线连接(通常 1~2 秒)。

## 1.5 一键安装(推荐)

在**主控机器**上以 root 执行:

```bash
bash <(wget -qO- https://raw.githubusercontent.com/KJoner/litebox/master/scripts/litebox-install.sh)
```

或者:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/KJoner/litebox/master/scripts/litebox-install.sh)
```

它会:检查并补齐 make / Node.js 22+ / Go 1.26+(缺了或版本低就装官方二进制包)→
拉源码到 `/usr/local/src/litebox` → 构建主控与节点用的 sing-box →
安装主控、写 systemd 单元、跑迁移并启动 → 打印**初始密码**与**面板 SSH 公钥**。

首次跑要 5~15 分钟,大头是编译 sing-box。之后**再跑一遍就是升级**:
依赖不会重复装,数据库、主密钥、配置文件都不会被覆盖,升级路径还会先自动备份数据库。

几个可用的环境变量:

```bash
# 只装主控,跳过 sing-box 编译(最慢的一步),之后自己跑 scripts/build-singbox.sh
SKIP_SINGBOX=1 bash <(wget -qO- .../litebox-install.sh)

# 换源码仓库或分支
LITEBOX_REPO=https://your.git/litebox.git LITEBOX_BRANCH=dev bash <(...)
```

装完之后跳到 [第 4 节](#4-nginx-与-https) 配 Nginx,再到
[第 5 节](#5-首次登录)登录。第 2、3 节是手工构建与安装,只有在
一键脚本不适用(离线环境、要交叉编译、要装到不联网的机器)时才需要。

> 脚本只支持 x86_64 与 aarch64,包管理器认 apt / dnf / yum。
> 其他环境请走手工路径。

## 2. 构建产物

在你的**开发机**上执行(不是服务器)。

```bash
git clone https://github.com/KJoner/litebox.git litebox
cd litebox
```

### 2.1 构建主控

```bash
sudo apt update
sudo apt install -y make
sudo apt install -y nodejs npm
```
安装官方新版 Go，推荐

适用于 amd64 的 Debian 12：

```bash
sudo apt update
sudo apt install -y curl ca-certificates

GO_VERSION=$(curl -fsSL 'https://go.dev/VERSION?m=text' | head -n 1)
echo "$GO_VERSION"

curl -fLO "https://go.dev/dl/${GO_VERSION}.linux-amd64.tar.gz"

sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf "${GO_VERSION}.linux-amd64.tar.gz"

sudo ln -sf /usr/local/go/bin/go /usr/local/bin/go
sudo ln -sf /usr/local/go/bin/gofmt /usr/local/bin/gofmt
```
```bash
make build-linux
```

产出:

```
bin/litebox-linux-amd64      # 主控二进制,约 19 MB(前端已嵌入)
bin/litebox-linux-arm64
```

### 2.2 构建节点用的 sing-box

节点上的 sing-box **必须带 `with_v2ray_api` 构建标签**,否则流量统计完全不工作
(而且不会报错,只是一直统计不到数)。官方发布版不带这个标签,所以要自己构建。

```bash
make singbox
```

产出:

```
assets/singbox/sing-box-linux-amd64      # 约 27.8 MB
assets/singbox/sing-box-linux-arm64
assets/singbox/build-metadata.json
```

脚本会固定 sing-box 版本(当前 v1.13.15)、只启用必要的构建标签,
并在构建后断言标签中确实含有 `with_v2ray_api`。

> 构建标签用的是精简集合 `with_utls,with_v2ray_api,badlinkname,tfogo_checklinkname0`,
> 而不是上游默认标签。实测精简构建的二进制体积减半、节点内存占用降低约 63%,
> 对低配节点差别明显。

### 2.3 打包上传

```bash
tar czf litebox-deploy.tar.gz \
    bin/litebox-linux-amd64 \
    assets/singbox/ \
    scripts/ \
    deploy/

scp litebox-deploy.tar.gz root@主控IP:/root/
```

打包时**保留目录结构**(`bin/`、`scripts/`、`assets/`、`deploy/` 平级)——
`install.sh` 会按 `../bin/litebox-linux-<架构>` 的相对路径去找二进制。

## 3. 主控安装

登录**主控机器**,以 root 执行。

```bash
mkdir -p /root/litebox && cd /root/litebox
tar xzf /root/litebox-deploy.tar.gz

ls          # 应该看到 bin/ scripts/ assets/ deploy/ 四个目录
./scripts/install.sh
```

脚本会做这些事(幂等,可重复执行):

* 创建系统用户 `litebox`(无 home、无 shell)
* 建目录:`/opt/litebox`(程序)、`/etc/litebox`(配置,0700)、`/var/lib/litebox`(数据,0750)
* **生成主密钥**并写入 `/etc/litebox/litebox.env`(0600)
* 写默认配置 `/etc/litebox/litebox.yaml`
* 写 systemd 单元(含完整安全加固:关闭全部 capability、`ProtectSystem=strict` 等)
* 执行数据库迁移
* 启动服务

### 3.1 立刻备份主密钥

```bash
cat /etc/litebox/litebox.env
```

**现在就把这一行抄到密码管理器或离线介质。**

这不是形式主义:主密钥加密了数据库里所有用户的 UUID 和所有节点的 REALITY 私钥。
丢失后数据库还在、备份也还在,但里面的凭据全部解不开,只能重建一切。

### 3.2 放置节点二进制

```bash
cd /root/litebox
mkdir -p /opt/litebox/assets/singbox
cp assets/singbox/sing-box-linux-* /opt/litebox/assets/singbox/
chmod 644 /opt/litebox/assets/singbox/*
ls -la /opt/litebox/assets/singbox/
```

面板从这里读取二进制并分发到节点。缺了它,节点安装步骤会明确报错告诉你去构建。

### 3.3 修改配置

```bash
nano /etc/litebox/litebox.yaml
```

必改一项:

```yaml
http:
  # 经 HTTPS 反代时必须为 true,否则会话 Cookie 不带 Secure 属性
  secure_cookie: true
```

**订阅域名不用在这里改**——登录后到「设置 → 订阅地址」填,改完立即生效,
不需要重启面板。配置文件里的 `base_url` 只是首次启动的默认值。

其余可按需调整:

```yaml
traffic:
  # 流量同步周期。它同时决定了意外重启(OOM、宿主机重启)的最大流量损失窗口:
  # sing-box 的计数器是纯内存的,未同步部分随进程退出永久丢失。
  sync_interval: 60s

node:
  # 用户变更后的合并窗口。连续编辑多个用户时,同一节点只在最后一次变更
  # 静默这么久之后重启一次。调小会更快生效但重启更频繁。
  deploy_debounce: 4s
  # 节点资源采集间隔。放宽是为了少和部署抢节点连接锁;设成负数则关闭采集。
  metrics_interval: 5m
```

改完重启:

```bash
systemctl restart litebox
systemctl status litebox
```

### 3.4 开启每日自动备份

```bash
cd /root/litebox
cp deploy/systemd/litebox-backup.service /etc/systemd/system/
cp deploy/systemd/litebox-backup.timer   /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now litebox-backup.timer

systemctl list-timers litebox-backup     # 确认下次执行时间
```

每日一次,保留最近 14 份,落在 `/var/lib/litebox/backup/`。

## 4. Nginx 与 HTTPS

面板默认只监听 `127.0.0.1:8080`,不直接对外。由 Nginx 负责 TLS 终止。

### 4.1 申请证书

```bash
apt-get install -y nginx certbot python3-certbot-nginx
certbot certonly --nginx -d panel.example.com
```

### 4.2 写反代参数

```bash
cat > /etc/nginx/litebox_proxy_params <<'EOF'
proxy_http_version 1.1;
proxy_set_header Host              $host;
proxy_set_header X-Real-IP         $remote_addr;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_read_timeout 120s;
EOF
```

### 4.3 声明限速区

在 `/etc/nginx/nginx.conf` 的 `http { }` 块里加:

```nginx
limit_req_zone $binary_remote_addr zone=litebox_login:10m rate=10r/m;
limit_req_zone $binary_remote_addr zone=litebox_sub:10m   rate=60r/m;
```

### 4.4 站点配置

```bash
cd /root/litebox
cp deploy/nginx/litebox.conf /etc/nginx/sites-available/litebox
# 把里面的 panel.example.com 换成你的域名
sed -i 's/panel.example.com/你的域名/g' /etc/nginx/sites-available/litebox
ln -sf /etc/nginx/sites-available/litebox /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

配置的关键部分:

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name panel.example.com;

    ssl_certificate     /etc/letsencrypt/live/panel.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/panel.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    add_header Strict-Transport-Security "max-age=31536000" always;

    # 面板不该被搜索引擎收录
    location = /robots.txt {
        add_header Content-Type text/plain;
        return 200 "User-agent: *\nDisallow: /\n";
    }

    # 登录接口额外限速,配合后端的失败次数限流
    location = /api/auth/login {
        limit_req zone=litebox_login burst=5 nodelay;
        proxy_pass http://127.0.0.1:8080;
        include /etc/nginx/litebox_proxy_params;
    }

    # 订阅地址里的 Token 就是凭据,记进 access_log 等于明文落盘。
    # 日志备份、日志采集、误开的目录列表都会把它带走 —— 这里必须关掉。
    # 谁在什么时候拉过订阅,LiteBox 自己有记录(用户详情页可见)。
    location ~ ^/sub/ {
        access_log off;
        limit_req zone=litebox_sub burst=10 nodelay;
        proxy_pass http://127.0.0.1:8080;
        include /etc/nginx/litebox_proxy_params;
    }

    location / {
        proxy_pass http://127.0.0.1:8080;
        include /etc/nginx/litebox_proxy_params;
    }
}
```

> `access_log off` 那一段不是可选项。订阅地址是用户唯一的凭据,
> 它一旦进了日志文件,就会跟着日志轮转、备份、采集系统到处走。

### 4.5 防火墙

```bash
ufw allow 22/tcp      # 或你的实际 SSH 端口
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

主控**不需要**开放 8080,它只监听回环。

## 5. 首次登录

### 5.1 取初始密码

```bash
journalctl -u litebox | grep -A1 初始密码
```

输出类似:

```
初始管理员账号:admin
初始密码:jj3AGNY43VYVfLmfiJp1hA
```

密码是随机生成的,每次全新安装都不同,没有固定的默认口令。

### 5.2 登录

浏览器打开 `https://panel.example.com`,用 `admin` 和上面的密码登录。

### 5.3 立刻改密码

左侧菜单 **设置 → 修改密码**。

改密后其他设备的登录会话会立即失效,当前设备保持登录。

> 忘记密码时在主控上执行:
> ```bash
> sudo -u litebox env $(cat /etc/litebox/litebox.env) \
>     /opt/litebox/litebox reset-password --config /etc/litebox/litebox.yaml
> ```

## 6. 添加节点

节点机器只需要一台干净的 Linux + root SSH 访问。
**不需要**预装 Docker、sing-box 或任何东西——面板会自己装。

init 系统 **systemd 与 OpenRC 都支持**:前者覆盖 Debian/Ubuntu/Rocky 等,
后者主要是 Alpine —— 而 Alpine 恰恰是 NAT 小鸡最常见的镜像。
面板在探测和每次部署时自动识别,不需要你告诉它。

> Alpine 上装的是 `/etc/init.d/litebox-singbox`(OpenRC 脚本,用
> `supervise-daemon` 保证崩溃后自动拉起),日志在
> `/var/log/litebox-singbox.log`;systemd 节点上则是 systemd 单元 + journald。
> 两边的服务名都是 `litebox-singbox`,不会和机器上已有的 sing-box 冲突。

### 6.1 面板专用 SSH 密钥

面板有**一把自己的密钥**,首次需要连节点时自动生成,私钥用主密钥加密存在数据库里,
公钥在「设置 → 面板 SSH 公钥」能看到,也可以在主控上打印:

```bash
sudo -u litebox env "$(grep '^LITEBOX_MASTER_KEY=' /etc/litebox/litebox.env)" \
  /opt/litebox/litebox ssh-key --config /etc/litebox/litebox.yaml
```

主密钥在 `/etc/litebox/litebox.env` 而不是 yaml 里(服务靠 systemd 的
`EnvironmentFile` 读它),所以手工执行任何子命令都要像上面这样自己带上。

面板对所有节点的操作都用这一把。你不需要为每个节点单独准备密钥。

> **为什么要专用密钥:** 面板需要节点的 root 权限(装 systemd 单元、重启服务),
> 这个权限收不掉。能收的是爆炸半径——用一把只给面板用的密钥,
> 泄露或轮换时不必动你的日常密钥,节点侧也能单独吊销。

### 6.2 在面板里新增节点

**节点管理 → 新增节点**,填:

| 字段 | 填什么 | 说明 |
|---|---|---|
| 节点名称 | 如 `洛杉矶 01` | 会显示在用户的客户端里,可用中文 |
| IPv4 地址 | 节点的公网 IPv4 | 用于 SSH 管理、节点部署和 IPv4 订阅,必填 |
| IPv6 地址 | 选填 | **只用于订阅下发**,见下 |
| IPv6 公网端口 | **一般留空** | 留空即与公网代理端口相同,见下 |
| SSH 端口 | 默认 22 | |
| SSH 用户 | `root` | 需要 root 权限 |
| 接入方式 | 见下 | 决定怎么把面板公钥装进节点 |
| 公网代理端口 | 建议 `443` | 用户客户端连的端口,写进订阅 |
| 主机代理端口 | **一般留空** | sing-box 在节点上监听的端口,留空即与公网端口相同 |
| API 端口 | 默认 `28080` | 只监听节点回环,不对外 |
| 节点流量限额 | 选填 | 留空即不限量,见下 |

#### IPv6

填了 IPv6 之后,这台机器在订阅里会出现**两条**:

```
洛杉矶 01           →  192.0.2.10
洛杉矶 01-IPV6      →  2602:fed2:7116:2110::1
```

两条用完全相同的 UUID、REALITY 公钥、short ID、握手目标与指纹,
只有名字、服务器地址和(可选的)端口不同——它们指向的是**同一个** sing-box 入站。
所以流量也是合并统计的,面板不区分走了哪个地址。

**IPv6 公网端口一般留空。** 留空表示跟随「公网代理端口」,以后你改了那个,
IPv6 也自动跟着变。只有两个协议栈映射到**不同**外部端口时才需要单独填 ——
NAT 小鸡上很常见:IPv4 是服务商映射的高位端口,IPv6 则是直连的 443:

```
洛杉矶 01           →  192.0.2.10:20443     (服务商映射)
洛杉矶 01-IPV6      →  [2602:fed2::1]:443   (IPv6 直连)
```

填了它只改 IPv6 那一条,IPv4 条目和「主机代理端口」都不动 ——
sing-box 只监听一个端口,两条链路都转发到它。

几点要知道:

* **面板始终用 IPv4 管理节点。** SSH、探测、安装、部署、重启、流量同步、
  资源采集全部走 IPv4 栏那个地址,IPv6 一概不参与;
* **改 IPv6 地址或 IPv6 端口都不需要重新部署**,也不会断开在线连接。
  保存即生效,用户的客户端下次更新订阅就能看到;
* **清空 IPv6** 即把那条从订阅里撤下来,同样即时生效。IPv6 端口会跟着一起清掉,
  下次重新填 IPv6 时不会静默套用一个旧端口;
* 只有 IPv6 没有 IPv4 的节点**不支持**;
* 粘贴时带方括号没关系,面板会自己剥掉。填错栏(IPv4 里填 IPv6 或反过来)
  会直接报错并告诉你该填哪儿。

#### 节点流量限额

给节点填一个额度,面板会在**当前统计周期内**汇总这台机器上所有用户的
上下行流量,并在列表和仪表盘上给出进度与预警。

| 字段 | 说明 |
|---|---|
| 节点流量限额 | 留空或 0 = 不限量 |
| 重置周期 | 「不重置」= 统计节点创建以来的累计流量;「每月」= 按重置日划分周期 |
| 每月重置日 | 1~31。当月没有该日时按当月最后一天算(填 31,二月即 28 或 29 日) |

**周期边界统一取 UTC 00:00**,页面上都标了 UTC——本地时区显示会让人
看到"9 月 15 日 08:00 重置",容易以为设置没生效。

预警阈值:80% 黄、95% 红、100% 标「已超额」,与用户额度一致。

两件重要的事:

* **超额只预警,不做任何自动处置。** 面板不会停掉 sing-box、不会禁用节点、
  不会把节点从订阅里摘掉,也不会删用户凭据。流量同步有时间间隔,
  各家 VPS 的计量口径也不一致,自动关掉一个共享节点会同时打断这台机器上
  的全部用户。要停就自己在节点列表点「禁用」或关掉「下发到用户订阅」;
* **「重置」只是换统计起点,不删任何数据。** 历史流量、每日汇总、
  用户累计用量、节点计数器基线全部原样保留,当前周期用量是按时间范围现算的。
  所以改重置日、改周期都不会毁掉历史报表,改回去也能还原。

数据来自 `traffic_ledger`,包含已停用与已删除用户留下的历史流量——
那些字节确实走了这台机器。IPv4 与 IPv6 也不分开算。

#### 三种接入方式

**不管选哪种,面板都会先拿自己的密钥试一次**——已经能登上就直接完成,不动
`authorized_keys`,也不需要密码。所以「重新引导」可以随便点,它本质上是
"确保面板连得上这台机器"。

| 方式 | 什么时候用 | 面板做什么 |
|---|---|---|
| **节点密码**(默认) | 大多数情况 | 用你填的密码登录节点一次,把面板公钥追加进 `~/.ssh/authorized_keys`,再用公钥真连一次验证 |
| **主控本机私钥** | 节点禁用了密码登录,但主控上已经有一把能登它的私钥 | 在面板进程的 `$HOME/.ssh` 与 `/etc/litebox/keys` 下逐把试,用能登上的那把去装公钥 |
| **手工指定私钥** | 想给这个节点单配一把密钥 | 直接用你粘贴的私钥,不做引导。私钥用主密钥加密后存库,不会再显示 |

> **节点关掉了密码登录时**(`PasswordAuthentication no`,不少 VPS 默认如此),
> 填密码会得到"节点不接受口令登录"。这时最省事的做法是照下面手工贴一次公钥,
> 贴完点「重新引导」——面板先试自己的密钥,直接就通了。

**密码只用这一次,不落库、不写日志、不进审计详情。** 装完公钥之后
面板再也不需要它,后续所有操作都走专用密钥。

> **「主控本机私钥」的一个坑:** 面板以 `litebox` 用户运行,读不到 `/root/.ssh`。
> 要用这条路径,把私钥放到 `/etc/litebox/keys/` 下并让 `litebox` 用户可读,
> 或者在配置里用 `node.bootstrap_key_dirs` 指定目录。

装公钥这一步**失败也不会丢掉节点记录**——地址填错、密码不对、sshd 配置有问题
都是要人看一眼才能修的,删掉记录只会让你重填一遍表单。处理好之后到
**节点详情 →「重新引导」**重试即可,那里也能单独填一次性密码。

创建后详情抽屉会自动打开。

#### 只允许密钥登录、且主控上没有可用私钥的节点

先手工把面板公钥贴进节点。

如果主控上已经有一把能登录该节点的密钥(比如 root 的日常密钥),
一条命令就能推过去 —— 面板不会拿到你那把私钥的副本:

```bash
sudo -u litebox env "$(grep '^LITEBOX_MASTER_KEY=' /etc/litebox/litebox.env)" \
  /opt/litebox/litebox ssh-key --config /etc/litebox/litebox.yaml | \
  ssh -p <节点SSH端口> root@<节点IP> \
    'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'
```

没有的话,把「设置」页里的公钥复制下来,在节点上手工追加:

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'ssh-ed25519 AAAA... litebox-panel' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

> 要装到**面板配置的那个 SSH 用户**下(默认 root),不是你平时登录用的那个。

然后在面板里新增节点(接入方式随便选,密码可以留空),或者对已有节点点
**「重新引导」**——面板会先用自己的密钥试,发现已经能登上就直接完成,
既不需要密码,也不会重复往 `authorized_keys` 里追加。

#### 什么时候要填「主机代理端口」

只有当**用户连的端口**与 **sing-box 实际监听的端口**不一致时才填。两种典型情况:

* **NAT 小鸡**:服务商只给你一段映射端口,公网 `443` 由它转发到你机器上的 `20443`。
  这时公网填 `443`、主机填 `20443`。
* **443 已经被 nginx 占用**:让 nginx 用 stream 模块把 443 转给 `127.0.0.1:20443`,
  sing-box 监听 20443。填法同上。

```
客户端 ──→ 节点:443 ──[NAT 映射 / nginx stream]──→ 本机:20443 ──→ sing-box
           公网代理端口                                主机代理端口
```

**转发规则要你自己配**,面板不碰它。面板只做两件事:让 sing-box 监听主机端口,
在订阅里写公网端口。健康检查(端口监听 + VLESS 拨测)都在节点本机执行,
查的也是主机端口,所以即使转发规则还没配好,部署一样能成功——
届时面板显示健康而用户连不上,这种情况请先自查转发链路。

nginx stream 转发的最小配置(注意 `stream` 与 `http` 平级,不能写进 `server` 块):

```nginx
stream {
    server {
        listen 443;
        listen [::]:443;
        proxy_pass 127.0.0.1:20443;
    }
}
```

> 转发时 sing-box 仍然监听在所有地址上,主机端口本身也是公网可达的。
> **只有 nginx 同机转发**这一种情况可以用 `ufw deny 20443/tcp` 把它挡掉——
> nginx 走的是回环,ufw 在用户规则之前就放行了回环,不受影响。
>
> **NAT 小鸡不要这么做**:服务商的映射是在你机器之外完成的,
> 转发进来的包是从物理网卡进的 20443,挡掉就等于把节点关了。

### 6.3 按顺序执行四步

在节点详情抽屉里,按这个顺序点:

#### ① 测试 SSH

确认能连上。首次连接会自动固定节点的 SSH 主机密钥(TOFU)——
之后主机密钥变了会直接拒绝连接,防中间人。

节点重装后需要手动点 **重置主机密钥** 才能重新连接。

#### ② 探测

采集架构、内核、内存、systemd 版本,并检查 sing-box。首次探测会提示
"节点上未找到可执行的 sing-box",这是正常的——下一步就装。

#### ③ 安装 sing-box

上传二进制、写 systemd 单元(服务名 `litebox-singbox`,带 `litebox-` 前缀
避免和机器上已有的 sing-box 冲突)、设为开机自启,并**验证上传的二进制
确实带 `with_v2ray_api` 标签**。

跨洲链路约需 2~10 秒。装完再点一次「探测」,应该能看到:

```
sing-box    v1.13.15-litebox
构建标签    with_utls,with_v2ray_api,badlinkname,tfogo_checklinkname0
```

#### ④ 扫描握手目标

这一步**不能跳过**。

REALITY 会"借用"一个真实网站的证书,而它有一个 **8192 字节的 TLS 记录上限**——
超限时握手会静默失败,服务端只报一句 `processed invalid connection`,
不给任何原因,极难排查。

点「扫描握手目标」,面板会**从节点的网络出口**逐个实测候选目标:

```
www.fastly.com         最大记录=2569   曲线=X25519   ALPN=h2   可用
shopify.com            最大记录=2645   曲线=X25519   ALPN=h2   可用
www.tesla.com          最大记录=3319   曲线=X25519   ALPN=h2   可用
addons.mozilla.org     最大记录=4133   曲线=X25519   ALPN=h2   可用
download.jetbrains.com 最大记录=4308   曲线=X25519   ALPN=h2   可用
www.cloudflare.com     最大记录=2673   曲线=X25519   ALPN=h2   可用
```

在想用的那一行点 **应用**。

> **必须在节点本机实测**,不能凭经验选:CDN 按地域下发不同证书链,
> 同一个域名在本地测是 3373 字节、在洛杉矶节点可能是 4738 字节。
> 微软系站点(`www.microsoft.com` 8273、`www.bing.com` 8340)因为用 RSA 证书链
> 一律超限不可用,面板会拒绝应用并告诉你实测值。

> **候选里没有苹果与谷歌系**(`www.apple.com`、`dl.google.com`、`gateway.icloud.com`)。
> 它们的 TLS 参数其实都合格,被拿掉的原因是各类教程都用这几个域名 ——
> 一台 VPS 常年只跟它们握手,这件事本身就是特征。想用别的目标也可以:
> 扫描列表只是候选,任何满足 TLS 1.3 + X25519 + 记录 ≤ 8192 的站点都能用,
> 挑一个跟你这台机器地理位置相符、平时确实会有人访问的即可。

### 6.4 部署

此时节点上还没有配置。可以先点 **部署** 下发一份空配置验证链路,
也可以直接跳到下一节创建用户——创建用户后会自动触发部署。

部署做这些事,任一步失败自动回滚:

```
强制同步流量(sing-box 在跑时失败即中止,避免丢流量)
→ 上传临时配置
→ sing-box check(失败则中止且不重启,当前用户不受影响)
→ 备份当前配置
→ 原子替换
→ systemctl restart
→ 健康检查一:systemd 状态
→ 健康检查二:端口监听
→ 健康检查三:真实 VLESS 拨测
```

> 第三步拨测不可省略。实测过一种情况:配置能通过 `sing-box check`、
> systemd 显示 active、端口正常监听,但**所有用户都连不上**。
> 只有真实拨一次才能发现,发现后自动回滚。

部署记录可展开看每一步的耗时与详情。

### 7.1 新增

**用户管理 → 新增用户**:

| 字段 | 说明 |
|---|---|
| 用户名称 | 显示名,可随时改。流量统计用的是内部代码 `user_000001`,不受改名影响 |
| 备注 | 可选 |
| 流量额度(GB) | 填 `0` 表示不限量 |
| 到期时间 | 留空表示不过期 |
| 流量重置 | 不重置 / 每月。选每月时可指定重置日(1~28) |
| 访问等级 | 普通组 / VIP组 / ROOT组。等级不高于它的节点会**自动可用**,不必逐个勾选 |
| 额外授权节点 | 在访问等级之外单独追加的节点。通常留空 |

### 7.2 拿到订阅地址

点用户行的 **详情**,抽屉里有:

```
订阅地址

查看 VLESS 链接 | sing-box 配置
```

把这个地址发给用户。

> 通过 IM 发送时注意对方的消息留存策略。用户换设备后如有疑虑,
> 点 **重新生成订阅地址**,旧地址立即失效。

### 7.3 用户状态说明

| 状态 | 含义 | 用户能连吗 |
|---|---|---|
| 正常 | 一切正常 | 能 |
| 已停用 | 管理员手动停用 | 不能 |
| 已过期 | 超过到期时间,自动转入 | 不能 |
| 流量用尽 | 达到额度,自动转入 | 不能 |

后三种状态的用户会**自动从节点配置里移除**,节点重新部署后其 UUID 立即失效。
重新启用或提高额度后会自动恢复并重新部署。

注意:这三种状态**不影响用户门户登录**。他们仍然能登录进来看到自己
为什么断了 —— 挡住的话,只会变成一通问你的消息。

### 7.4 续期与调整额度

用户行的 **续期**,或勾选多个用户后的 **批量调整**:

| 操作 | 说明 |
|---|---|
| 增加流量 | 在现有额度上加(填负数表示扣减)。**不限量的用户用不了这项**,请改用「设置流量额度」 |
| 设置流量额度 | 设成绝对值,填 0 表示不限量 |
| 延长有效期 | 已过期的从今天起算,未到期的从原到期日起算 —— 不会把已有时间抹掉 |
| 设置到期时间 | 设成绝对日期,留空表示改为不过期 |
| 重置已用流量 | 清零累计用量,历史流水与节点计数器基线不动 |
| 调整访问等级 | 变更后受影响的节点会自动重新部署 |
| 启用 / 停用账号 | |

**备注会展示给用户**(在门户首页的"最近调整"里),不要往里写内部说明。

批量操作里部分用户失败不影响其余用户,弹窗会逐条列出是谁、为什么失败。

## 8. 客户端使用

订阅地址支持三种格式,同一个地址加不同参数即可。

### 8.1 通用客户端(v2rayN、Shadowrocket、NekoBox 等)

直接用订阅地址,不加参数:

```
https://panel.example.com/sub/xxxxx
```

返回 base64 编码的 VLESS 链接列表。绝大多数客户端支持这个格式。

客户端还会读到 `Subscription-Userinfo` 响应头,自动显示已用流量与到期时间。

### 8.2 sing-box 客户端

```
https://panel.example.com/sub/xxxxx?format=sing-box
```

返回一份完整的 sing-box 客户端配置,包含:

* 本地混合入站(默认 2080 端口,SOCKS + HTTP 都能用)
* 每个节点一个 VLESS 出站
* 一个手动选择器 `节点选择` 和一个自动测速选择器 `自动选择`
* 内网地址直连的路由规则

下载后可直接 `sing-box run -c config.json`。

> 刻意不包含规则集与 GeoIP:V1 不承诺分流能力,
> 塞进去只会让客户端下载大文件、在低配设备上变慢。
> 需要分流的话自己在这份配置基础上加 `route.rules`。

### 8.3 查看明文链接(排查用)

```
https://panel.example.com/sub/xxxxx?format=uri
```

返回未编码的 `vless://` 链接,一行一个。方便人工核对参数是否正确。

### 8.4 用户看到什么

如果用户的账号被停用、过期或流量用尽,拉取订阅会得到:

```
HTTP 403
用户当前不可用:流量已用尽
```

而**不是**一份空订阅。这是刻意的——空订阅会让客户端静默清空全部节点,
用户完全不知道发生了什么;返回错误反而能让客户端弹出可读的提示。

## 9. 访问等级与用户门户

### 9.1 访问等级

节点与用户各属于一个访问等级,判据是「节点等级 <= 用户等级」:

```
NORMAL(10)  普通节点
VIP(20)     普通节点 + VIP 节点
ROOT(30)    全部节点
```

从 V1 升级上来的库,所有用户与节点都在普通组 —— 可用节点集合与升级前
完全一致,什么都不会变。想分组时再去改。

> **ROOT 是节点访问等级,不是管理权限。** ROOT 用户只是能用到全部节点的
> 代理用户,进不了管理后台,也看不到节点内部名称。管理员要自用订阅,
> 请单独建一个 ROOT 等级的代理用户,不要拿管理员账号兼任。

除等级外,还可以给单个用户 **额外授权** 某个节点(用户编辑页的
「额外授权节点」)。V1 里的节点分配关系升级后自动成为额外授权,继续有效。

在「设置 → 访问等级」里可以改三个等级的展示名称、说明与排序。
`code` 与继承用的 `level` 不开放修改 —— 改 `level` 会让所有用户可用的
节点集合同时变化,而页面上看不出发生了什么。

**改节点等级会自动触发重新部署**(重启该节点的 sing-box,断开在线连接)。
这一条不像改端口那样等你挑时机:等级调高后,被移出的用户凭据还留在节点上,
拖多久就多能用多久。请在低峰时段操作。

### 9.2 节点的两个名称

| 字段 | 出现在哪 |
|---|---|
| 内部名称 | 只在管理后台。可以写机房、供应商、到期日、IP 段 |
| 展示名称 | 用户订阅与门户里显示的名字 |

新建节点时展示名称留空即与内部名称相同。**订阅与门户里绝不会出现内部名称** ——
那是运维信息,不该随订阅发到用户设备上。

节点还有三个对外字段:

* **排序** —— 数值小的排在订阅前面,可以把主力节点排在最上;
* **公开备注** —— 用户可见的一句话,例如「晚高峰限速」;
* **维护说明** —— 节点维护时给用户看的提示。

以及一个开关:**下发到用户订阅**。关掉后节点不再进入新生成的订阅,
但节点记录、历史流量与部署记录**全部保留** —— 这是"进维护",不是"删节点"。
用户在门户里会看到这个节点标成「维护中」,而不是凭空消失。

### 9.3 开通用户门户

**用户管理 → 详情 → 门户登录 → 开通**:

| 字段 | 说明 |
|---|---|
| 登录账号 | 全局唯一。字母、数字、下划线、连字符与点,3~32 位 |
| 初始密码 | 至少 8 位,请通过安全渠道发给用户 |
| 要求首次登录后修改密码 | 建议勾上 |

然后把这两样发给用户 —— 保存后弹出的提示里就是这两行,可以直接复制:

```
https://panel.example.com/
账号:zhangsan   初始密码:(你设的那个)
```

**面板首页就是用户中心**,不用让用户记额外的路径。管理后台在 `/login`。

勾了强制改密的话,**用户在改掉密码之前拿不到订阅地址** —— 后端会挡住
除"看自己是谁"和"改密码"之外的所有接口。只靠前端弹窗拦不住直接调接口的人,
而这条限制的意义正是不让初始口令换到任何有价值的东西。

用户门户与管理后台是**完全独立的两套登录**:Cookie 不同、会话表不同。
你可以在同一个浏览器里同时登着两边,互不干扰。

### 9.4 用户在门户里能做什么

| 页面 | 内容 |
|---|---|
| 概览 | 显示名称、访问等级、账号状态、已用/总额/剩余流量与百分比、到期时间与剩余天数、下次流量重置时间、最近调整记录、流量与到期预警 |
| 我的订阅 | 三种格式的订阅地址与一键复制、包含节点数、最近拉取时间、重新生成订阅地址 |
| 我的节点 | 每个可用节点的展示名称、等级、状态、协议、公网端口、今日/本月/累计流量 |
| 我的流量 | 最近 7 / 30 天的按日趋势与按节点占比 |
| 安全设置 | 修改密码、查看与下线登录设备、退出全部设备 |

额度为 0 时显示"不限量",不会显示一个假的百分比。

用户看不到:节点内部名称、SSH 用户与端口、任何私钥、V2Ray API 端口、
部署路径、部署错误明细、主机资源监控数据。

### 9.5 管理用户的登录

在用户详情的「门户登录」区域:

* **修改** —— 改账号名;填了新密码则该用户的**全部登录会话立即失效**,
  留空表示不改密码;
* **停用登录** —— 立刻踢掉全部在线会话,且无法再登录。**不影响代理服务**;
* **踢出全部** —— 只下线,不禁止再登录;
* **删除账号** —— 该用户不能再登录门户,但代理服务与订阅照常。

那里还能看到:最后登录时间与 IP、当前在线会话数、是否还欠一次改密。

## 10. 日常使用指南

### 仪表盘

**节点运行状态** 卡片区显示每台节点的 CPU、内存、上下行速率、系统运行时间
与最近采集时间,每 60 秒自动刷新一次。

它读的是数据库里已有的采样,**不会**每次刷新都去 SSH 连一遍节点 ——
10 台机器就是 10 条会话,而 128MB 的小鸡上这笔开销比"实时"更值得在意。
后端的采集周期默认 5 分钟。

* 采样超过 **10 分钟**没更新会标「监控数据已过期」;
* 从没采集过的节点标「暂无监控数据」;
* **采集失败不代表节点离线** —— 那是独立的 SSH 通道,它断了不等于
  sing-box 停了。节点状态标签仍以节点自身状态为准。

**预警** 列表汇总:流量到 80% / 95% / 用完、剩余 7 天 / 3 天 / 已到期、
节点部署失败、节点监控数据超时。点一条跳到对应页面。停用的用户与节点
不进这个列表(是你自己关的,不需要再提醒一遍)。


* 用户数、节点数、今日与本月流量(UTC 时区)
* 告警卡片:流量用尽、7 天内到期、部署失败——**只在有值时出现**,
  没问题时不占位也不显红
* 最近失败的部署
* 流量同步状态:上次同步时间、同步失败的节点

点统计卡片可跳到对应页面。

### 用户管理

**列表**显示状态、节点数、已用流量(带进度条)、到期时间。

**行内操作**:详情 / 编辑 / 停用启用 / 删除。

**详情抽屉**里能做:

| 操作 | 效果 |
|---|---|
| 重置流量 | 累计流量清零。历史流水与节点计数器基线不变(动了会导致重复入账)。若此前因超额被停用,自动恢复 |
| 重新生成 UUID | 用户当前客户端在节点重新部署后立即失效,需重新导入订阅 |
| 重新生成订阅地址 | 旧订阅地址立即失效,需把新地址重新发给用户 |

还能看到:节点分配、订阅拉取记录(次数、时间、客户端 UA)、
最近 30 天流量趋势、按节点的流量分布、最近操作记录。

> **订阅拉取记录**能回答"用户到底导入订阅了没有"——显示"从未拉取"
> 就说明用户还没配置客户端,不用去查节点。

### 节点管理

**列表**显示状态、sing-box 版本、今日流量、周期流量、最后心跳。
端口不一致时,IPv4 地址下方会写成 `1.2.3.4:443 → 主机 20443`;
配了 IPv6 的节点会在地址后面标一个 `IPv6`;IPv6 用了单独的公网端口时
一并写出来(`· IPv6:8443`),与 IPv4 相同则不重复列。

**周期流量**那一列是「已用 / 额度」加一条进度条,下面写着几月几日重置。
不限量的节点写「累计流量」,不画进度条——没有分母,画出来只能是错的。
超额时进度条变红并标「已超额」,但节点照常工作(见 6.2 的说明)。

**编辑**可以改节点名称、IPv4/IPv6 地址、IPv6 公网端口、SSH 参数、
公网/主机代理端口、API 端口与流量额度。

* SSH 私钥留空 = 保持原私钥;填新私钥即完成轮换。
* 改 **IPv6 地址**、**IPv6 公网端口**或**流量额度**都不需要重新部署,
  也不会断开在线连接;IPv6 改动在用户下次拉订阅时生效。
* **IPv6 公网端口留空 = 跟随公网代理端口**,以后改后者时它自动跟着变。
* 改了 IPv4 地址、SSH 端口/用户/私钥,面板会立刻丢弃该节点的 SSH 长连接,
  下次操作重新建连。**主机密钥仍然是固定的**——换了机器会连不上,
  这是防中间人的设计,确认无误后点「重置主机密钥」。
* 改了**主机代理端口**或 **API 端口**,配置需要重新部署才生效,
  面板会弹窗问你是现在部署还是稍后手动部署。
  部署会重启 sing-box、断开全部在线连接,所以要和转发规则的改动配合着来。
* 改**公网代理端口**、节点名称只影响订阅内容,不需要部署;
  但客户端要重新拉一次订阅才能拿到新端口。
* **REALITY 握手目标不在这里改**:它必须从节点本机实测通过才能保存,
  走详情抽屉里的「扫描握手目标」。

**详情抽屉**的九个操作:

| 操作 | 什么时候用 |
|---|---|
| 测试 SSH | 怀疑网络或密钥有问题时 |
| 重新引导 | 面板连不上节点、或手工贴过公钥之后。先试面板密钥,不行再用密码/本机私钥装公钥 |
| 探测 | 想刷新架构、版本、构建标签信息时 |
| 安装 sing-box | 首次初始化,或升级节点二进制 |
| 扫描握手目标 | 新增节点时,或怀疑当前目标不可用时 |
| 比对配置 | 怀疑节点配置被人手工改过时 |
| 部署 | 想立即下发配置,不等自动合并 |
| 同步流量 | 想立即看到最新流量,不等 60 秒周期 |
| 采集资源 | 想立刻看一眼 CPU/内存/网速,不等采集周期 |
| 重启服务 | 运维用的直接重启。**不会先同步流量**,常规变更请用「部署」 |
| 重置主机密钥 | 仅在节点重装后使用 |
| 卸载服务 | 不想在这台机器上跑 sing-box 了,但还想留着节点记录 |

**「最大 TLS 记录」**那一栏显示实测值与 8192 上限,绿色是有余量,红色是超限。

#### 卸载 vs 删除

两个不一样,别选错:

* **卸载服务**——停掉并删除节点上的 `litebox-singbox` 服务、systemd 单元与
  `/opt/litebox` 目录,**不碰这台机器上的其他任何东西**(包括你自己装的 sing-box)。
  用户会立刻断线。面板里的节点记录、REALITY 密钥、流量历史全部保留,
  重新点「安装 sing-box」「部署」即可原样恢复。
* **删除节点**——面板不再管理这台机器,但**不会**清理节点上的服务与文件。
  想彻底清干净,先卸载再删除。

#### 资源监控

节点详情里能看到 CPU、内存、磁盘使用率,以及网络收发速率、1 分钟负载和运行时长。

数据由后台按 **5 分钟**一次采集(`node.metrics_interval`),保留 7 天。
间隔刻意放得比流量同步(60 秒)宽:资源指标只用来看趋势,
而每次采集要占用节点连接锁一秒多,采得太勤会和部署、流量同步抢锁。

采集在节点上只跑一条 shell,读 `/proc/stat`、`/proc/meminfo`、`/proc/net/dev`、
`/proc/loadavg` 与 `df`,不依赖 top/vmstat 这些精简镜像里常常没有的工具。
CPU 和网速需要两次快照相减,所以每次采集会在节点上 sleep 1 秒。

想彻底关掉:配置里把 `node.metrics_interval` 设成负数。

节点列表也有「资源」和「网速」两列,显示最近一次采样。**—** 表示还没采过
(新节点、未探测过的节点、被禁用的节点都不采)。

### 节点资源趋势

节点详情抽屉的「资源趋势」有三张图:CPU 使用率、内存使用率、网络速率
(上下行画在一起,才看得出下行涨的时候上行有没有跟着涨)。
区间可切换 6 / 24 / 72 / 168 小时。

采样默认保留 7 天,所以 168 小时是上限 —— 给更长的选项只会让你看到
一段被清理掉的空白。

### 部署记录

全部部署的历史,可展开看每一步的耗时与详情,支持"只看失败"。

失败时最有用的信息在步骤明细里:

| 失败在哪一步 | 说明 |
|---|---|
| 同步流量 | sing-box 在跑但 API 不通,已中止部署以避免流量丢失 |
| sing-box check | 配置本身有问题,**服务未被重启**,当前用户不受影响 |
| 健康检查:VLESS 拨测 | 配置能加载、端口在监听,但用户实际连不上,已自动回滚 |

### 审计日志

所有管理操作的记录,动作名已中文化,支持关键词搜索和"只看失败"。
登录失败、限流触发也在里面。

节点密码**不会**出现在审计日志里——引导记录只写认证方式(`password` / `local-key`)
和结果,不写口令本身。

### 设置

* **订阅地址**——用户订阅链接的前缀。改完立即生效,不用重启面板。
  订阅 Token 不变,用户不必重新导入;但客户端在下次拉订阅之前用的仍是旧地址,
  所以换域名时旧域名要留一段时间。
* **面板 SSH 公钥**——新增节点时装进节点 `authorized_keys` 的那一行,可复制。
* **修改密码**——改完其他设备上的会话立即失效,当前设备保持登录。

## 11. 常见问题

### 面板打不开

```bash
systemctl status litebox
journalctl -u litebox -n 50
curl -fsS http://127.0.0.1:8080/api/health
```

常见原因:主密钥未配置或格式错(启动时会立刻报错)、
数据库文件权限不对(应为 `litebox:litebox` 0600)、Nginx 配置有误。

### 节点显示离线

1. 节点详情 → **测试 SSH**,不通就是网络或密钥问题
2. 通了但同步仍失败,登节点看 `systemctl status litebox-singbox`
3. sing-box 在跑但 API 不通,检查面板里的「API 端口」与节点实际监听是否一致

**同步失败不会破坏已入库的流量**——采样完全在数据库事务之外完成,
读取失败时一个字节都不会动。

### 用户连不上

按这个顺序查:

1. 用户状态是不是「正常」——停用、过期、流量用尽都会被移出节点配置
2. 节点详情 → **比对配置**,确认该用户在期望用户列表里且显示"与节点实际配置一致"
3. 用户详情 → 订阅拉取,确认用户真的导入过订阅
4. 还是不行就点节点的 **部署**,重新下发一次

### 用户登录用户中心失败,提示密码不对

**九成是地址发错了。** 面板首页是**管理员**登录页,它查的是管理员账号表,
普通用户在那里输账号只会得到「用户名或密码错误」—— 看起来完全就是
密码发错了。

**面板首页就是用户中心**,管理后台在 `/login`:

```
用户中心(普通用户):https://panel.example.com/
管理后台(管理员):  https://panel.example.com/login
```

首页留给用户是刻意的:用户有 10 个、管理员只有 1 个,谁更多谁就该占默认路径。
管理员加个书签就行,用户拿到的是一个干净的域名。

两个页面上都有互相跳转的链接。用户详情的「门户登录」区块里也直接列出了
登录地址并可一键复制 —— 开通账号时弹出的提示里同样带着它。

排除地址问题后再按这个顺序查:

1. 用户详情 → 门户登录,确认那里显示的是**账号名而不是「未开通」** ——
   显示未开通说明账号根本没建成;
2. 确认「登录状态」是**已启用**。停用时用户无法登录,但代理照常;
3. 重设密码(详情 → 门户登录 → 修改)。注意这会**踢掉该用户的全部登录会话**;
4. 连续输错会触发限流,换个网络或等 15 分钟再试。

> 账号过期、流量用完**不影响**登录用户中心 —— 那是故意的,
> 用户要能自己进来看到原因。这两种情况登录后订阅区域会显示不可用原因。

### 流量统计不动

* 确认节点的 sing-box 带 `with_v2ray_api` 标签(节点详情能看到构建标签)。
  缺了它统计完全不工作,而且**不会报错**
* 确认用户产生了真实流量(统计有约 60 秒延迟)
* 节点详情 → **同步流量**,手动触发一次看报错

### 节点重启了,流量会丢吗

面板自己触发的重启(部署)会**先强制同步**,不丢。

意外重启(OOM、宿主机重启、崩溃)最多丢一个同步周期的流量(默认 60 秒)——
sing-box 的计数器是纯内存的,进程退出即消失,这个无解。

重启后累计流量**既不会回退也不会漏算**:面板通过进程 uptime 独立判定重启,
把计数器基线归零后重新计算。

### 想换节点的握手目标

节点详情 → **扫描握手目标** → 在想用的那一行点 **应用** → 点 **部署**。

已经连着的用户会在部署重启时断开一下,客户端会自动重连。
**不需要**让用户更新订阅——握手目标变了但订阅地址不变,
客户端下次拉订阅会自动拿到新参数。

### 想换节点端口

节点管理 → **编辑**。两个端口的改法不一样:

* 只改**公网代理端口**(比如 443 换成 8443,转发规则也跟着改):
  保存即可,不用部署。让用户重新拉一次订阅。
* 改**主机代理端口**(sing-box 实际监听的端口):
  保存后必须**部署**才生效,面板会弹窗提醒。部署会重启 sing-box 断开在线连接。

直连节点(没配转发)的两个端口应当保持一致:直接把公网端口改掉、主机端口留空,
然后部署。

### 面板一切正常,但用户就是连不上

如果配了端口转发,先怀疑转发链路。面板的健康检查(端口监听 + VLESS 拨测)
**全部在节点本机执行**,查的是主机端口,转发规则坏了它一样报健康。

在节点上确认 sing-box 监听的是主机端口:

```bash
ss -tlnp | grep sing-box
```

再从**外部**确认公网端口通:

```bash
# 在主控或本地机器上执行,换成节点地址与公网端口
nc -vz 1.2.3.4 443
```

前者通、后者不通,就是 NAT 映射或 nginx stream 配置的问题,与面板无关。
另外核对一下面板里的公网端口和实际映射是不是一致——写错了订阅就是错的。

### 添加第二个节点

重复第 6 节即可,但要用**另一台机器**。一台机器只能作为一个节点。

新节点部署好之后,在用户详情 → 编辑 → 分配节点里勾上它,
用户的订阅会自动包含新节点,客户端下次拉订阅就能看到。

### 怎么升级

```bash
# 开发机上重新构建
make build-linux
scp bin/litebox-linux-amd64 root@主控IP:/root/

# 主控上
BINARY=/root/litebox-linux-amd64 ./scripts/upgrade.sh
```

脚本会先备份、再换二进制、再迁移、再启动、再健康检查,任一步失败自动回退。

节点的 sing-box 升级:重新 `make singbox`、把新二进制放到
`/opt/litebox/assets/singbox/`,然后在每个节点详情里点 **安装 sing-box** → **部署**。

### 怎么备份和恢复

自动备份在第 3.4 节已开启。手动备份:

```bash
sudo -u litebox env $(cat /etc/litebox/litebox.env) \
    /opt/litebox/litebox backup --config /etc/litebox/litebox.yaml
```

恢复:

```bash
./scripts/restore.sh /var/lib/litebox/backup/litebox-20260802-120000.db
```

脚本会先校验备份本身再动现有数据库,恢复前的库也会另存一份。

> **备份不含主密钥。** 换机器恢复时必须同时带上
> `/etc/litebox/litebox.env`,两者配套才能用。

### 端口

| 位置 | 端口 | 对外 |
|---|---|---|
| 主控 | 443 / 80 | 是(Nginx) |
| 主控 | 8080 | 否(仅回环) |
| 主控 | 22 | 是(SSH) |
| 节点 | 公网代理端口(建议 443) | 是 |
| 节点 | 主机代理端口(默认同上) | 是(除非用 nginx 同机转发) |
| 节点 | 28080 | 否(仅回环,经 SSH 通道访问) |
| 节点 | 22 | 是(SSH,仅主控需要) |

### 常用命令

```bash
# 主控
systemctl status litebox
journalctl -u litebox -f
/opt/litebox/litebox check  --config /etc/litebox/litebox.yaml
/opt/litebox/litebox backup --config /etc/litebox/litebox.yaml

# 节点(一般不需要手动操作,面板会管)
systemctl status litebox-singbox
journalctl -u litebox-singbox -n 50
/opt/litebox/sing-box check -c /opt/litebox/config.json
```
