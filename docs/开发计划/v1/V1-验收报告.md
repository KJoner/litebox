# LiteBox Panel V1 验收报告

验收日期:2026-08-02
验收环境:主控 Windows 11 / Go 1.26.3;节点 Debian 12 (bookworm) x86_64 真实 VPS(洛杉矶)
版本:v0.7.0-phase7

---

## 1. 结论

**V1 全部验收标准通过。**

原计划的 13 条标准与 v2 新增的 5 条标准逐条核对结果见第 2、3 节。
唯一有保留的是"管理至少 3 个节点":面板确实管理了 3 个节点记录并验证了
故障隔离,但受限于只有一台测试 VPS,只有 1 个节点能真正部署 sing-box
(产品设计上一台机器只能承载一个节点)。

## 2. 原计划验收标准

| # | 标准 | 结果 | 证据 |
|---|---|---|---|
| 1 | 一个主控管理至少 3 个节点 | 通过(有保留) | 面板同时管理 3 个节点,两个不可达节点同步失败时,可用节点的同步与数据完全不受影响。受限于单台测试 VPS,只有 1 个节点能真正部署 |
| 2 | 创建用户后能自动同步到指定节点 | 通过 | 创建用户后协调器在数秒内触发部署,拨测读到 SSH 横幅,用户 UUID 可实际连接 |
| 3 | 删除或禁用用户后连接失效 | 通过 | 删除 Alice 后旧 UUID 连不上;停用 Bob 后从可连接变为断线 |
| 4 | 用户可通过一个订阅地址获得所有分配节点 | 通过 | `/sub/{token}` 返回全部已部署节点;把 sing-box 格式的产物原样导入并运行,下载 2,000,000 字节 |
| 5 | 可分别统计每个用户在每个节点的上下行流量 | 通过 | 两用户互不串扰(3,011,090 / 1,008,336 字节),上下行分开记录,按节点分布可查 |
| 6 | 所有节点流量可汇总为用户总流量 | 通过 | 用户详情的 `used_total` 由 ledger 累加而来,与按节点分布之和一致 |
| 7 | 超额或到期用户会被自动停用 | 通过 | Bob 用满 3MB 额度后自动转 QUOTA_EXCEEDED,重新部署把他从节点配置与统计白名单中一并移除 |
| 8 | 节点配置错误可以自动回滚 | 通过 | REALITY 私钥不配套的配置:systemd active、端口监听均通过,拨测失败并触发回滚,复验后节点恢复服务 |
| 9 | 主控重启不会丢失业务数据 | 通过 | Phase 7 演练 6:重启前后用户 2 个、累计流量 5,013,936、部署记录 4 条,完全一致 |
| 10 | 节点重启不会清空主控累计流量 | 通过 | 重启前后 Alice 累计均为 3,011,090;重启后产生 5MB(超过重启前计数值)完整入账 5,013,660,未漏算 |
| 11 | 节点无需 Docker 或常驻管理 Agent | 通过 | 节点上只有 sing-box 二进制 + systemd 单元 + 配置文件,无任何自研常驻进程 |
| 12 | 1C1G 节点可稳定运行 | 通过 | 见第 4 节压测:10 用户并发下 cgroup 实占 13.3 MB,远低于 1GB |
| 13 | 128MB 节点完成实验性测试并明确记录是否可用 | 通过,**可用且余量充足** | 见第 4 节 |

## 4. 128MB 低配节点压测

在真实 Debian 12 节点上用 systemd `MemoryMax`(cgroup v2 硬上限,超限即 OOM kill)
模拟低配 VPS,节点配置 10 个用户,每个用户一个客户端并发下载。

| 场景 | 峰值 RSS | 峰值 cgroup | 服务状态 | 重启次数 |
|---|---|---|---|---|
| 无限制,空闲 | 28.5 MB | 10.2 MB | active | — |
| 无限制,10 用户 × 2MB | 32.3 MB | 11.5 MB | active | — |
| **128M 限制,空闲** | 26.7 MB | 10.3 MB | active | 0 |
| **128M 限制,10 用户 × 2 轮 × 3MB** | 30.9 MB | 12.5 MB | active | 0 |
| **128M 限制,10 用户 × 3 轮 × 2MB** | 31.7 MB | **13.3 MB** | active | 0 |
| 64M 限制,10 用户 × 2 轮 × 2MB | 33.3 MB | 13.5 MB | active | 0 |

OOM 相关日志:0 条。重启次数:0。

**结论:128MB 节点完全可用,余量非常充足。** 满载 10 用户时 cgroup 实占约 13 MB,
只占 128MB 的十分之一。作为探底,64MB 限制下同样稳定运行未被 OOM kill。

需要注意 RSS 与 cgroup 计量的差异:RSS 约 30MB 中大部分是 mmap 进来的二进制页面
(精简构建二进制 27.8MB),而决定是否被 OOM kill 的 `memory.current` 只有 13MB。
这也解释了为什么用精简构建标签对低配节点收益明显(完整标签构建 cgroup 实占约 27MB)。

## 5. 故障演练结果

| # | 演练 | 结果 |
|---|---|---|
| 1 | sing-box 进程被 KILL(模拟 OOM) | systemd 在数秒内自动拉起;下次同步识别出重启,累计流量未回退 |
| 2 | 节点 API 不可达(服务停止) | 同步报错退出,累计流量 5,013,904 完全未变;面板记录该节点为同步失败 |
| 3 | 服务停止时执行部署 | 部署成功。同步步骤记为 SKIPPED 并说明"sing-box 未运行,无待同步流量" —— 崩溃的节点能通过部署恢复 |
| 4 | 节点 SSH 不可达 | 测试 SSH 5 秒内失败;同步失败;其他节点的数据完全未受影响 |
| 5 | 节点恢复 | 恢复后同步立即正常 |
| 6 | 主控重启 | 用户数、累计流量、部署记录三项完全一致 |
| 7 | 数据库备份与自检 | 备份生成(180 KB),完整性检查与外键检查均通过 |

演练 3 值得强调:如果"同步失败必须中止部署"是无条件的,一个崩溃或全新的节点
将永远无法通过部署恢复 —— 那才是真正的故障。正确规则是看 sing-box 是否**正在运行**:
在跑就必须中止(计数器里有未落库的流量),没在跑就跳过继续。

## 6. Phase 7 交付内容

### 命令

* `litebox backup` —— 用 `VACUUM INTO` 生成 WAL 安全的备份。
  直接 `cp` 主文件会得到一份缺少最近事务的副本;有测试专门验证
  50 条未 checkpoint 的记录必须出现在备份中。
* `litebox check` —— `integrity_check` + `foreign_key_check` + 各表行数。
  外键检查是必要的:SQLite 的外键约束可以在运行时关掉,
  历史上一次未开启约束的写入会留下潜伏的坏引用。

### 脚本

| 脚本 | 用途 |
|---|---|
| `../../../scripts/install.sh` | 建系统用户与目录、生成主密钥、写配置与 systemd 单元、迁移、启动。幂等 |
| `../../../scripts/upgrade.sh` | 先备份 → 换二进制 → 迁移 → 启动 → 健康检查 → 自检;任一步失败自动回退 |
| `../../../scripts/restore.sh` | 先校验备份本身再动现有数据库;恢复前的库另存一份 |
| `../../../scripts/setup-node-key.sh` | 生成面板专用的节点 SSH 密钥并安装公钥 |
| `../../../scripts/build-singbox.sh` | 构建带 `with_v2ray_api` 的节点二进制 |

### 部署文件

* `../../../deploy/systemd/litebox.service` —— 主控单元,含完整安全加固
* `deploy/systemd/litebox-backup.{service,timer}` —— 每日备份,保留 14 份,
  `Persistent=true` 保证关机期间错过的备份会补做
* `../../../deploy/nginx/litebox.conf` —— TLS 终止、登录与订阅分别限速
* `../../../deploy/logrotate/litebox` —— 仅在把日志重定向到文件时需要

### 一个安全问题的修正

**订阅地址会完整出现在 Nginx 的 `access_log` 里,那等同于明文凭据。**
日志备份、日志采集、误开的目录列表都会把它带走。
反代配置已改为对 `/sub/` 关闭 `access_log` —— 谁在什么时候拉过订阅,
LiteBox 自己有记录(用户详情页可见),不需要 Nginx 再记一份。

## 7. 已知限制

这些是设计上的选择,不是缺陷,但使用者需要知道:

1. **一台机器只能承载一个节点。** 节点上的路径(`/opt/litebox`)与服务名
   (`litebox-singbox`)是全局固定的,两个节点记录指向同一主机会互相覆盖配置。
   节点本来就是独立 VPS,为单机多租户拆分路径只会让部署事务与回滚逻辑复杂化。

2. **未同步窗口内的流量不可恢复。** sing-box 的计数器是纯内存的,
   进程退出即消失。意外重启(OOM、宿主机重启、崩溃)最多丢一个同步周期
   (默认 60 秒)的流量。面板自己触发的重启会先强制同步,不受此影响。

3. **用户变更需要重启 sing-box 才生效。** VLESS 用户列表无法热更新。
   面板把连续变更合并成一次重启(默认静默 4 秒),但重启仍会中断在线连接。

4. **主密钥丢失不可恢复。** 数据库与备份中的用户 UUID 与节点 REALITY 私钥
   都用它加密,丢失后只能重建全部用户与节点。

5. **REALITY 握手目标有 8192 字节的记录上限。** 新增节点时必须用
   「扫描握手目标」实测,且检测要在节点本机执行(CDN 按地域下发不同证书链)。
