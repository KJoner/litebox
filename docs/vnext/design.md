# VNext 设计决定与实施计划

需求见 `requirements.md`,现状见 `current-state.md`。本文只写**决定**与**理由**,以及每批的交付清单;
做完一项在清单里勾掉并写上提交号。不做 §17 Nexus Portal。

## 0. 总原则

* 渐进式:Go 单体 + Vue 3 + Ant Design Vue 不变;不换 ORM、不重写前端;
* **只要不是本次明确调整的行为,原有数据与使用方式一律保留**:旧库原地升级、订阅地址与 Token、凭据、入口、转发、探针与流量历史;
* 升级后默认不增加任何探测、付费任务、常驻 Agent 或额外核心;已关闭的功能保持关闭;
* 性能、内存、协议、客户端兼容性没有实测的,一律写「未验证」,不把目标写成结果。

## 1. 数据库(S2,DB01–DB11)

**引擎选择**:`database.driver` = `sqlite`(默认)/ `postgres`。环境变量 `LITEBOX_DB_DRIVER`、`LITEBOX_DB_SQLITE_PATH`、
`LITEBOX_DB_DSN`、`LITEBOX_DB_DSN_FILE`、`LITEBOX_DB_MAX_OPEN`、`LITEBOX_DB_CONNECT_TIMEOUT`、`LITEBOX_DB_STATEMENT_TIMEOUT`;
旧的 `LITEBOX_DATABASE_PATH` 映射到 SQLite 路径。PG 连不上直接报错退出,**绝不回落成一个空 SQLite**。

**SQL 写法:一份 SQL 两种引擎都认,而不是两套 SQL。** 79k 行 Go 里有 74 个文件写 SQL,复制一套 PG 版会让两边迟早分叉。做法:

1. **占位符在驱动层改写**:包一层 `database/sql` 驱动(`litebox-pg`),把 `?` 按词法改成 `$1..$n`
   ——跳过字符串字面量、双引号标识符与注释,与 sqlx 的 Rebind 同一种做法。**这不是对 SQL 文本做全局替换**:
   只认占位符这一种记号,其余一个字节不动;
2. **不可移植的写法在调用处改成两边都认的写法**:`LastInsertId` → `INSERT ... RETURNING id`(SQLite ≥ 3.35 支持);
   `INSERT OR IGNORE` → `INSERT ... ON CONFLICT DO NOTHING`(SQLite ≥ 3.24);`INSERT OR REPLACE` → 显式 upsert;
   `IFNULL` → `COALESCE`;标量 `MAX(a,b)` → `CASE`;`LIKE` 的大小写行为 → `LOWER(x) LIKE LOWER(?)`。
   **`ON CONFLICT DO NOTHING` 只吞唯一冲突**,不像 `OR IGNORE` 那样连 NOT NULL / CHECK 一起吞 —— 语义更窄、更对;
3. **布尔参数**:库里布尔列一律 INTEGER 0/1。PG 驱动层把 Go `bool` 参数转成 0/1,扫描时 `database/sql` 本来就把 0/1 转回 bool;
4. **事务的单写入者语义在 PG 下保留**:驱动层的 `BeginTx` 取一把进程内的写事务锁,`Commit` / `Rollback` 释放。
   SQLite 单连接下「事务里先查后写」天然是串行的(Boce 预算、续费幂等、端口冲突检测都靠它);
   PG 的 READ COMMITTED 不保证这一点。PG 模式只支持一个主控实例(下面的运行锁保证),所以进程内的锁就等价于全局串行。
   **不在事务外的单条语句仍然并发** —— 读请求不再排在写队列后面,这正是 PG 能带来的那一点好处。
   PG 连接池默认最大 5、空闲 2(DB08);
5. **类型**:PG 里整数一律 BIGINT(流量是字节数),`INTEGER PRIMARY KEY AUTOINCREMENT` → `BIGINT GENERATED BY DEFAULT AS IDENTITY`
   (导入时保留原 id,事后 `setval` 校正序列);时间仍是 RFC3339 的 TEXT;金额已是最小货币单位的整数。

**迁移**:SQLite 的 `migrations/` 只追加不变。PG 另有 `migrations_pg/`:`0046_baseline.sql` 是等价于 SQLite 0001–0046 的整份结构,
之后每加一个迁移两边各写一份,**版本号统一**(逻辑 schema version 一致),各自记各自的哈希。
`schema_migrations` 的形状两边相同;PG 迁移用 `pg_advisory_lock` 防双进程;**库的版本比程序新时拒绝启动**(两种引擎都做)。

**运行锁**:SQLite 在数据文件旁边持有一把 `flock`(Windows 上是独占打开);PG 用会话级 `pg_try_advisory_lock`。
第二个实例拿不到锁就拒绝启动。`litebox db ...` 这类离线命令同样要拿锁。

**测试**:所有包的测试库都经 `internal/database/dbtest.Open(t)`;设了 `LITEBOX_TEST_PG_DSN` 时每个测试建一个独立的临时库跑在 PG 上,
否则用临时 SQLite 文件。CI 增加一个 PG 服务容器的 job,同一批业务测试在两种引擎上各跑一遍。

**SQLite → PG 迁移工具**:`litebox db inspect | export | import | verify`(DB09)。
`import` 只往空库(或只有 `schema_migrations` 的库)里导;按外键依赖顺序逐表复制、保留 id 与密文、校正序列;
`verify` 比对每张表的行数与按主键排序的逐行哈希,再比对有效权限视图的结果集。主密钥不变、不重新加密。

## 2. 构建与部署(S3)

* 镜像 `kjoner/litebox`(linux/amd64 + arm64):主控二进制 + 前端 + 节点要用的全部产物(`assets/`:精简 sing-box、litebox-probe、
  mita / mieru、realm)与 `release-manifest.json`。容器内不装 Go / Node,不现场编译;
* 非 root(uid 10001),数据卷 `/data`(库、主密钥文件、节点访问私钥都在里面),根文件系统可只读;不挂 Docker socket、不用 host 网络;
* Compose 三份:`compose.yaml`(SQLite)、`compose.postgres.yaml`(叠加一个 PG 17 服务,不发布 5432)、
  `compose.external-postgres.yaml`(只改连接参数与外部网络);
* 发布:`.github/workflows/release.yml`,只在 `v*` tag 上跑 —— 测试 → 构建节点产物 → buildx 多架构推送 → 冒烟 → 校验推送后的 digest → GitHub Release
  (二进制、`SHA256SUMS`、manifest、SBOM)。**预发布 tag 不动 `latest`**。需要仓库 secrets `DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN`;
* `deploy/docker/litebox.sh`:install / status / backup / verify-backup / restore / update / logs;重复执行沿用已有 `.env` 与 override,版本相同且健康时不重启;
* 原生安装:`litebox-install.sh` 默认下载 GitHub Release 的预编译包并核对 sha256;`--build-from-source` 保留旧路径。

## 3. 授权与链路(S5,AUTH01–04、CHAIN02–05、UI06)

迁移 0049(两种引擎各一份):`user_inbound_grants(proxy_user_id, entry_kind, entry_id, created_at)`,`entry_kind` ∈ SINGBOX / MIERU
(两张入口表的 id 会撞,所以种类 + id 才是身份);`proxy_users.access_mode` ∈ INHERIT(默认)/ DIRECT_ONLY;
`node_inbounds.restricted` 与 `node_mieru_inbounds.restricted`(入口「仅指定用户」)。

归属集合:INHERIT 模式 = `G ∪ N ∪ D`,DIRECT_ONLY = `D`;入口 restricted 时还必须属于 `D`。
硬条件(账号停用 / 过期 / 超额)由 `User.Serviceable` 在 Go 侧照旧拦,入口停用 / 删除、机器删除在视图里拦 ——
直接授权**只**能越过等级门槛。**改的是视图**(`user_effective_inbounds`、`user_effective_mieru_inbounds`,
`user_effective_nodes` 是前者的投影随之变化,`user_effective_relays` 跟着重建),配置编译、订阅、门户、脏标记全都已经查视图。
旧数据:默认值让归属集合逐用户不变,`grants_upgrade_test.go` 对四个视图升级前后逐行比对。

* **授权没有单独的到期时间。** 需求里没有硬性要求,而它会让「这个人今天能不能用」多出一个只有定时任务才会去重算的条件 ——
  到期那一刻没有任何东西会把节点标脏,凭据会一直留到下一次别的原因触发部署。要限时就给用户本身设到期;
* **预览不另写规则**:`PreviewAccess` 在事务里写进去、读视图、回滚 —— 预览与保存是同一份判据;
* **撤权取前后并集标脏**(sing-box 入口所在的机器);Mieru 入口逐入口下发,不自动做,结果里单列 `mieru_pending`;
* **撤权收敛只读库里的配置状态**,按机器说「撤销待下发 / 已撤销 / 下发失败 / 离线」,新连接与已有连接分开说:
  sing-box 下发会重启进程,已有连接随之断开;Mieru 走 `mita reload`,旧会话可能继续存活;离线的机器不说已阻止任何东西;
* **链路**:`ChainPathFrom` 把一条服务端链路整条走一遍(每跳协议取 `deployed_*`、停用 / 没部署 / 拼不出出站逐跳标出、
  最终出口、DNS 位置);`SetChain` / `SetMieruChain` 补上两道拦截 —— **成环**与**落地已停用**(在此之前 A → B → A 存得进去);
* **快速组链**只做「保存草稿」:新建入口 + 把出口写进库 + 可选的仅指定用户,一个字节都不下发;下发走已有的
  `POST /api/inbounds/{id}/chain`(先落地、后入口机、真实拨测、失败回滚)。出口在建入口的**同一步**写进库,
  否则中间任何一次顺带触发的下发会把新入口按直连部署上去(CHAIN05 禁止的静默回退);
  预览里有问题(同机、端口被占、成环、下游停用、外部代理拼不出出站)整个拒绝;
* **多跳的拖动编辑没有做**:链是逐跳设的(每个入口只有一个下一跳),跳点卡片是按方向排列的只读预览,
  替换出口在同一个弹窗里选;「一个中转配多个落地」的批量也没有做;
* **批量排序**(`POST /api/sort-order/batch`):带每一项的旧值,一个事务里核对后写入,有冲突整组拒绝(409);
  只收机器 / sing-box / Mieru / 转发四类(外部代理改排序要锁字段,仍走单条)。新值沿用这一组原来占着的值重新分配,
  组外条目一个不动。

## 4. 其余批次的取舍

* **S1 任务模型**:`tasks` 表 + `GET /api/tasks/{id}`;部署 / 安装 / 重启等长操作支持 `?async=1` 立即返回 `task_id`,
  前端进度弹窗改为轮询。同步调用保留(脚本与旧页面还在用)。主控重启时运行中的任务标 `INTERRUPTED`,**不自动重放**;
* **S1 执行器接口**:`executor.Executor`(`Do` / `TryDo` / 结构化结果),先有 `SSHExecutor`;Agent 在 S6 作为第二个实现;
* **S4 视觉**:令牌换成 Nexus R1.5 / R2 的暖炭 + 琥珀,默认深色;浅色单独定一套对比度;布局与信息架构按 §04.2 调整,接口与权限不动;
* **S6 计费**(已做):`proxy_users.billing_mode`(SUM 默认 / UP / DOWN / MAX)+ `billing_multiplier_pct`(100 = ×1)+ 规则版本;
  改规则默认下一周期生效,立即生效封存旧段;额度检查先按周期聚合 U/D 再套函数,不逐样本取大;
  节点额度可改用 vnStat 网卡实测,分界之前仍按代理折算、两段分开;计量网卡可指定;
* **S6 Agent**(已做):可选,默认关,只做状态采集(计划内探测没有做),节点主动 HTTPS 上报;握手之后才切换资源采集的写入者,
  超时没报 SSH 自动接手;配置下发仍走 SSH;
* **S7 新协议**:先做 Trojan(sing-box 入站 + REALITY 或证书),逐项记录能力矩阵;Hysteria2 / TUIC 需要 `with_quic`,只给选了它们的机器分发能力构建;
* **S7 客户端**:Stash 走 Clash 系 serializer 的能力子集;Surge / Loon / Quantumult X 各写 serializer,商业客户端无法自动验证的标「未人工验证」。

## 6. 视觉(S4)

(base `#1b1a17`、ink `#efeae1`、amber `#e6c08a` / `#f1d3a6`、ok `#a7bf9f`、warn `#e3a35b`、error `#e9765f`、unknown `#9a948a` 一档),
**默认深色**;浅色是单独定的暖纸色,琥珀在浅色下换成深琥珀 `#8C5D16`(浅琥珀做文字只有 1.7 : 1)。
圆角:卡片 16、弹窗 18、控件 10;轻动效 140–220 ms,外观里可选「减弱 / 关闭」(`<html data-motion>`)。
