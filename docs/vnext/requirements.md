# LiteBox 大版本升级需求与实施方案

版本：需求基线 1.0  
日期：2026 年 11 月 6 日  
适用项目：KJoner/litebox，配套修改 KJoner/nexus-portal  
执行对象：Claude Code 与项目维护者

## 01 本次升级的目标与决定

我们要把 LiteBox 打磨成适合个人长期使用的节点管理工具：页面打开快，添加节点步骤短，入口与用户关系清楚，链式代理容易配置，流量数字有明确含义，升级和恢复可靠。管理员与普通用户界面一起改造，视觉沿用 Nexus Portal 的暖炭色、琥珀强调色和设置中心风格，同时保留 LiteBox 面向节点运维的信息密度。

本次采用渐进式重构，继续使用 Go 单体、Vue 3 与 Ant Design Vue。保留现有数据、账号、订阅地址、节点凭据、入口、转发、探针和流量历史，在已有能力上改善结构与操作。主控增加预构建 Docker 镜像和 Compose 部署；节点继续提供原生程序与 SSH 管理，64/128 MB 节点不强制安装 Docker 或常驻自研 Agent。

数据库保留 SQLite 默认模式，增加新建 PostgreSQL 和接入已有 PostgreSQL 两种模式。LiteBox 与 Nexus Portal 可以连接同一个 PG 实例，但分别使用独立数据库和独立账号。两套应用各自迁移、备份、升级和认证，不互读业务表。

**优先级含义**：P0 是升级发布必须通过的基础与兼容要求；P1 是本次大版本的后续交付批次，不能在只完成 P0 后宣称全部需求完成；P2 是明确留待后续的扩展。性能与内存数字均为拟定验收目标，需要基线测量验证，不代表当前版本或参考产品已经达到。

### 01.2 本次不扩张的范围

不新增公开注册、支付、订单、优惠券、推广返佣、拼车市场、商业套餐销售或工单系统。现有基础订阅、用户专属配置下载和凭据管理必须继续工作，但不把复杂订阅运营作为本次主线。不引入必须部署的 Redis、消息队列、微服务或 Kubernetes。不因视觉统一而重写为 React，不引入通用远程命令执行平台。

用户已经明确要求增加 PG 和可选 Agent。因此应同步修订 `CLAUDE.md` 中“仅 SQLite”和“禁止任何常驻自研 Agent”两条旧约束，并注明本次需求依据；其他有效约束继续保留。不得把该局部调整扩大为取消所有低资源、权限或部署安全约束。

### 02.2 LiteBox 已有能力应直接继承

当前 LiteBox 已经拥有多入站、nginx/realm 转发、服务端链式代理、客户端模板 detour、URI/Clash/sing-box 导出、外部代理与导入、Mieru 独立核心、节点地址池、用户门户、访问等级、部署事务、配置差异、主机流量、用户流量账本，以及本地、BOCE、指定节点和 HTTP 探针等基础。需求执行时首先区分“已有但不好用”和“确实缺失”，避免重复建模。[L01][L04][L07][L08][L14]

以下现状尤其需要正确理解：

1. **流量已经覆盖多个来源**。代理用户流量使用 sing-box 与 Mieru 独立实例计数器、账本和日聚合；主机流量使用 vnStat，并可通过 SSH 读取网卡累计计数。全站链式汇总已有内部链身份去重，按主机仍保留各跳实际消耗。不能把本次工作写成从零添加网卡统计或链式去重。[L04][L05][L18]
2. **页面已经做过部分优化**。路由使用懒加载，仪表盘各块已有失败降级，多个查询并发发起，实时网速由主控缓存配合短期采样租约提供。应保留这些机制，再测剩余瓶颈。[L02][L03]
3. **数据库仍深度依赖 SQLite**。Go 使用 `database/sql` 和 `modernc.org/sqlite`，当前连接池为一条连接，迁移及业务 SQL 需要逐项适配 PG。切换连接字符串不足以完成改造。[L06]
4. **Mieru 已使用官方发布二进制**。需要迁移的是产物准备与分发流程；sing-box 的精简构建和 `with_v2ray_api` 标签承担了现有计量功能，不能未经验证换成默认构建。[L09][L10]
5. **主控安装仍有现场构建步骤**。`litebox-install.sh` 会准备工具链、拉源码、构建主控与辅助程序；这是预构建镜像和发布产物要解决的实际部署问题。[L11]
6. **主控产物缓存有改进空间**。二进制分发器把完整文件按架构缓存在内存，查询哈希也可能触发完整读取。需要用可观测数据确认其常驻和峰值成本，再改为流式分发与磁盘缓存。[L12]
7. **两项核心行为已经完成**。`?format=sing-box` 已生成可用的原生极简配置；部署入口已在配置 SHA 相同且未强制部署时跳过重启。应做兼容回归，不能以过时注释为依据重做或退回旧行为。[L14][L19]

### 02.4 实现方式的借鉴与修正

**链式引用使用稳定 ID。** 经典版创建单链时复制出口端点、保存中转节点 ID，在导出时解析当前名称并写入 dialer-proxy；目标改名不会破坏关联。实际方向是“客户端 → 被引用的中转 → 出口 → 目标”，不能根据界面 source/target 名称猜测流向。快速链式生成器添加“落地/中转”选择组，首先只修改草稿。LiteBox 复用稳定 ID 思路，同时显示运行位置、真实方向和发布状态。[M02][M03][M04]

**拖拽应改善操作，也要解决持久化。** 经典版支持多选保持相对顺序整体移动，桌面拖动阈值与手机长按防误触；排序先本地更新再防抖保存。审阅的离页清理逻辑只取消定时器，未提交剩余更新，说明不能照抄其保存细节。LiteBox 要补保存状态、跳页提交/保留草稿与版本冲突处理。[M02]

**以能力矩阵管理格式。** 经典版通过共享解析包和格式 producer 处理多种客户端，代码注释记录过 Mieru 参数转换丢失问题。应学习分层适配，测试协议、传输、安全、端口范围和链路参数的保真；“格式名称存在”不代表所有组合可用。[M06]

**健康检查按层级解释。** 经典版区分 TCP 连通与完整协议连接，完整测试会启动 mihomo 子进程，其调度默认关闭并受并发限制。LiteBox 保留轻量任务，把重测试放在主控或明确的测试节点；不随 UI 刷新在 64 MB 节点启动额外完整核心。[M08]

**流量展示不能替代账本。** 经典版汇总 Nezha、DStatus、Komari 等探针和外部订阅额度；部分显示路径把已用量截到额度上限。LiteBox 只借鉴数据源组织，原始用量允许超额，进度条封顶不修改实际数字；同步外部数据也不应阻塞普通页面 GET。[M07]

**X 的工作流可借鉴，内部实现另行设计。** 服务器与入站分离、简单/专家模式、草稿/已下发状态、逐跳路径与计量口径很适合 LiteBox。它的“仅监控”仍安装 Agent；一些限速、协议和嵌入能力依赖定制核心。公开安装脚本虽有 PG 参数，仍需为我们的已有 PG 单独设计不创建数据库服务的向导，不能直接复制默认安装分支。[X02]–[X08]

参考实现必须先核对授权。两仓库 README 的许可声明不能替代具体文件及依赖的许可证检查；引用代码须保留必要声明。妙妙屋 X 公开可访问的安装资料不等于未公开主控源码可复制。本项目可独立实现文档所描述的操作体验。

## 03 产品对象与架构边界

### 03.1 统一术语

| 对象 | 含义 | 与其他对象的关系 |
| --- | --- | --- |
| 主机 | 一台可管理 VPS 或容器，持有管理地址、SSH 或 Agent 身份 | 一台主机可运行多个入口与多个受支持核心 |
| 入口 | 用户连接的协议、监听端口、公开地址与凭据配置 | 属于主机，可绑定用户，拥有自己的部署状态 |
| 外部节点 | 别人已经部署好的代理端点 | 可导入、导出或作为链路出口，不自动视为可管理主机 |
| 转发入口 | TCP/UDP 转发的监听与目标映射 | 与协议入站分清，沿用 nginx/realm 等现有能力 |
| 链路 | 从用户接入到最终出口的有序关系 | 引用稳定对象 ID，不用显示名称作为关联键 |
| 探测任务 | 指定来源、目标、方式、频率和预算的检测 | 与卡片展示选择分开 |
| 用户授权 | 允许哪个用户使用哪些入口及其有效期 | 控制真实凭据下发、配置下载、门户展示和撤销 |

当前数据库里 `nodes` 主要承担主机职责，已有入站和地址池可继续复用。本次先统一服务层与 UI 术语；只有现有表确实无法表达需求时才新增表，不做无收益的全库重命名。外部代理、地址池中的多个 IP、同主机多个入站均不得误计成多台主机。

### 03.2 主控与执行端

主控保持一个 Go 应用进程，提供 API、调度、配置编译、授权判断、计量和持久化任务。增加执行器接口，至少实现 `SSHExecutor` 和 `AgentExecutor`，让部署、采样与探测调用统一的结构化任务。两种执行器共享配置校验、期望版本和结果模型，不能各写一套业务规则。

一个主机同一时刻只能有一个配置写入者。切换执行模式需要完成在途任务处理、计量基线交接和旧连接撤销，不能让 Agent 与 SSH 同时更新配置或重复记账。主控故障时，已部署的代理服务继续工作；中央监控与新配置下发暂停并显示最后成功时间。

PG 模式首先支持一个主控实例。使用 PG 不自动意味着支持多个调度实例或高可用；多个实例同时运行会涉及任务租约、幂等和领导者选举，本次不对外宣称支持。

运行期必须有单活动主控锁或等价机制，第二个实例不能启动调度和远程写入；失去运行锁时停止提交新变更。迁移锁不能替代运行期约束。隔离测试/恢复实例使用明确的只读或演练模式。

| 入口与链路 | 协议入口、转发规则、链式代理 | 配入口、绑定用户、快速组链 |
| 用户与权限 | 用户、入口授权、额度、有效期、会话 | 授权、停用、重置、查看生效状态 |
| 监控与流量 | 主机/代理/用户流量，入站出站探测 | 查看趋势、调整任务与口径 |
| 操作记录 | 部署任务、失败项、审计 | 查看差异、重试、回滚 |
| 设置 | 连接、运行、外观、数据库、备份、通知 | 查找设置与验证配置 |

**UI04 首屏层次**：顶部概况采用少量稳定指标；异常优先列出原因、影响对象和下一步动作。主机卡片保留实时速率、周期流量、到期/费用、入站与出站探针。列表/卡片切换、筛选、搜索、排序和滚动位置在返回页面时保留。正常状态不能掩盖采样过期、同步失败或配置尚未生效。

**UI05 操作反馈**：区分“已保存”“待应用”“应用中”“已生效”“失败待处理”。显示配置期望版本与已应用版本。同步按钮显示正在处理的目标与阶段；批量任务返回每项结果，支持仅重试失败项。页面加载错误只影响相应模块，保留旧数据并显示更新时间。

**UI06 拖拽**：用于主机显示顺序、分组、入口顺序及链路跳点。必须提供键盘或上移/下移替代、清晰落点、保存失败回退。纯排序不触发节点部署；改变链路属于配置变更，需要预览和显式应用。筛选状态下排序需定义只调整可见项还是完整顺序，默认只在明确的排序模式开放。

支持单项与非连续多选整体拖动；多选保持相对顺序，落点在选中项内部时不产生变更，拖动未选项只移动该项。个人列表偏好与影响门户/订阅的业务排序分开，后者保留现有 LEGACY/GLOBAL 语义并预览结果。分页、筛选和虚拟化不能丢失隐藏对象或覆盖其顺序。排序只提交对应字段与版本，显示未保存/保存中/成功/失败；跳页前提交或保留待保存状态，刷新和并发冲突不得静默丢失操作。[L15]

### 04.3 普通用户端

**UI07 用户首页**：优先显示可用状态、剩余额度/不限量、到期时间、下一次重置、可用入口与复制/下载配置。流量趋势标明统计区间、计量口径和最近更新时间；被停用、过期或超额的用户仍可登录查看原因，沿用现有账号登录规则。

**UI08 用户操作**：根据用户选择的客户端显示可用格式、安装/导入提示和不支持的协议说明。普通用户不接触 SSH、Agent Token、主机内部名称、运维地址、部署路径、管理端日志或其他用户数据。入口列表和配置下载使用同一授权结果。

**UI09 移动端与设置**：覆盖桌面 1440、1366 和手机 390/375 px 宽度。手机表单采用整页或底部面板，主操作区域不被键盘遮挡；关键触控目标建议至少 44 px。支持设置搜索、未保存提示、重置当前分组和连接测试。只影响显示的开关可即时保存；数据库、凭据、配额与远程配置需明确保存/应用结果，不能采用离线自动补发危险动作的模式。

**验收**：管理员与用户端关键路径均覆盖浅/深主题、错误、空数据、部分过期、无权限和移动端。颜色、圆角、字体、控件和微文案形成统一规范；不出现只完成管理端、用户端仍为旧版的交付。

## 05 节点与主机的创建和编辑

**NODE01 类型选择**：新增时先选择“自建主机”或“已有外部节点”。从 URI/配置粘贴导入可以直接识别为外部节点；没有 SSH 或 Agent 管理权限时，不能引导用户安装服务端。

**NODE02 自建主机的首屏字段**：第一组只放名称、管理 IP/域名、SSH 端口、SSH 用户和认证方式。密码或密钥用独立字段，不与代理密码混用。紧接第二组放“同时创建默认入口”、协议、监听端口及协议必填项。主机保存可独立完成；入口的安全凭据可生成默认值。

**NODE03 外部节点的首屏字段**：名称、服务地址、端口、协议及该协议需要的 UUID/密码/密钥放在同一块。切换协议只展示相关字段。区分 SSH 端口、服务监听端口和公开映射端口，并通过示例说明 NAT 映射。

**NODE04 高级信息**：展示名称、地区、分组、标签、排序、额外 IP、公开地址池、流量配额与周期、到期/价格、核心版本、监听调优、探针选项置于折叠区域。只填首屏必需信息即可创建。展示名称为空时默认取名称，用户端仍只读取公开展示字段。

**NODE05 保存行为**：保存对象与安装/部署为不同动作。保存后可选择“测试管理连接”“安装并部署”“稍后配置”。连接测试采用超时和结构化错误，不把 SSH 成功等同于代理可用。失败时保留所有非敏感输入；密码不回显，后端响应不返回保存的密钥。

现有一次性 root 引导密码只用于安装并验证面板公钥，不落库、不写日志，也不得进入持久化任务 JSON。“稍后安装”可保存待接入对象并在接入时重新输入口令，或先完成公钥接入再延后核心安装。SSH 主机密钥发生变化需明确核实和接受，不能因编辑地址自动重建信任。[L25]

**NODE06 编辑与批量操作**：主机地址修改需要提示对管理连接的影响；展示、排序、账单和探针名称修改不重启核心。支持复制节点配置模板、批量分组、批量调整展示和导入预览；复制时重新生成适用的私有凭据，不能静默复制唯一身份。批量导入显示新增、更新、重复、无效与待确认条目。

**验收**：熟悉 SSH 的用户在无可选资产信息的情况下，能完成一个可保存的自建主机；IPv4、IPv6、域名、NAT、密码和密钥认证分别验证。必填错误在对应字段附近出现，协议切换不把不相关字段写回配置。后端校验与前端一致。

## 06 用户管理与入口授权

**AUTH01 直接授权**：在用户编辑页选择可用入口；在入口详情反向查看并管理被授权用户。支持一用户多个入口、一入口多个用户，并可设置入口仅供指定用户。现有访问等级、节点额外授权和入口等级必须保持兼容，不能改造后扩大旧用户权限。

**AUTH02 授权政策的唯一来源**：在现有 effective access 视图/仓储基础上扩展。当前是入口等级继承与整机额外授权，并非主机等级门槛；不得重新启用已经冻结的主机等级限制。入口标识使用种类加 ID 或统一身份，避免 sing-box/Mieru/转发不同表的 ID 重号。[L16]

明确分为“授权归属集合”和“当前可提供服务集合”：前者保留用户与入口的关系，不因账号停用/超额而消失；后者再应用账号、资源和部署可用条件。配置、导出和门户使用同一政策服务，允许展示的状态与实际服务能力分别返回。撤权影响范围必须取变更前后归属集合并集及已部署记录，不能先停用用户再查空集合，漏掉需要删除凭据的主机。

配置编译使用“期望授权与凭据集合”，不把已经部署或当前在线作为授权前提，避免首次部署的循环依赖。门户与导出可以按现有发布条件显示当前可用结果；新建未部署、离线待撤权、停用但保留归属都是合法且不同的状态。

**AUTH03 组合与迁移规则**：令 G 为有效入口等级继承集合，N 为旧整机额外授权展开后的入口集合，D 为有效直接入口授权集合。默认“继承等级并添加”模式的归属为 `G ∪ N ∪ D`；管理员明确切换“仅指定入口”后，归属为 D。入口启用“仅指定用户”时，该入口还必须属于 D。直接授权可越过入口等级门槛，但不能越过账号停用/过期/超额、对象删除/停用或入口关闭等硬条件；额度为 0 的现有不限量语义保持不变。`unmetered` 表示不参与该入口计量，不自动成为被停用或超额账号的访问豁免。

旧数据默认保持原模式与入口限制开关。逐用户比较迁移前后的归属集合与可用集合；缺失授权不能通过扩大到整台主机来补齐。新增直接授权不改变旧等级继承和整机授权。切换限定模式先预览将增加/移除的入口、受影响主机和共享凭据限制；不增加含糊的 deny 优先级体系。

**AUTH04 真实撤权**：停用或撤销入口后，更新节点配置中的对应凭据，并展示“撤销待下发/已撤销/失败”。分别报告新连接是否已拒绝、已有连接是否已终止，不能从凭据更新推导所有旧连接立即断开。节点离线时不能声称已经阻止其现有连接。提供受影响主机和待收敛列表，恢复连接后优先处理权限撤销。历史计量与审计保留。只改订阅可见性不算完成撤权。

**AUTH05 独立身份**：继续保持管理员和门户独立 Cookie、会话和中间件。普通用户 ID 从会话取得，不接受请求参数决定读取哪个用户。新增只读运维角色可以在管理员体系内实现，默认角色至少覆盖管理员和普通用户；对象级校验不能只由前端按钮承担。

**AUTH06 额度与凭据**：每用户每入口能使用独立身份时，应使用可稳定映射的统计标识；协议只能共享 PSK 或无法识别用户时，明确显示用户级隔离/计量限制，不伪造精确的用户配额。重置口令、撤销设备或订阅 Token 不必同时轮换 SSH 密钥。

共享 PSK 模式无法只撤销一人的已知秘密：界面需提供迁移独立身份、另建独享入口或轮换共享密钥并通知其影响范围的明确选择；不能把隐藏入口当成旧凭据已经失效。能否主动断开现有连接也按核心能力说明。

**验收**：用户 A 无法通过修改 ID、导出参数、WebSocket/SSE 订阅或缓存命中获得 B 的入口、凭据、流量和资料。增加/撤销授权在 UI、生成配置和实际连接上结果一致；过期、额度耗尽、维护和未部署各有明确状态。权限迁移必须通过集合对比和旧版本回归测试。

## 07 链式代理与快速组链

### 07.1 明确链路在哪里运行

**CHAIN01 两类模式**：服务端链路表示入口主机上的核心继续连接下一跳；客户端链路表示客户端导出的配置指定上游代理，例如 `dialer-proxy` 或 `detour`。它们影响流量路径、客户端兼容性和计量边界，编辑器必须显示运行位置，不能用相同的“链式代理”按钮静默混用。妙妙屋的节点链式配置主要可作为客户端链路与分组操作的参考。[M02][E01]

LiteBox 现有服务端链式能力优先打磨，并保留已有客户端模板 detour。P0 完成服务端“入口 → 出口”两跳的快速创建、替换与可靠应用；P1 完成客户端快速组链/候选组和经过验证的线性多跳，默认上限 4 个代理跳点，可根据资源验证进一步限制。分支、自动最优选路和复杂负载画布列为 P2。候选中转池是择一使用，有序多跳是依次经过，两者使用不同字段与控件。

服务端链导出只包含用户连接入口所需凭据，不暴露内部专用链身份。客户端链需要各跳获准使用的用户凭据，不能误删这些必要字段，也不能混入 SSH 密钥、Agent 身份或服务端内部身份。[L14][L17]

### 07.2 快速操作

**CHAIN02 快速创建**：在可管理主机的入口菜单提供“作为入口组链”；在可用自建入口与外部代理菜单提供“作为出口组链”。外部代理不能因被选中就变成可部署的服务端入口。用户选择另一端、名称、协议/端口和使用用户后即可看到完整路径。默认继承合理参数，并明确哪些入口将新建、哪些既有对象会修改。客户端组链入口单独标注，仅可选用户获准连接的端点。

**CHAIN03 顺序与预览**：跳点以有方向的有序卡片展示，支持拖动、插入、替换、上移和下移。显示每跳主机、接入协议、下一跳、TCP/UDP 能力、DNS 解析位置、预计修改范围和最终出口。名称更改不能改变底层引用。批量“一个中转配多个落地”应先预览产物数量、端口分配与授权，再提交。

**CHAIN04 静态校验**：禁止环路、自引用、重复绑定同一监听地址和端口、已删除或无权限的目标、协议不兼容、缺少 DNS/TLS 参数。UDP、端口范围、IPv6、域名解析及 QUIC 等能力逐项校验；不支持时直接解释，不能保存一条注定不可用的链。一个普通地址转发规则不应自动宣称拥有代理协议转换能力。

**CHAIN05 应用流程**：服务端链执行“保存草稿 → 编译配置 → 差异预览 → 候选配置校验 → 先准备出口/下游 → 再应用入口/上游 → 真实链路拨测 → 标记生效”。外部出口只验证能力与连接，不尝试管理其机器。多个主机的变更是可恢复的分阶段操作，不宣称数据库事务能原子控制全部服务器。失败时记录已经变更的对象，对可回滚项执行补偿，保留管理连接和旧可用配置。客户端链执行“保存草稿 → 权限与依赖校验 → 目标格式校验 → 预览并导出”，不进入远端部署流程。任一依赖被删除、禁用或失去授权，都应报错/禁用受影响链，禁止静默回退为直接连接出口。

**CHAIN06 计量规则**：同一用户的一次业务数据经过两个自管跳点时，用户额度只在指定计费入口扣一次；每台主机仍独立记录自己的网络成本。现有链式内部凭据与不计量处理先做回归，再扩展多跳。路径变更不回写历史账本，历史记录保留原链路与计量规则版本。

**验收**：覆盖自建入口到自建出口、自建入口到外部代理、nginx/realm 透传、节点离线、目标被删、循环、UDP 不兼容、端口冲突、下游准备失败与上游回滚。界面路径必须与实际出口拨测一致；纯改显示顺序不重启任何核心。

## 08 流量口径与控制

### 08.1 三种流量必须分开

| 指标 | 数据源 | 主要用途 | 不应当承担的用途 |
| --- | --- | --- | --- |
| 主机流量 | 指定网卡计数器、vnStat 或 Agent 主机采样 | VPS 带宽套餐、账单、主机用量 | 直接分摊给每个用户 |
| 代理流量 | sing-box/mita 等核心统计接口 | 入口和核心运行、用户业务字节 | 替代服务商账单 |
| 用户计费流量 | 指定计费点的用户字节，经规则计算 | 用户额度、周期重置和限额 | 把整条链路各跳简单相加 |

**TRAFFIC01 页面说明**：每个数字标明口径、方向、周期、数据源与更新时间。网卡 RX/TX 是主机视角；用户上传/下载是用户视角，不能直接用相同中文标签混在一张无说明表里。主机网络用量包含代理之外的 SSH、更新和其他服务，允许与代理业务字节不同。

原始用量与超额数字完整保留，不能把 used 截断为 quota；只有进度条的视觉宽度可以封顶。变更主机统计来源或方向不得自动改变用户额度口径或历史账本。

**TRAFFIC02 计费公式**：支持上行、下行、双向合计和双向取大，记录 multiplier 与规则版本。先按同一计费对象、同一结算周期与同一规则版本聚合 U/D，再计算 U、D、U+D 或 max(U,D)，最后应用倍率。双向取大不能把每次采样、每天或每个内部跳点的 max 相加。默认规则只在新周期生效；若立即变更，应封存旧规则段，明确新旧分段合计，不把分段结果伪称为全周期同一规则结果。原始方向字节必须保留。GiB/GB 和倍率必须明确，不得将 1 GiB 与 1 GB 混算。

**TRAFFIC03 主机网卡**：保留 vnStat 路径，允许明确选择计量网卡；默认排除 loopback、docker/veth/tun 等不应重复累计的接口。默认路由只是候选，IPv4/IPv6 不同出口、多网卡、网卡改名和 LXC 必须可人工确认。没有常驻采集器时可用 SSH 快照差值，但需要提示离线与重启造成的缺口。

**TRAFFIC04 入口粒度**：现有用户计数器不天然具有“用户 × 入口”的联合维度。当前同一主机多个入口显示同一个用户主机总量时，必须标明是主机口径；不可把该数当成每个入口独立用量并再次汇总。入口级用户额度必须有可验证的独立身份/计数维度后才开放，否则显示“不支持此粒度”。[L13]

旧节点周期 `EGRESS/BOTH` 使用代理 U+D 再乘 1/2 估算主机计费用量，必须保留为明确的“代理折算”来源，不能迁移时直接当成真实网卡 TX/RX+TX。历史不具备网卡证据的区间标记为旧估算，切换实测来源建立新基线并展示分界；该折算规则也不能套用到用户历史额度。[L24]

### 08.2 账本与异常恢复

**TRAFFIC05 幂等**：保留现有单调累计计数、账本、日聚合和重启判断，扩展采集源、启动 epoch、样本序号、采集时间与规则版本。Agent 重传、主控重启或网络重试不得重复入账；用户代码、主机、核心实例、方向与批次的唯一性需由数据库约束保证。

计量按远端实际已应用的配置版本解释身份、shared/unmetered 和计费点；期望配置尚未下发时，不能提前按新模式记账。计费对象需要跨入口汇总时先合计该对象 U/D，再取方向函数；逐入口独立结算与用户总额度结算必须分开命名。

**TRAFFIC06 重启与切换**：核心重启与主机重启分别识别，继续使用核心 uptime 等可靠信息，不能只看“计数器变小”。计划重启必须在获取 SSH 节点锁之前执行计量同步，不能在锁内再调用需要同一锁的采样；同步失败且核心仍在运行时中止部署，核心已停止时才走恢复路径，不得把该约束弱化为忽略错误。SSH/Agent/vnStat 数据源切换必须建立可核对的交接点，同一段时间不可重复累计。

**TRAFFIC07 数据质量**：区分未知、从未采样、过期、采集失败、统计不支持和真实零流量。异常跳增、时钟跳变、计数器归零和超长空窗记录原因；没有证据时标记缺口，不用平滑或填零掩盖。历史修正使用带备注的调整记录，不覆盖原始账本。

**TRAFFIC08 周期**：用户额度周期与服务商主机结算周期独立配置，支持每月指定日、自然月和固定周期。时区、周期起止、当月无该日的处理写入规则；内部时间统一 UTC，展示按设定时区。规则变更默认下一周期生效；立即切换需先显示旧新口径差异，不追溯静默扣费。

### 08.3 限额与断线行为

**TRAFFIC09 限额**：提供提醒阈值、停止接受新连接/撤销凭据等受核心支持的控制；主机限额与用户限额分开。不得默认关闭整台主机来实现用户配额。已有阿里云 CDT 自动处置只保留显式启用对象与现有授权。

普通主机额度沿用现有默认预警行为；任何新增强制处置需管理员显式启用。P1 可增加有能力支持的速率/连接数策略，显示最终规则与来源、单位和实际生效状态；连接数不得命名成设备数。当前核心不支持的用户级硬限速不能仅靠 UI 开关宣称生效，也不为追求该功能强制替换所有低资源节点核心。

SSH 轮询模式的限额具有同步与部署延迟，不能承诺逐字节硬配额。可以估算最大超额约为“实际速率 × 采集及下发延迟”，并显示最后成功同步时间。Agent 只有在已实现本地可识别用户计量和本地执行规则后，才可声称断开主控仍执行该限额；不支持的核心明确降级为告警或中心轮询。

**验收**：用固定流量夹具验证 upload/download/sum/max 和倍率；重复样本计费不变；重启、来源切换、月末/闰年/时区边界正确；多跳不重复扣用户额度；采样失败不归零；有独立计数维度的入口与用户实测一致。代理字节测试与网卡字节测试分别建立基准，允许并说明网络协议开销差异。

## 09 探针与状态展示

**PROBE01 继承范围**：保留主控到入口、指定自建节点到入口、自建节点到公共目标、BOCE 入站、TCP/ICMP/HTTP、卡片自定义显示名与入站/出站各最多 3 项展示。已有功能先核对接口和回归测试，不重复开发同名模块。[L07][L08]

**PROBE02 方向明确**：任务字段包含 `source`、`target`、`method` 和观测范围。主控能连接入口不代表亚洲用户能连；节点到公共目标的探测不能显示成主控到节点。SSH/Agent 无法执行任务是采集失败，不能记作目标网络丢包。

**PROBE03 HTTP**：DNS、TCP、TLS 或超时为传输失败；收到有效 HTTP 响应时保留状态码，200、404、403 等均可产生有效延迟。延迟统一定义到响应头/首字节，页面区分“网络可达”和“业务状态正常”。默认不下载完整大文件，限制响应体和重定向次数；记录证书验证失败，不能为得到延迟默认忽略证书。

**PROBE04 调度与预算**：检测任务与展示选择分开。支持时段、频率、超时、并发上限、错峰和手动运行。BOCE 沿用已配置时段、拨测节点、免费配额和费用预算，默认关闭付费任务；不把历史服务价格或免费次数硬编码。夜间停测是计划暂停，不标为离线或采样故障。默认配置要保留已有用户选择。

BOCE 每轮取得的部分结果和终态结果及时入库，重启后继续轮询已有任务；不因保存失败、超时或提交结果未知就再次创建收费任务。外部任务 ID、预算预留与结果状态一起持久化，避免 UI 改版破坏既有恢复行为。

**PROBE05 资源策略**：64/128 MB 模式降低采集频率，限制同主机并发，复用既有辅助二进制。禁止每次刷新卡片都发起真实全量探测；外部代理继续遵循仅手动检查的现有规则，本次不自动开启持续测速或下载测速。

**PROBE06 数据与通知**：短期样本按时间聚合，长期保留小时/日统计；原始保留期可配且有总量限制。失败率、丢包率与无数据比例分开。通知有去重、恢复和冷却，按事件分类设置；发送测试由管理员显式触发，日志脱敏。

**验收**：每种方向通过源节点日志或可控目标验证；BOCE 预算不足不提交任务；关闭展示不停止真实任务，关闭任务不删除历史；HTTP 404 正常记录延迟；采集失败不会增加目标丢包；界面显示暂停、未知、超时和网络异常的不同含义。

## 10 低资源节点与可选 Agent

### 10.1 资源档位

| 节点条件 | 默认管理模式 | 默认部署与采集策略 |
| --- | --- | --- |
| 64 MB | SSH 被动管理 | 原生精简核心，按需辅助命令；不自动装 Docker、Agent、数据库 |
| 128 MB | SSH 被动管理 | 保留现有能力，按需启用 vnStat；并发与频率受限 |
| 256 MB 及以上且有足够余量 | 提供 Agent 选项 | 安装前检测实际可用内存、CPU、架构和容器限制 |
| 无法获得管理权限的外部代理 | 外部节点模式 | 只导入、导出、手动检测，不尝试安装采集器 |

容量只是初始建议，实际可用内存、cgroup 限额、核心数量、并发连接和协议类型决定是否适合 Agent。64 MB 是明确要验证的目标，不承诺所有协议组合在任意 64 MB 系统中都能运行。发现资源不足时说明具体原因并保留可用模式，不能强制增加资源才能管理。

**LOW01 SSH 路径**：复用长连接，所有同主机远程操作受统一并发控制；管理写操作互斥，后台非关键采样遇忙可跳过。被动模式表示由主控发起任务，不等于节点主动推送；NAT 下无可达 SSH 通道时需现有可达路径或用户选择 Agent，不能宣称被动模式自动解决 NAT。

**LOW02 非必需组件**：安装向导显示将安装的程序和理由。vnStat 可独立开启；iftop/nload 等排障工具按需选装。只有存在相关入口/转发规则时才安装 mita/nginx/realm；不为“以后可能用”安装所有核心。

**LOW03 验收方式**：在真实 VM/LXC 或明确 64/128 MiB cgroup 限制的环境测试，记录系统基线、各进程 RSS/PSS、cgroup 实占、CPU、交换和 OOM。Docker 容器的内存限制不代表宿主系统已包含在该预算，报告必须区分。至少覆盖 24 小时稳定运行、重连、部署、核心重启和实际转发负载。

S0 必须冻结一个 64 MiB 最小参考栈与一个 128 MiB 常用栈，写清 OS/sshd、所选协议、入口数、用户数、并发和流量负载。最小档至少包含一个现有主线协议入口和真实 TCP 转发；适用协议再加 UDP。分别记录无 swap 与允许 swap 的结果，不能用打开 swap 的通过结果冒充无 swap。安装/更新时的解压、暂存、校验和短暂双进程峰值同样计入门槛；不满足的组合在产品中标为不支持，而非笼统标注“支持 64 MB”。

### 10.2 Agent 的最小职责

**AGENT01 程序形态**：一个可独立版本化的 Go 二进制，支持 systemd/OpenRC，按架构分发。职责限于状态采集、计划内探测、结构化配置应用和受控服务操作；不内嵌 Web 面板、数据库服务或多个代理核心。

**AGENT02 连接**：默认节点主动连接主控，优先 WSS；可回退到 HTTPS 长轮询。保持心跳、指数退避和随机抖动，限制重连风暴。Agent 管理 API 不默认公开监听。使用一次性短有效期安装凭证注册，换取单节点身份；支持撤销、轮换和可信服务器校验。

**AGENT03 命令协议**：任务含 ID、目标主机、期望配置版本、期限、幂等键、操作类型和经过校验的参数。仅接受定义好的能力，如 `apply_config`、`collect_metrics`、`probe_target`、`restart_managed_service`。重试不重复执行已成功的破坏性操作；拒绝旧版本覆盖新版本。

**AGENT04 本地状态**：持久化最小必要的已应用版本、任务结果与未确认计量批次。使用有上限的磁盘队列并明确溢出策略，不能无上限驻留内存；没有可写磁盘时显示能力限制。主控确认后清理，重复上报由中心去重。

**AGENT05 模式切换**：SSH → Agent 先完成握手、能力检查和数据比对，再切换采样写入者；Agent → SSH 同理。切换保持主机 ID、入口 ID、密钥、历史和预算不变，不默认重启代理进程。卸载 Agent 只移除其本身，不卸载核心与配置。

模式切换增加递增管理世代或等价隔离令牌，任务与回执带上世代；旧连接、滞留任务和旧身份在切换后不可继续写配置。先排空/终止旧写任务，再采集交接基线，再启用新写入者。仅修改数据库里的 mode 字段而不处理仍在线的旧 Agent 不算完成切换。节点永不直接连接主控业务数据库。

回滚采用“新版本号携带旧的已知可用内容”，不能发送更小版本号与防重放规则冲突。卸载或重新注册前处理未确认计量队列；旧 Agent 断网期间保留的队列不得在重新上线后覆盖新执行器的结果。

**AGENT06 资源目标**：建议将无代理核心的 Agent 空闲 RSS 目标设为不高于 12 MiB，常规采集 p95 不高于 20 MiB，并记录峰值；这是开发目标，不是现有产品实测值。若达不到，优化采集/队列并调整适用档位，不虚报兼容 64 MB。所有可选采集关闭后应可测出真实空闲成本。

**验收**：断网一小时后恢复、主控重启、Token 撤销、重复任务、过期任务、旧配置重放、磁盘满、升级中断和资源不足均有可解释结果。主控不可达时代理按最后有效配置运行；是否继续本地配额控制按已验证能力显示。

## 11 页面与主控性能

### 11.1 先定位当前慢点

**PERF01 基线**：记录概览、主机列表、节点详情、入口列表、用户首页和用户流量页面。采集导航到首个有效数据、p50/p95 API 时间、SQL 条数/耗时、数据库连接等待、响应体大小、JavaScript 体积、主控 RSS 和后台任务占用。使用固定数据集、冷/热缓存、相同主机配置和相同网络条件对比。

已发现的静态检查方向包括：单条 SQLite 连接让读写共用一个执行队列；节点列表配置状态计算会重新读取/渲染期望配置；侧栏计数请求完整用户/节点/外部代理列表与部署记录；管理员与门户认证每次请求写 last_seen_at；主机详情专用 live 接口涉及 SSH 节点锁；二进制文件完整缓存会占用主控内存。应分别测 SQL/CPU、连接等待、重复请求及锁等待，优先用轻量计数接口、状态版本缓存、会话写入节流和可取消等待解决对应热点。[L06][L12][L20][L21][L22][L23]

现有主机列表已批量加载入口，普通节点列表本身不是逐机同步 SSH；仪表盘也已有多个并行模块。批量查询、小时汇总、懒加载、失败降级和采样租约应继续复用，不把它们当成缺失功能。[L02][L03]

不能仅凭这些静态现象断言“几秒卡顿完全由 SQLite/SSH 导致”。优化项必须与 trace 或基准对应，也不能只加骨架屏就视为接口性能达标。

### 11.2 改造要求

**PERF02 读路径**：首屏优先读数据库已有结果或主控快照，返回各模块生成时间与状态。普通查询不能同步触发全量 SSH、安装、探测或部署。实时详情提供短期采样租约和缓存，多个浏览器共享采样结果，不线性增加节点采集次数。

**PERF03 聚合与查询**：按 SQL 计划添加索引，批量读取主机、入口和权限信息，避免 N+1；热点周期统计使用现有聚合表或小型汇总缓存。缓存有 TTL/版本失效与有界容量；权限缓存以用户和权限版本区分，不能把管理员数据缓存给门户。

期望配置哈希缓存必须绑定所有影响配置的依赖版本；依赖变更立即失效，缓存无法确认时显示“待计算”，不能把过期的“已同步”继续当真。优化会话 last_seen_at 写频率时，保留吊销、到期和会话查询的安全语义。

**PERF04 SQLite 并发**：保留单写入者语义；是否增加只读连接池、读写分离句柄应通过锁冲突测试决定，不能直接把 `MaxOpenConns` 从 1 改大而忽略事务和嵌套查询。PG 同样需限制连接数和超时，避免小主机被连接池耗尽。

**PERF05 前端**：页面数据按模块加载，首屏有效信息不等待低优先级历史/费用明细；同参数请求去重，离页取消，搜索防抖，列表按规模分页或虚拟化。保留已加载数据，失败模块独立重试；可读缓存与后台更新分开。秘密、订阅凭据和管理密钥不写持久化浏览器缓存。

**PERF06 后台任务**：安装、配置下发、测速、导入及迁移采用后台任务及进度接口。API 快速返回 task ID，不让长任务占住普通页面请求。支持超时、取消语义、分项结果和幂等；取消不能声称撤销已经执行的远程变更。

### 11.3 拟定验收门槛

参考环境为单个主控 2 vCPU/1 GB RAM、本地持久化存储；5 与 50 台主机两档，100/500 个入口、10 个用户、30 天监控与流量历史，5 个并发页面会话。通过可重放夹具模拟节点，真实节点测试另列。网络场景分别记录本地请求与约 100 ms RTT 浏览器访问，冷缓存和热缓存独立报告。

| 指标 | 拟定目标 | 测量边界 |
| --- | --- | --- |
| 普通列表/概要 API p95 | ≤300 ms | 不包含真实远程任务执行 |
| 仪表盘聚合 API p95 | ≤500 ms | 50 主机档，固定历史量 |
| 热缓存导航到有效信息 p95 | ≤500 ms | 浏览器路由切换，数据时间明确 |
| 冷打开主要页面到有效信息 p95 | ≤1.5 s | 约 100 ms RTT 的固定测试网络 |
| 创建/修改普通记录 API p95 | ≤500 ms | 远程部署另行计时 |
| 长任务提交响应 p95 | ≤300 ms | 返回 task ID 而非等待完成 |
| 正常后台采集时页面响应 | 仍满足对应门槛 | 覆盖部署/探针并发与部分节点离线 |
| 内存与数据库体积 | 无持续增长，保留策略有效 | 至少 24 小时测试 |

这些目标若因已证明的环境限制需要调整，应记录原始数据、原因与新门槛，不能删除失败样本或只展示最好的一次。对小规模 5 主机场景尤其要验证体验，避免只对大规模基准优化。

## 12 双数据库与共享 PG

### 12.1 选择模式

| 模式 | 安装结果 | 推荐用途 |
| --- | --- | --- |
| SQLite 默认 | 仅应用及持久化卷 | 单机个人使用与最少依赖 |
| 快速 PostgreSQL | 应用与独立 PG 服务，由 Compose 创建 | 希望同时完成数据库安装的用户 |
| 已有 PostgreSQL | 只部署应用，连接用户已有实例 | 本用户的共享 PG 场景 |

SQLite 在进程内直接读写文件，没有独立数据库服务。共享 PG 可减少多套 PG 实例的重复运维，但从两份 SQLite 改成一个 PG 不必然减少内存，也不会自动修复请求瀑布、查询和网络延迟。[E02]

**DB01 引擎选择**：启动时显式选择 `sqlite` 或 `postgres`。配置文件与环境变量的优先级文档化，环境变量可覆盖配置；未知驱动、缺失 DSN、权限不足或连接失败都明确报错。PG 不可用时不能自动回退成空 SQLite，避免用户误以为数据丢失。

**DB02 配置契约**：建议新字段使用 `LITEBOX_DB_DRIVER`、`LITEBOX_DB_SQLITE_PATH`、`LITEBOX_DB_DSN`、`LITEBOX_DB_DSN_FILE`，以及连接池、连接超时、SQL 超时和 TLS 配置。保留旧 `LITEBOX_DATABASE_PATH` 等 SQLite 配置的兼容映射。普通字段按文档优先级覆盖；DSN 与 DSN_FILE 同时提供、或同优先级的连接来源矛盾时才报错，不把正常环境变量覆盖误判为冲突。以上新字段是拟实现命名，不是当前版本可直接使用的环境变量。

**DB03 SQL 适配**：保持 `database/sql`，可使用 pgx 的 stdlib 驱动；提取存储接口或集中 dialect 能力，不为此更换为大型 ORM。清点问号占位符、LastInsertId、PRAGMA、strftime/datetime、INSERT OR IGNORE/REPLACE、布尔类型、JSON、RETURNING、NULL、部分索引、视图和迁移脚本。不可用字符串全局替换来改写 SQL。

**DB04 事务语义**：两种数据库均验证授权视图、流量账本唯一约束、聚合更新、配置版本、幂等键和软删除。PG 下并发写需要明确锁或原子更新；不能依赖 SQLite 单连接恰好串行的行为。时间统一 UTC，金额与流量使用准确整数或 decimal，避免 JS 浮点丢失大整数。

**DB05 迁移管理**：SQLite 旧迁移保持只追加；PG 使用单独可追踪的方言迁移与校验和，逻辑 schema version 可统一。迁移执行锁、防止双进程迁移、失败回滚/恢复和“数据库版本比程序新则拒绝启动”必须实现。支持 PG 16/17/18 是建议兼容目标，实际支持版本以 CI 验证矩阵为准；快捷部署锁定一个已测稳定主版本及具体镜像版本/digest。

### 12.2 两套应用共享实例

**DB06 隔离**：同一 PG 实例创建 `litebox` 与 `nexus_portal` 两个数据库，应用各有独立账号，迁移版本表、备份与连接池互不复用。应用账号不拥有集群超级用户权限；角色、CONNECT 和 schema 权限按最小范围设置，并测试交叉访问被拒绝。初始化用的管理员账号不保留为应用运行账号。

已有实例的库和角色由管理员预先提供或单独执行初始化向导；应用运行不要求 CREATEDB 权限，不擅自创建新库或重设共享实例账号密码。

**DB07 网络**：同宿主不同 Compose 项目通过显式 external network 和稳定服务名连接；容器内 `localhost` 指向容器自身，不能当作另一个容器的 PG 地址。已有外部 PG 支持域名、端口和证书路径，跨主机连接采用可验证 TLS，例如 `verify-full` 与可信 CA，不默认关闭证书验证。[E03][E04]

**DB08 容量与故障**：应用连接池从保守值起步，例如每应用最大 5、空闲 1–2，并以总实例预算调整；该值是建议初值。设置连接与 SQL 超时、健康状态和有限重试。PG 故障不触发无限重连或每次请求新建池；门户显示维护/数据不可用，已运行节点服务继续运行。

### 12.3 SQLite 迁移到 PG

**DB09 迁移工具**：提供 `db inspect`、`db export`、`db migrate`、`db verify` 或等价命令。默认 dry-run 输出源/目标版本、表数量、记录数、预期空间和不兼容项。目标为空或明确为该应用预建数据库时才导入，不对用户已有数据库执行清库。

正式迁移顺序为：准备目标 schema → 进入维护并暂停写入任务 → 取得一致性源备份 → 保留 ID/密文/关联关系导入 → 校正 sequence → 校验行数、主外键、有效权限、关键汇总与抽样哈希 → 使用新连接启动 → 校验核心读写与权限 → 退出维护。源 SQLite 及升级前应用版本保留到验收完成。

**DB10 迁移内容**：包括管理员与门户账号、密码哈希、用户代码、会话/令牌、节点与地址池、入口、内部链路身份、密文凭据、当前/已应用配置版本、流量账本/聚合、探针历史与预算、BOCE、资产、通知、任务和审计。主密钥必须保留，不做全量重新加密或重新发凭据，除非单独明确迁移原因。

任务历史保留；运行中任务在恢复后转入待核对状态，查询真实执行结果后才能继续，不能自动重放远程变更。恢复主控库不会自动回滚远端，恢复后先核对配置版本、权限撤销和计量，再恢复调度。

**DB11 回退**：切换前故障可继续使用未改动源库；切换并产生新写入后，不能直接改回旧 SQLite 而丢掉新数据。必须进入维护，导出/恢复所需写入或使用受控停机窗口完成回退。首版不支持在线双向切换，但必须交付经过验证的离线回退方案，明确停机、增量数据保留与 schema 兼容边界。

**验收**：同一业务测试分别跑 SQLite 与每个承诺支持的 PG 版本；脱敏旧库完整迁移后用户入口集合、额度、配置和关键历史一致；在导入中途失败、目标断连、权限不足与旧程序启动场景中都不会损坏源库。

## 13 Docker Compose 与一键部署

**DEPLOY01 镜像**：一个主控镜像包含 Go 服务与前端静态资源，正常启动无需 Go/Node/npm/git，也不临时编译代理核心。镜像发布到拟定的 `kjoner/litebox`，真实仓库名称以用户创建结果为准。支持 linux/amd64 和 linux/arm64，使用固定语义版本、提交标识及 digest。

**DEPLOY02 Compose 文件**：建议 `compose.yaml` 是 SQLite 默认应用；`compose.postgres.yaml` 添加专用 PG 和对应依赖；`compose.external-postgres.yaml` 仅覆盖已有 PG 连接与网络。也可用经测试的 profiles 实现，但必须保证未启用 PG 时不会启动 PG、要求其必填密码或依赖其健康检查。

**DEPLOY03 配置入口**：安装向导选择部署目录、端口、域名/反代方式、数据库模式和管理员初始化。SQLite 路径、已有 PG 的连接参数、时区与版本通过 `.env` 或只读 secret 文件提供。DSN 处理 URL 编码、特殊字符、IPv6 和 `$` 的 Compose 插值；渲染预览需脱敏。

**DEPLOY04 容器约束**：主控不默认使用 privileged、host 网络或挂载 Docker socket，不把节点 SSH 服务混进主控容器。应用非 root，持久化数据、主密钥、证书、配置、产物缓存按路径挂载；根文件系统尽量只读，日志轮转。主控如承担本机代理或特殊探测角色，应作为独立明确选项提供最小能力，不因参考产品的默认 host 网络直接扩大权限。

**DEPLOY05 数据库服务**：快捷 PG 默认不向公网发布 5432，健康检查通过后启动应用迁移；已有 PG 模式不创建、修改或删除共享实例。PG 18 官方镜像的数据目录布局与 17 及以前不同，Compose 必须按锁定版本选正确持久化挂载，并测试重建后数据仍在；PG 大版本升级是独立迁移任务，不能只改镜像标签。[E05]

**DEPLOY06 一键脚本**：首次安装拉取预构建镜像，识别已有目录、Compose、`.env`、容器和版本。重复执行使用已有设置，保留用户 override，不覆盖主密钥和数据。版本相同且健康时不制造一次无意义重启。提供 status、backup、verify-backup、restore、update 和日志入口。

**DEPLOY07 备份与恢复**：更新前备份应用数据、配置、密钥和必要文件；SQLite 使用一致性快照，PG 使用匹配版本的 `pg_dump` 等逻辑备份。PG 备份只针对应用数据库，不要求复制整个共享集群。保留最近 3 次已验证完整部署备份；新备份验证成功前不删除最后可用备份。凭据与密钥备份按敏感数据处理。[E06]

隔离还原演练默认禁用调度、SSH/Agent 下发、通知和云自动处置，必要时限制网络；不能启动一份生产备份就让其执行原有任务。验证数据可读取之外，还需验证密码/密文可解、权限正确和必要文件齐全。

**DEPLOY08 更新过程**：拉取目标镜像 → 验证产物 → 提前用副本演练恢复与迁移 → 进入维护并排空 API/后台写入 → 取得最终一致性恢复点 → 迁移 → 启动 → 就绪检查与应用冒烟 → 恢复写入 → 完成。采样与任务队列在维护边界有明确暂停/续传语义；数据库迁移不主动重启节点核心。失败时按 schema 兼容情况回滚应用及应用数据库，恢复后先核对远端应用版本与计量基线。不能把维护前的旧备份当成没有新写入损失的最终恢复点，也不能把新 schema 上直接启动旧镜像称为可靠回滚。

**DEPLOY09 原生升级与迁移**：继续保留原生主控安装选项，但默认下载预编译发布包。已有 systemd 部署迁移到 Compose 时，检查端口、数据目录、文件属主和主密钥；先在隔离副本验证，切换时停止旧主控防止双写。保留原服务定义及回退路径，不移动或删除节点上的服务。

**DEPLOY10 发布流水线**：普通提交/PR 执行测试，不发布生产镜像；正式 tag 触发完整门禁、构建、镜像冒烟、多架构检查、推送和 GitHub Release。预发布标签不覆盖 latest。发布源码 SHA、核心版本、构建标签、校验文件、SBOM/构建来源和兼容矩阵；验证实际推送的 digest。可直接参考 Nexus Portal 现有流程。[N03][N04]

**验收**：新装 SQLite、新装 PG、接已有 PG、重复安装、异目录执行、停机后升级、保留 override、无网络更新、数据库损坏、迁移失败和恢复分别测试。生产主机正常安装不需要编译工具链；SQLite 模式只有应用服务；卸载默认保留数据且绝不删除共享 PG。

## 14 核心产物与协议能力

**CORE01 发布产物分工**：GitHub Actions 构建 LiteBox 主控、可选 Agent、litebox-probe 和需要的精简 sing-box。mita/mieru、realm 等优先使用已经核对版本和校验信息的官方产物。所有可执行文件按 OS/架构/版本/能力记录在 release manifest，主控按需缓存并分发。

**CORE02 保留精简构建**：现有 sing-box 使用特定构建标签支持用户计量和低资源部署。CI 首先复现当前构建与回归行为，再评估官方预编译包能否满足相同能力。不能因为某官方镜像可以启动，就认为 V2Ray Stats、REALITY、Snell 和现有拨测全部可用。官方文档也明确 V2Ray API 不默认包含在构建中。[L09][E07]

**CORE03 小内存分发**：主控通过流式下载和流式 SSH 上传发送文件，磁盘缓存按 SHA 定址并限制保留版本，不长期把所有架构的完整二进制放在 Go 堆。已存在文件必须核对版本、hash 与 manifest，不能仅凭文件非空跳过。节点只下载/接收本机架构和实际所需核心，不在节点编译。

**CORE04 安装与更新**：下载到候选路径，校验来源和摘要，检查版本/能力，编译并校验配置后原子替换，保留可回滚旧版本。只影响管理界面的升级不自动更新全部节点核心；核心升级显示范围、预期重启及版本差异，按少量节点试运行后逐步应用。

### 14.1 协议规划

当前自建入站主线是 VLESS/REALITY、Shadowsocks 2022 与传统 AEAD、Mieru、Snell；外部代理可导入的协议范围更大。必须把“可以导入”“可以作为出站”“可以安装为自建入站”“可按用户计量”“某客户端能导出”分开列出，不能用一个支持标记代替。[L01]

**PROTO01 保留与完善**：优先保证上述现有入站、转发和外部出站完整可用。保留传统 AEAD 的多用户独立密码与空用户时的安全回退；Snell shared 模式的共享 PSK 限制另列，不能把两者混为单用户协议。对时间敏感的协议检查时间偏差；LXC 没有改时权限时给出诊断，不尝试强行修改宿主时间。

**PROTO02 新增协议**：P1 至少交付一个新增自建入站协议的端到端能力，默认优先验证 Trojan；S0 若发现具体版本/计量/资源阻碍，必须用证据确定替代项并冻结交付清单。Hysteria2、TUIC、AnyTLS 为同批候选，逐个记录固定核心版本、构建标签、TLS/证书、UDP、内存、计量、客户端支持及延期理由。外部导入已支持不代表自建安装已经支持；只有调研、枚举或表单不能算新增协议交付。

当前精简 sing-box 未启用 `with_quic`；HY2/TUIC 的外部导入/客户端导出能力不等于小节点核心可把它们作为出站。需要新增核心能力时，只对选择该功能的主机分发经过验证的能力构建，不扩大所有低资源节点的默认包。每台主机继续只有一个受管 sing-box 实例，不能为每个协议再启动一份。[L01][L09]

**PROTO03 能力注册**：协议 schema 驱动表单字段、校验、配置生成、计量支持、节点资源提示和客户端适配。既有运行实例可以继续工作，即使后来将某协议的新建入口暂时标为不推荐。不要以数据库枚举更新完成代替端到端功能完成。

**验收**：每个宣称可自建的协议需要完成安装、配置检查、真实连接、TCP/UDP 所需测试、计量、权限撤销、升级回滚与最低资源档验证。不支持的组合在保存前拦截。主控、Agent、probe 和核心版本兼容关系可查询。

## 15 客户端格式与基础订阅

**CLIENT01 输出架构**：内部使用统一的节点与链路模型，再按客户端 serializer 输出。权限过滤在 serializer 之前执行；同一格式使用确定性的字段顺序、稳定名称和去重规则。不把某客户端的完整配置当成数据库唯一模型。

| 批次 | 格式 | 本次交付要求 |
| --- | --- | --- |
| P0 | Clash Meta/mihomo 与已有 Shadowrocket/URI 路径 | 现有链接、字段与链路回归，不因新适配层退化 |
| P0 | sing-box | 保留原生极简配置与模板路径，完善版本兼容、预览与回归 |
| P1 | Stash | 基于真实支持范围适配，不能只改格式名称 |
| P1 | Surge、Loon、Quantumult X | 加入常用协议与规则映射，明确不兼容项 |
| P2 | Egern、Surfboard、其他 V2Ray 家族完整配置 | 以实际使用需求及测试条件扩展；通用 URI 另行复用 |

**CLIENT02 兼容预览**：用户选择客户端和必要版本后，显示可导出的入口、跳过项与原因。格式不支持链路或协议时不能悄悄输出直连配置，不能无提示删除节点。配置有语法验证和样例快照；具备本地 CLI 的客户端做实际解析检查，商业客户端无法自动化时记录人工验证版本。

每个 P1 客户端固定验证版本、输出形态、最小协议集合、TLS/传输、DNS/规则及链式能力，至少提供一种可直接导入并真实连接的最小配置。无法完成验证的适配器保留为未完成项，不因文件扩展名正确就标为通过。Mieru 的端口范围、UDP、handshake-mode、traffic-pattern 和 Snell 共享/独立身份必须纳入字段保真夹具。[M06]

**CLIENT03 基础功能**：保留专属配置链接、Token 重置、复制、下载与二维码等已有行为。自定义模板仍按权限替换，不允许模板绕过用户授权。普通用户链接不得携带管理员会话；基础配置输出可以做，付费订阅运营继续不做。

**CLIENT04 迁移兼容**：旧 URL 路径和 Token 默认继续有效；若安全问题必须变更，提供清晰迁移与旧链接过渡策略。展示名、Unicode、逗号、引号、反斜线、IPv6、端口范围和重复名称有测试；不能用正则粗暴改写 YAML/JSON 并破坏转义。

已有 `?format=sing-box` 保持内置极简配置的默认网络行为，不自动加入 TUN、DNS 劫持或复杂规则集；高级分流继续走现有配置文件模板，不新建相互冲突的第二套生成器。[L14]

## 16 配置应用与安全边界

**CONFIG01 状态分离**：数据库保存期望配置、远端已应用版本与校验结果。只有真实核心校验、启动与拨测成功，才更新“已生效”。配置 SHA 一致时不重启；字段仅影响展示或订阅地址时不重启核心。

**CONFIG02 保留现有硬约束**：用户列表与统计白名单同源；UUID、flow 等由面板强校验；真实拨测失败取回经过脱敏的核心日志；核心停止场景可走恢复流程；重启前计量同步在适当锁顺序执行；不把单纯进程 active 当作代理健康。

保留已有 RAM 配置模式、watchdog 自愈和启用后的主机重启恢复；不能因主控容器化或引入 Agent 就把原来要求不落盘的明文配置写回永久磁盘。备份与排障同样遵守该模式的敏感数据边界。

**SEC01 凭据**：管理员密码继续强哈希，SSH/节点私钥与需恢复的秘密继续使用主密钥加密存储；哈希和加密不可混用。主密钥与数据库一起迁移但不写入镜像、前端包、审计正文或错误响应。环境变量并不等于加密，`.env` 与 secret 文件应受权限保护。

**SEC02 输入与网络**：命令参数避免拼接 shell；主机名、端口、路径、网卡和协议字段强校验。公共订阅抓取与普通用户可提交 URL 采用严格出站限制；管理员配置内网主机/探针属于产品必需功能，使用权限、显式目标和审计控制，不能用一刀切禁私网破坏合法管理。

**SEC03 公共展示**：如果保留或增加公开探针页面，只使用专用白名单 DTO，不输出管理 IP、节点 token、SSH 信息、内部名称、核心原始配置和其他用户数据。缓存和推送均沿用同一边界。

**SEC04 审计**：记录操作者、对象、动作、变更摘要、前后版本、任务 ID 和成败；敏感值用不可逆标识或掩码。用户被删除后保留必要历史关联，不把历史账本级联清除。操作记录可按对象和失败筛选，能直接定位原因。

## 17 Nexus Portal 的配套 PG 改造

Nexus Portal 当前使用 Hono 与同步 `better-sqlite3`，多个业务模块直接调用 `prepare()`/`transaction()`，迁移版本用 PRAGMA 管理。增加 PG 必须调整异步数据访问和事务，不能只加一条 DSN。[N05][N06]

**NEXUS01 仓储**：为配置、认证会话、设备授权、集成令牌、壁纸和健康状态建立可测试的异步存储接口；SQLite 实现可保留同步驱动内部逻辑，对外按同一契约提供结果。所有调用链明确 await，避免未完成写入就返回保存成功。

**NEXUS02 配置并发**：保留 `revision`、`batch_id` 幂等和操作 reducer。PG 下对单文档配置写入采用事务行锁或版本 CAS，避免两个设备读到同一旧 JSON 后相互覆盖。Web/Chrome 扩展只在提交成功后发布新 revision；重复批次不重复执行。

**NEXUS03 迁移范围**：账号哈希、会话、扩展设备令牌、配置、op_log、集成密文、壁纸元数据与健康状态都迁移。`/data` 的图片、图标、缓存与 `secret.key` 不因使用 PG 消失，文件备份继续存在。保留当前每日一图与“我的壁纸”的边界，避免重新引入历史图片自动入库。

**NEXUS04 部署复用**：沿用现有 Docker Hub、多架构镜像、非 root、固定版本、完整部署备份最近 3 次、验证恢复和失败回滚。当前还存在单独的数据库迁移前快照保留规则，改造时说明其用途与数量，不把所有备份误报为只有 3 份。支持 SQLite / 新建 PG / 已有 PG，与 LiteBox 分别维护 `.env`。

**NEXUS05 验收**：共享一个实例的两个应用可以同时读写、升级和单独恢复；恢复 LiteBox 不改动 Nexus 数据库，反之亦然。Chrome 扩展继续本地缓存优先、设备授权可撤销、版本同步与离线行为不退化。Nexus 的界面与项目框架不因数据库改造而重新设计。

## 18 迁移保护与验收矩阵

### 18.1 必须保留的数据与行为

以脱敏旧库建立兼容夹具，覆盖管理员、门户账号、用户代码、有效权限集合、节点与地址池、入口与映射、链式内部身份、配额/到期/倍率/周期、已应用配置、流量历史、探针任务与结果、BOCE 配额与拨测点、CDT 设置、通知、审计和所有加密材料。

导出内容保持语义一致；不为“统一名称”擅自更换用户已使用的节点名或订阅 Token。升级后默认不自动增加探测、付费任务、常驻 Agent 或额外核心。已关闭的功能保持关闭。
