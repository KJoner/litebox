# 出站网络质量探测 —— 交付说明

技术方案与修改范围见 [02-outbound-plan.md](02-outbound-plan.md)。本文是交付清单:做了什么、数据怎么存、
指标怎么算、接口、安全、已知限制,以及实际跑过的测试。

## 1. 完成情况

| 需求 | 状态 | 内容 |
|---|---|---|
| (1) 公共探测目标库 | 完成 | 系统设置「公共探测目标(出站)」:名称、IP 或域名、ICMP / TCP、端口、地址族、间隔、每轮包数、超时、排序、备注;批量启用(全部节点 / 选中节点 / 都不启用),节点详情里逐台「跟随全局 / 启用 / 停用」 |
| (2) 出站为主、走 SSH、不驻留 | 完成 | 每台 VPS 在本机执行;经已有的 SSH 长连接临时启动非驻留辅助程序 `litebox-probe`(JSON 进、JSON 出,跑完即退出);同一台机器的全部到期目标一次执行;采集失败、工具不可用、DNS 失败、目标受限与真实探测失败分开记 |
| (3) 指标 | 完成 | ICMP:平均 / 最小 / 最大 RTT 与按包计的丢包率;TCP:建连 RTT、成功率与失败率;1h / 24h / 7d 历史与点阵;延迟在 VPS 上量,不含 SSH 耗时 |
| (4) 界面 | 完成 | 卡片网络区每个公共目标一行(名称、协议、延迟、丢包率或失败率、点阵),入口连通性单列一小块;节点详情「网络监测」分「出站网络质量」与「入口连通性」两块 |
| (5) 数据模型 | 完成 | 复用 `probe_results` / `probe_hourly`、汇总、告警与历史;新增全局目标与节点绑定;序列表标明方向、来源与协议;增量迁移 0041 保留全部历史;不改计费、续费、资产价值 |
| (6) 安全与可靠性 | 完成 | 只有管理员能建目标;危险地址与端口默认拒绝、解析之后再查一次;目标只经 stdin 传入;DNS 变化、IPv4 / IPv6、工具缺失、云实例停机都有对应结局;SSH 失败不记丢包;非阻塞取锁、每次执行有硬上限 |

原来的「主控 → 节点」TCP 探测**保留**,改称「入口连通性」,语义与历史一个字没动。

## 2. 执行方式

工具对比见方案 §1,结论是**非驻留辅助程序,不做系统工具回退**。

* `cmd/litebox-probe`:静态 Go 二进制(`CGO_ENABLED=0`,amd64 / arm64 各约 2.9 MB),由 `scripts/build-probe.sh`
  从本仓库构建,一键安装脚本每次都重建(它与面板之间有协议版本号 `netprobe.Version`);
* 面板按 sha256 认文件:节点上的哈希与主控现在分发的那一份不一致(或文件不在)才上传,先传 `.new` 再改名;
  执行时退出码 126 / 127(文件被删)会在**同一次占锁里**重新上传再跑一次;
* 位置 `/opt/litebox/litebox-probe`,整机卸载时随目录删除;不常驻、不开机自启、不监听端口、不写任何文件;
* 命令行只有固定的程序路径,目标经 stdin 的 JSON 传入,地址与端口不经过远端 shell;
* ICMP 先开原始套接字,开不了(非 root,或容器没给 CAP_NET_RAW)退到非特权 ICMP(`ping_group_range`),
  两者都不行报「工具不可用」,不冒充丢包。**测试 VPS 是一台容器,root 也开不了原始套接字,走的就是这条回退**。

## 3. 调度

* 出站引擎每 15 秒一拍,各公共目标按自己的间隔(30~3600 秒)到期;一台机器一次 SSH 执行跑完全部到期目标,
  机器之间并发上限 4;
* **非阻塞取锁**(`sshx.Pool.TryDo`):节点正在部署 / 同步 / 巡检时本拍让路,不记任何结果、不推进到期时间,
  下一拍再试;
* 一次执行的硬上限 = 目标预算 + 53 秒(含建连与可能的上传);辅助程序自己在预算 + 2 秒后结束、+5 秒强制退出;
* 云实例停着 → 记「未执行」,不连 SSH;节点停用 → 不探测;架构未知或主控缺这个架构的辅助程序 → 「工具不可用」;
* 面板重启后按上一次的时间接着排,不在启动那一刻把全部目标打一遍。

## 4. 数据模型(迁移 0041)

* `probe_public_targets`:公共目标库。`(host, protocol, port, family)` 唯一;**协议与地址族创建后不能改**
  (换了就是另一条测量);`apply_all` 默认 0 —— 登记与启用是两步;
* `probe_node_bindings(node_id, public_id, mode ON/OFF)`:节点覆盖,没有行 = 跟随 `apply_all`。
  判据只有 `effectiveOn` 一处:公共目标没暂停,且(节点显式开,或没有覆盖而公共目标对全部节点生效);
* `probe_targets` 成为序列表:加 `direction`(INGRESS / OUTBOUND)、`protocol`(TCP / ICMP)、`public_id`;
  CHECK 写死两种组合(入口 = 主控发起的 TCP、MGMT / SERVICE、没有公共目标;出站 = 节点发起、PUBLIC、挂着公共目标);
  出站序列在第一次生效时建行,失效只停用不删(历史保留),名称跟着公共目标走,改主机或端口换代;
* `probe_results` 加 `sent` / `received` / `rtt_min_us` / `rtt_max_us` / `peer`;`probe_hourly` 加
  `lossy` / `ssh_errors` / `tool_errors` / `blocked` / `sent` / `received` / `rtt_n`;状态多了
  `LOSS` / `BLOCKED` / `SSH_ERROR` / `TOOL_ERROR`;
* 三张表按「建新表 → 全量拷贝 → 先删子表、后删父表 → 改名」重建;旧明细按「一次建连 = 发 1、成功 = 收 1」换算;
* **迁移不创建任何公共目标、不写任何绑定,旧的入口目标不转换**:升级后不会有任何一台机器开始出站探测。

## 5. 指标定义

| 指标 | 定义 |
|---|---|
| ICMP 丢包率 | Σ(发 − 收) ÷ Σ发,按包。一个包都发不出去(没有路由、没有 IPv6 出口)按「这一轮打算发的包全丢了」记,与 ping 一致 |
| ICMP RTT | 按收到的包加权:平均 = Σ(每轮平均 × 收到数) ÷ Σ收到数;最小 / 最大取各轮的最小 / 最大 |
| TCP 失败率 | 失败的建连 ÷ 发起的建连;成功率 = 1 − 失败率 |
| 不进分母 | DNS 失败、目标受限、采集失败、工具不可用、未执行 —— 各自单列;分母为 0 时比例是 `null`,显示「—」 |
| 告警 | 连续失败(TCP 失败、ICMP 整轮全丢、DNS 失败)达到阈值推一条,恢复推一条;**部分丢包算可达**;采集失败、工具不可用、目标受限、未执行不改变计数 |
| 点阵 | 每个点一个窗口,宽度至少 2 分钟且不比目标间隔窄;采集失败是灰色斜纹、工具不可用 / 目标受限是琥珀空框,都**不按失败画** |

告警阈值、免打扰时段与全局开关两类探测共用;入口的间隔与超时仍是全局设置,出站的是每个公共目标自己的。

## 6. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/probe/public-targets` | 公共目标列表(含生效机器数、显式开 / 关数)+ 概况(出站引擎最近一拍、主控有哪些架构的辅助程序) |
| POST | `/api/probe/public-targets` | 新建,默认不对任何节点生效;受限地址 / 端口、非法主机名一律 400,重复 409 |
| PUT | `/api/probe/public-targets/{id}` | 编辑;改协议或地址族 400 |
| DELETE | `/api/probe/public-targets/{id}` | 删除,连同各节点上的序列、历史与覆盖 |
| GET | `/api/probe/public-targets/{id}/nodes` | 每台机器上的开关与是否生效 |
| PUT | `/api/probe/public-targets/{id}/scope` | `{scope: ALL \| SELECTED \| NONE, node_ids}`:换成这个集合,原有的节点覆盖一并清掉 |
| PUT | `/api/nodes/{id}/probe-public/{publicId}` | `{mode: ON \| OFF \| INHERIT}` 单节点开关 |
| GET | `/api/nodes/{id}/probe` | 多了 `outbound`(出站序列汇总)与 `public`(全部公共目标在这台机器上的开关);`targets` / `candidates` 仍是入口 |
| GET | `/api/dashboard/cards` | 多了 `outbound`;`targets` 仍是入口 |

出站序列不能用 `PUT / DELETE /api/probe-targets/{id}` 单独停或删(400):它跟随公共目标与节点开关,
单独停掉的话下一次同步又会被打开。历史接口两类都能用。审计动作:`probe.public_create` / `update` /
`delete` / `scope`、`probe.node_binding`。

## 7. 安全

* 公共目标只有管理端会话能建;主机名按严格规则校验(IP 字面量或至少两段的域名,末段不能全是数字);
* 默认拒绝:私网、回环、链路本地(含云元数据 169.254.169.254)、CGNAT、保留 / 文档 / 基准测试地址段、组播、
  IPv6 ULA 与链路本地;端口拒绝邮件(25 / 465 / 587)与 SMB / NetBIOS(135~139 / 445)。每个目标可以显式勾选放开;
* 辅助程序在**解析之后**再查一次地址:域名解析到内网同样拒绝(防 DNS 重绑定),结果记「目标受限」;
* 每轮最多 10 个包、包间隔 500 毫秒、超时 200~3000 毫秒、间隔不小于 30 秒,一次最多 32 个目标;
* 页面上的采集失败原因按类归好、不带地址;原始错误只在机器「连得上 → 连不上」时写一条日志。

## 8. 已知限制

* 没有远端测点(电信 / 联通 / 移动三网、多地区)—— 仍是 P2,`source` 维度预留,界面只显示真实存在的来源;
* 不做 UDP、HTTP 层探测与路由追踪;
* 节点锁被长时间连续占用时(比如连着下发),出站探测会一直让路,点阵上那一段是空心(没有样本),不是失败;
* 节点没有 IPv6 出口时,IPv6 目标是「网络不可达」并进告警 —— 在那台机器上单独停用即可;
* 域名目标每轮由节点自己解析,指向变了不换代(域名目标的含义就是「它现在指向的地方」),最近一次实际连的 IP 在详情里。

## 9. 测试与验证(实际结果)

**自动化**

* Go:`go test ./...` 全部通过。新增迁移测试(0040 → 0041 历史一行不少、外键改写、CHECK 拒绝混写)、
  公共目标校验 / 范围 / 绑定 / 同步、出站引擎(按节点批量、按间隔到期、重启续排、SSH 失败 / 工具不可用 /
  正忙 / 停机都不是丢包、ICMP 统计与告警、入口引擎不碰出站序列、并发上限)、执行器在建连之前的分类、
  `sshErrorText` 不带地址、辅助程序的 ICMP / TCP / DNS / 受限地址 / 回环实测、`TryDo` 不等锁;
* 前端:`vue-tsc` 与 `vite build` 通过;Playwright 功能用例 109 个通过(新增出站卡片、采集失败不计失败、
  出站告警说法、网络 Tab 两块与三态开关、系统设置公共目标的登记→选范围);截图基线 34 张
  (卡片视图 4 张更新、节点「网络监测」4 张新增)。

**测试 VPS 真机**(Alpine 3.24 / aarch64 / OpenRC / NAT 容器;本机隔离 scratch 面板,节点专用私钥,
主机密钥预置为本机 known_hosts 里已核实的那份 —— 面板第一次握手拿到的算法与预置的不同时直接拒绝,没有接受新密钥;
没有改动服务器的 SSH 配置与 authorized_keys)

| 场景 | 结果 |
|---|---|
| 登记之后 | 7 个目标生效机器数都是 0,没有任何执行 |
| 首次执行 | 辅助程序自动上传(2.9 MB),ICMP 5/5、TCP 建连成功,域名在 VPS 上解析 |
| 与系统 ping 对比 | 两个公共 DNS 的 ICMP 平均 RTT:辅助程序 12.20 / 1.79 ms,系统 ping 12.20 / 1.85 ms |
| DNS 失败 / 解析到内网 / 无 IPv6 出口 | 分别记 DNS 失败(不进分母)、目标受限、网络不可达(每轮 3 个包全丢) |
| 占锁时长 | 7 个目标一次执行 2.6 秒(每 30 秒一次);含上传的那一轮 6~11 秒 |
| 辅助程序换了版本 | 下一轮自动发现哈希不同并重传 |
| 节点上的辅助程序被删 | 下一轮退出码 127 → 同一次占锁里重传并重跑,没有记「工具不可用」 |
| SSH 连不上(改错端口) | 7 条全部记「采集失败」,丢包率不变、连续失败计数不变、点阵是采集失败点,占锁 1.8 秒 |
| 节点锁被连续占用 | 4 拍立刻让路(1 毫秒、不写结果),锁一空下一拍照常执行 |
| 单节点停用 / 跟随 | 停用后只测其余 6 个,序列显示「这台机器没有启用这个公共目标」、历史保留;改回跟随立即恢复 |
| 收尾 | 删除节点上的辅助程序,确认没有残留进程;本机隔离面板的数据库与密钥文件删除 |

没有接触生产节点与生产数据库,没有合并 master,没有部署。
