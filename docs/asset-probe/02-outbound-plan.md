# 出站网络质量探测 —— 技术方案与修改范围

方向改造:主力从「主控 → 自建节点」的入口 TCP 探测,改成「**每台自建 VPS → 管理员配置的公共目标**」的出站探测
(像 monitor-probe 那样每台机器自己测多个公共目标,LiteBox 统一汇总)。原来的入口探测保留,归类为「入口连通性」,
两类数据分开存、分开算、分开显示。

## 1. 执行方式:远程系统工具 vs 非驻留辅助程序

| | 远程系统工具(ping / nc / curl / bash) | 非驻留辅助程序 `litebox-probe` |
|---|---|---|
| 是否到处都有 | ping:Alpine 是 busybox 版,Debian 最小镜像常常没装 iputils-ping;curl / bash / nc 都不保证 | 主控按架构下发一份静态二进制(amd64 / arm64,约 2–3 MB),sha256 校验,只传一次 |
| 输出与语义 | busybox 与 iputils 的输出格式、`-W` 含义、IPv6 写法(`ping -6` / `ping6`)、DNS 报错文字都不同,只能靠解析文本 | JSON 进、JSON 出,一种语义 |
| TCP 建连 RTT | 没有通用的微秒计时工具;`date +%N` 计时包含进程启动(毫秒级)误差;`/dev/tcp` 要 bash | 进程内计时,只量 `connect()` 三次握手 |
| 批量与并发 | 要在远端拼 shell 脚本做后台作业与收集 —— 违反「不拼接远程 shell」 | 一次执行内并发跑完全部到期目标 |
| 注入面 | 目标地址进命令行参数 | 目标经 stdin 的 JSON 传入,命令行只有固定路径 |
| 内网 / 危险地址 | 域名解析在 ping 内部,拦不住解析到内网的域名 | 解析在辅助程序里,解析结果是内网 / 保留地址时拒绝探测(防 DNS 重绑定) |
| ICMP 权限 | ping 自带 setuid / capability | 原始套接字要 root(且容器要给 CAP_NET_RAW);开不了时退到 unprivileged ICMP(需 `ping_group_range`),都不行时报「工具不可用」 |

结论:**采用非驻留辅助程序**。它不是常驻 Agent:每轮由主控经已有的 SSH 长连接启动一次、跑完就退出,
节点上没有守护进程、没有开机自启、不监听任何端口;文件放在 `/opt/litebox/litebox-probe`,整机卸载时随目录删除。
不做系统工具的回退:两套语义不同的实现只会让同一个目标在不同机器上得出不可比的数字;
辅助程序不可用时如实报「工具不可用」,不冒充丢包。

## 2. 数据模型(迁移 0041,增量,保留全部历史)

* **`probe_public_targets`**(公共目标库,全局):名称、主机(IP 或域名)、协议(ICMP / TCP)、端口、地址族、
  探测间隔、每轮 ICMP 包数、超时、是否对全部自建节点启用(`apply_all`)、全局启停、是否允许受限地址与端口、排序、备注;
* **`probe_node_bindings`**(节点覆盖):`(node_id, public_id, mode ON / OFF)`;没有行表示跟随 `apply_all`。
  批量启用 = 改 `apply_all` 或批量写绑定;单节点开关 = 写一行绑定;
* **`probe_targets` 成为「监测序列」表**:加 `direction`(INGRESS / OUTBOUND)、`protocol`(TCP / ICMP)、
  `public_id`;`kind` 加 `PUBLIC`、`source` 加 `NODE`(在 VPS 本机执行)。出站序列 = (节点 × 公共目标),
  由调度器在它第一次生效时建行,停用不删(历史保留);
* **`probe_results` / `probe_hourly` 复用**,加列:每轮 ICMP 发送 / 收到数、最小 / 最大 RTT、实际连接的 IP;
  状态加 `LOSS`(部分丢包)、`SSH_ERROR`(采集失败)、`TOOL_ERROR`(工具不可用)、`BLOCKED`(解析到受限地址)。
  SQLite 改不了 CHECK,三张表按「建新表 → 拷数据 → 先删子表再删父表 → 改名」重建,外键不会级联删掉历史;
* 迁移**不创建任何公共目标**、不改动已有入口目标,升级之后不会自动开始任何探测。

## 3. 调度与执行

* 新的出站引擎每 15 秒看一次:按节点汇总「到期」的目标(各目标自己的间隔),**每台机器一次 SSH 执行跑完全部到期目标**;
  机器之间并发上限 4;
* 用连接池的**非阻塞取锁**(`TryDo`):节点正在部署 / 同步 / 巡检时本轮直接跳过、15 秒后再试,不排队等锁;
  辅助程序整轮有硬上限(约 6 秒),锁不会被长期占用;
* 跳过与失败分开记:云实例停着 → 未执行;节点停用 → 不探测;架构未知或主控没有对应二进制 → 工具不可用;
  SSH 连不上 → 采集失败(**所有到期目标记「采集失败」,不记 100% 丢包**);辅助程序本身报错 → 工具不可用;
  域名解析失败 → DNS 失败;只有真正发出去的包 / 连接才进丢包率与失败率;
* 延迟在 VPS 本机测量:ICMP 是每包往返时间,TCP 是 `connect()` 三次握手时间,都不含 SSH 耗时。

## 4. 统计与告警(复用现有窗口、汇总、告警状态机)

* ICMP:平均 / 最小 / 最大 RTT(按收到的包加权),**丢包率 = Σ(发送 − 收到) ÷ Σ发送**;
* TCP:连接 RTT、成功率与失败率(分母 = 实际发起的连接);
* 1h / 24h / 7d 历史与点阵复用 `bucketize` / `Sum` / 小时汇总;点阵多两种颜色:采集失败、工具不可用;
* 告警沿用 `decideAlert`:一整轮全部丢包 / 连接失败 / DNS 失败算一次失败;**部分丢包算可达**(清零连续失败计数,
  DOWN 时触发恢复 —— 它说明目标能到,丢多少由丢包率另外回答);采集失败、工具不可用、目标受限、未执行不改变计数;
  推送正文分「出站」与「入口」两种说法;
* ICMP 一个包都发不出去(没有路由、机器没有 IPv6 出口)按「这一轮打算发的包全丢了」记,与 ping 一致 ——
  只记真正发出去的几个的话,这一轮在丢包率里的分量比正常轮次小,丢包率会被稀释。

## 5. 安全

* 公共目标只有管理员能建(管理端会话);主机名按严格规则校验,IP 字面量是回环 / 私网 / 链路本地(含云元数据
  169.254.169.254)/ CGNAT / 组播 / 保留段时默认拒绝;端口默认拒绝邮件(25 / 465 / 587)与 SMB / NetBIOS(135–139 / 445);
  每个目标可以显式勾「允许受限地址与端口」;
* 目标经 stdin JSON 交给辅助程序,不进命令行;辅助程序在解析之后再检查一遍(域名解析到内网同样拒绝);
* 每轮包数、间隔、超时都有上限,单个目标每轮最多 10 个包、间隔不小于 30 秒。

## 6. 修改范围

| 位置 | 内容 |
|---|---|
| `cmd/litebox-probe/` | 辅助程序(JSON 进出、ICMP / TCP、受限地址检查) |
| `internal/netprobe/` | 辅助程序与主控共用的测量与分类代码(无重依赖) |
| `internal/probe/` | 公共目标库与绑定、出站引擎、统计字段扩展、入口引擎只取 INGRESS |
| `internal/sshx/` | `TryDo`(非阻塞取锁)、`RunInput`(带 stdin 执行) |
| `internal/httpapi/` | 公共目标 CRUD、批量启用、单节点开关;节点网络与卡片聚合接口区分出站 / 入口 |
| 迁移 `0041_outbound_probe.sql` | 见 §2 |
| `scripts/build-probe.sh`、`Makefile`、`scripts/litebox-install.sh`、配置 `probe_binary_dir` | 构建与分发辅助程序 |
| 前端 | 系统设置「公共探测目标」;卡片网络区按公共目标分行、入口连通性单列;节点详情网络监测分「出站网络质量」与「入口连通性」两块 |

不改动:套餐计费、续费、资产价值;入口探测的语义与历史。

## 7. 验证

* 自动化:Go 单测(辅助程序的 ICMP / TCP / DNS / 受限地址 / 超时;调度的批量、跳过、SSH 失败不记丢包、
  工具不可用、忙时跳过;迁移保留历史与外键;统计口径)、前端类型检查与构建、Playwright 回归;
* 本机 Docker(linux/amd64)里实跑辅助程序;
* 测试 VPS(Alpine / aarch64)真机:由本机隔离的 scratch 面板经 SSH 下发辅助程序并跑几轮公共目标,核对丢包与延迟、
  SSH 断开时的表现、锁占用时长;不碰生产机,不合并 master,不部署。
