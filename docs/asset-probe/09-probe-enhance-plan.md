# 探针系统增强三项 · 技术方案(V22.6)

需求见 `docs/开发计划/v22/探针系统增强-三项.md`:自建节点互测入站(PEER)、出站 HTTP(S) 请求响应检测、
卡片展示项的自定义名称。三项共用**一次迁移、一个执行器、一套统计**,不是三套互不相干的东西。

## 一、复用什么

| 现有模块 | 这次怎么用 |
|---|---|
| `litebox-probe` + `internal/netprobe` | 加 HTTP 测法;PEER 的 Ping / TCPing 就是它已有的 ICMP / TCP 建连 |
| 出站引擎 `OutboundEngine` | PEER 序列按「拨测来源机器」并进那台机器这一拍的批次:**一次 SSH 执行同时跑它自己的出站目标与它替别人测的 PEER 目标**,不为每个目标单独建连 |
| `sshx.Pool.TryDo` | 不变:来源机器正忙就整批让路,什么都不记 |
| 主控入口引擎的引用解析(`topology.resolve`) | PEER 的被测地址与主控入口检测同一份白名单(订阅入口,不含管理通道),每轮重新解析,变了就换代 |
| `probe_results` / `probe_hourly` / 点阵 / 历史 / 告警状态机 | 三项全部沿用;HTTP 多一列状态码与四个状态码分类计数 |
| `probe_card_prefs` / `PickCards` | 别名存在偏好表里,PEER 进入站候选 |

## 二、功能一:PEER(自建节点互测入站)

- **序列**:`probe_targets` 一行 = 被测节点(`node_id`)× 被测入口(`ref`)× 拨测来源(`peer_node_id`)× 测法。
  `direction = INGRESS`、`source = PEER`、`kind = SERVICE`;Ping 记 `protocol = ICMP`(口径 LOSS:ICMP 丢包率),
  TCPing 记 `protocol = TCP`(口径 CONNECT:TCP 连接失败率)。与主控、Boce、节点本机的序列各自独立,不合并计算。
- **执行**:出站引擎每拍把到期的 PEER 序列按 `peer_node_id` 归到来源机器的批次里,与那台机器的出站目标一起交给
  `litebox-probe`;结果按序列 id 落回被测节点的入站序列。间隔继承入口检测的全局间隔(首期不做每个来源独立调度)。
- **不冒充**:来源与被测节点必须不同;来源连不上 / 辅助程序不可用记「采集失败 / 工具不可用」,**不进分母、不改连续失败计数**,
  绝不记成被测节点 100% 丢包;来源或被测节点停用、云实例停着记「未执行」;不触发任何重启或部署。
- **限额**:PEER 目标不是第三方目标,不占第三方预算;但计入来源机器那一拍的单轮上限(`RoundMax` / `MaxTargets`)。
  来源节点「暂停本机出站探测」时,它替别人测的 PEER 也一起停(那是这台机器的负载开关)。
- **管理**:节点详情「入口连通性」下多一块「自建节点拨测」:多选来源节点、选被测入口、勾 Ping / TCPing(可两种都要),
  每个「来源 × 测法」各建一条序列;可单独暂停 / 启用 / 删除,可「立即检测」一次(结果照常进历史)。

## 三、功能二:出站 HTTP(S)

- **测法**:`protocol = HTTP`,目标是完整 URL(`http://` / `https://`,可带端口、路径、查询)。GET,不跟随跳转,
  收到响应头即结束、立刻关 Body;HTTPS 校验证书与主机名;不读 `HTTP_PROXY` 这类环境变量;不调 curl / wget。
- **计时**:从发起请求(含 DNS 解析)到收到完整响应头。叫「HTTP 响应耗时」,不叫 RTT。
- **判定**:取得任何 HTTP 响应(200 / 204 / 3xx / 403 / 404 / 429 / 5xx)都是 OK,记耗时与状态码;5xx 另标
  「服务返回异常状态」(点阵上琥珀色,不冒充正常)。没取得响应的:连接被拒 / 网络不可达 / 超时 / TLS 错误 /
  响应格式无效都记失败,错误文本按类写明。**DNS 失败沿用全站口径:单独计数,不进分母**(与其他三种出站测法一致)。
- **口径**:`metric = HTTP`,「HTTP 请求失败率」= 未取得有效响应的次数 ÷ 实际发出的请求数;与 ICMP 丢包率、
  TCP 连接失败率、握手无应答率、Boce 两种丢包率名字不同、不相加。
- **安全**:URL 不收账号密码;受限地址与端口照旧拦(解析后再查一次,并且**只连那个查过的 IP**,防 DNS 重绑定);
  目标库、来源授权、节点覆盖、限额、试测全部沿用。URL 的查询串不进日志、推送与审计(只写到路径)。
- **数据**:`probe_public_targets` 加 `url`,超时上限对 HTTP 放宽到 10 秒;协议与地址族创建后不可改,改 URL 就换代。
- **协议**:辅助程序升到 v3,仍认 v1 / v2 请求。V15 的部署拨测(`deployment/httpprobe.go`)一个字不动。

## 四、功能三:卡片展示名称

- `probe_card_prefs` 加 `ingress_aliases` / `outbound_aliases`(JSON:序列 id → 别名)。别名按「被测节点 × 方向 × 序列 id」保存,
  只影响这台节点的卡片;与展示方式(自动 / 手动)、排序解耦,改名不碰任何检测、历史与告警。
- 卡片显示别名,悬停仍能看到原始名称、来源与测法;比例那一行的口径名不被覆盖。别名最长 24 个字符,空 = 原始名称。

## 五、迁移 0045

`probe_public_targets`、`probe_node_bindings`、`probe_targets`、`probe_results`、`probe_hourly` 照 0043 的顺序重建一次
(SQLite 改不了 CHECK):先建新表、全量拷贝,先删子表、后删父表,最后改名。存量数据一行不少、含义不变;
`probe_card_prefs` 只加列。迁移不建任何 PEER 序列、不建任何 HTTP 目标、不打开任何开关。

## 六、交叉影响

1. 入站列表 `List` / `ListAll` 只给主控那一类;PEER 与 Boce 一样单独一个字段返回。主控引擎只取 `source = MASTER`。
2. 出站统计按 `metric` 起名;HTTP 的状态码分类只对 HTTP 序列有值,不影响 ICMP / TCP / SYN 的任何数字。
3. 别名只在展示层,`PickCards` 与引擎都不读它。
