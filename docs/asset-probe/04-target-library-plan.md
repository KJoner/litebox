# 公共探测目标库与预置目标来源:调研与方案(V22.2)

需求:在 V22.1 出站网络质量探测的基础上,把「公共探测目标」做成一个可自由配置、可批量应用、可扩展来源的目标库;
增加 Zstatic 预置与 TcpQuality 动态导入两个来源;评估并实现不需要 root 的 TCP 握手近似探测。
不完整移植 NetQuality / TcpQuality 的脚本,不改计费、续费、资产价值。

## 一、参考项目调研

### NetQuality(xykt/NetQuality,AGPL-3.0)

* 三网 TCP 测试的目标由 `ref/province.json` 的省份代码拼出:`{省份代码小写}-{ct|cu|cm}-v{4|6}.ip.zstaticcdn.com`,
  只取 `province < 70`(31 个大陆省级行政区);路由测试固定北京 / 上海 / 广东三地;
* 测量是 `mtr --tcp -P 80 -f 100 -c 1`:首跳 TTL 拉到最大,只测终点那一跳。mtr 的 TCP 探测由内核发 SYN
  (流式套接字 + 非阻塞建连),量到的就是 TCP 握手时间;RST 也算「到达」;
* 我们**不复制它的代码与数据文件**:只用域名命名规则(事实)与 ISO 3166-2:CN 的省份代码(公开标准)。
  三方核对过:NetQuality 的 31 个省份代码、Zstatic 目录里的 31 个省级记录、我们的 `regions.go` 完全一致。

### Zstatic CDN 节点目录(www.zstaticcdn.com)

* 页面由 `/api/v1/DescribeAllNodes` 渲染(JSON,5 分钟缓存):`ProvinceNodes` 31 个(三网,端口 **80**)、
  `CityNodes` 223 个(端口 **443**,大部分是联通);目录里只有 IPv4 记录,`-v6` 省级域名有 AAAA 记录;
* 页面公告(原文要点):节点名称只作 IP 归属地展示;**仅供个人测试与研究参考**,不能作为网络质量评价、
  服务承诺、商业宣传或第三方结论依据;请在合法合规且获得授权的网络环境中使用,严禁扫描、压测、攻击、
  绕过访问控制或其他未经授权的用途;内容可能随时调整、限制或下线;
* 结论:可以作为候选来源,但它**不是无限制的监测服务** —— 默认不启用,对节点启用前要管理员确认授权,
  频率有下限(300 秒)与预算。

### TcpQuality(ibsgss/TcpQuality,GPL-3.0-only)

* `load_remote_nodes` 拉 `https://tcpquality.ibsgss.uk/getNodes?format=tsv&scope=…`,TSV 固定 12 列:
  `type family province isp host ip port target backup_host backup_ip backup_port backup_target`;
* 实测拉取一次(HTTPS 200,约 38 KB,Cloudflare,`Cache-Control: max-age=300`),解析出 278 行:
  `cdn` 186(IPv4 / IPv6 各 93)、`cernet` 31、`cernet2` 31、`tos` 19、`telegram` 10、`applecdn` 1;
  113 行带备用节点;
* `cdn` 行的 `target` 就是 Zstatic 的省级节点域名,`ip` 是作者中心服务预先解析好的地址,备用节点多是
  Zstatic 的市级节点;其余类型是大学官网、对象存储、Telegram DC 这类第三方业务站点,不是测速节点;
* 测量是 `nping --tcp --flags syn`(原始 SYN,需要 root / CAP_NET_RAW),每节点 25~600 个包;
* **使用条款**:代码 GPL-3.0,README 没有任何允许第三方程序调用 getNodes 的说明。结论:只做「管理员手动拉取
  → 预览差异 → 存到本地」,不做定期同步;首版只收 CDN 类。

## 二、实测:现有协议能不能测这些目标

测试 VPS djj-ph(Alpine 3.24 / aarch64 / NAT 容器,root 没有 CAP_NET_RAW),用 V22.1 的辅助程序,单轮:

| 目标 | TCP 建连 | ICMP |
|---|---|---|
| 北京 / 上海 / 广东 × 三网省级(:80) | 9/9 成功,RTT 163~272 ms | 5 个一包不回、2 个部分回(1/4、3/4)、2 个全回 |
| 市级 3 个(:443) | 3/3 成功 | 2 个一包不回 |
| IPv6 省级 | 无 IPv6 路由 → 正确记为「网络不可达」 | — |

* **TCP 建连能直接用**,与 NetQuality 的 TCP 测试是同一类测量;
* **ICMP 不可靠**(第三方节点普遍限速或不回 ping),所以 Zstatic / TcpQuality 预置只生成 TCP 目标;
* **关键发现**:14 次建连里有 2 次耗时约 1.2 秒 —— 第一个 SYN 丢了,内核 1 秒后重发。TCP 建连会把
  SYN 丢失藏成一次延迟尖峰,连接失败率反映不出来。这是增加「握手近似」的直接理由;
* DNS:IPv4 的解析结果在主控、测试 VPS 与 TcpQuality 列表三处一致(不是按地域返回),可以直接用域名做目标。

## 三、方案(已与用户确认)

1. **目标库**:`probe_public_targets` 加来源、上游标识、地区 / 省 / 市 / 运营商、TCP 方式、验证状态、
   上游快照、手工改过的字段;新表 `probe_sources`、`probe_node_settings`。迁移 0042 只加列、加表。
2. **来源**:自定义 / Zstatic(省级本地生成 + 读目录得到市级,端口按记录)/ TcpQuality(只收 CDN 类,
   手动拉取,上游改动逐条确认,手工字段不覆盖,消失只标记,上游不可用时不动目标库)。第三方来源一律
   授权确认 + 默认不对任何节点生效 + 管理员手动选目标;授权确认只是管理员的声明,不能替代来源方授权。
   主机属于已知第三方后缀的自定义目标照样归到那个来源。
3. **开关优先级**:全局关闭 > 目标暂停 > 来源暂停 > 来源未确认授权 > 本机暂停 > 选择(节点覆盖优先于
   「全部节点」)。单节点只提供暂停与间隔覆盖,不能强开。
4. **频率与预算**:第三方来源最小间隔默认 300 秒,没有声明更高频率许可时不能调低,有许可也不低于 60 秒;
   单台节点最多 12 个第三方目标;全站每分钟最多 120 次实际探测尝试(ICMP 按包、握手近似按次、建连按次);
   单目标全站限流(每分钟、每节拍);超出的延后执行,不记任何结果、不算失败;首次探测错峰、每轮抖动;
   同时执行的机器数与单轮目标上限可配。
5. **TCP 握手近似**:每次只等一个 SYN 的应答(截止 900 ms,早于内核 1 秒的首次重发),每轮 1~10 次;
   普通 SOCK_STREAM 套接字,不需要 root;从 TCP_INFO 读内核重发次数照实计数。它**基于系统 TCP 建连,
   不是原始套接字的 SYN 探测**,口径叫「握手超时无应答率」,不能叫丢包率。
6. **四类指标分开**:ICMP 真实丢包率 / TCP 连接失败率 / TCP 握手超时无应答率 / DNS、SSH、工具异常
   (后者不进任何分母)。RST 是应答(不进无应答率),但这一轮单独记「端口拒绝」。
7. **辅助程序协议 v2**:同时认 v1 请求(按 v1 回话、全部按建连测),面板回滚时节点上的新文件照样能用;
   上传后问一次版本,主控分发旧文件时给出能照着做的提示。

## 四、改动范围

* 数据库:迁移 0042;
* 后端:`internal/netprobe`(v2、握手近似、Linux 的 TCP_INFO 实现)、`internal/probe`(来源、门禁、限额、
  预算、错峰、目标库导入 / 同步 / 验证、试测)、`internal/settings`(四项调度限额)、`internal/httpapi`(新接口与审计);
* 前端:新页面「探测目标库」、节点详情「网络监测」的目标选择器与本机覆盖、节点列表的批量应用、
  所有比例按 `metric` 起名;
* 测试:迁移、门禁、限额、预算、错峰、解析、同步、导入、验证、试测、握手近似的计数、v1 兼容、拉取器安全,
  以及 Playwright 用例与截图基线。
