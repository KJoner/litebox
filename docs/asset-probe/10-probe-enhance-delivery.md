# 探针系统增强三项 · 交付记录(V22.6)

需求见 `docs/开发计划/v22/探针系统增强-三项.md`,方案见 `09-probe-enhance-plan.md`。三项共用一次迁移(0045)、
一个执行器(出站引擎 + `litebox-probe`)与一套统计(`probe_results` / `probe_hourly` / 点阵 / 历史 / 告警):

1. **自建节点互测入站(PEER)**:选别的自建 VPS 当拨测来源,对这台机器的订阅入口做 Ping / TCPing;
2. **出站 HTTP(S)**:探测目标库里新增 HTTP(S) 测法,任何有效 HTTP 响应都计时并记状态码;
3. **卡片显示名称**:每台节点的卡片上,入站 / 出站每一项都可以单独起名,只改展示。

## 一、自建节点互测入站(PEER)

| 项 | 做法 |
|---|---|
| 序列 | `probe_targets` 一行 = 被测机器(`node_id`)× 订阅入口(`ref`)× 来源机器(`peer_node_id`)× 测法;`direction = INGRESS`、`source = PEER`、`kind = SERVICE`。Ping 记 `protocol = ICMP`(口径 LOSS)、`resolved_port = 0`;TCPing 记 `TCP`(口径 CONNECT) |
| 执行 | 出站引擎每拍把到期的 PEER 序列按 `peer_node_id` 并进**来源机器**那一拍的批次 —— 一次 SSH 执行同时跑它自己的出站目标与它替别人测的 PEER 目标;`TryDo` 正忙就整批让路、什么都不记 |
| 间隔 | 继承入口检测的全局间隔与超时(首期不做每个来源独立调度);Ping 每轮 4 个包、间隔 500 ms |
| 目标白名单 | 与主控入口检测同一份(`Candidates`),只收对外服务入口,**不含管理通道**;每轮按引用重新解析,地址变了换代(Ping 只看地址),引用失效标 INVALID 停测;受限地址检查照做(订阅地址解析到回环 / 私网时来源测到的是它自己,冒充不了公网入站质量) |
| 不冒充 | 来源与被测机器必须不同(写入时拒绝、迁移 CHECK 再拦一次);来源连不上记 `SSH_ERROR`、辅助程序不可用记 `TOOL_ERROR`,**不进分母、不改连续失败计数、不告警**;被测或来源的云实例停着记 `SKIPPED`(原因码 `CLOUD_STOPPED` / `PEER_SOURCE_STOPPED`);来源停用或暂停了本机探测时不测(那是这台机器的负载开关);任何结果都不触发重启或部署 |
| 上限 | 一台被测机器最多 24 条,一台来源机器最多替别人测 32 条,一次新建最多 16 台来源;计入来源机器那一拍的单轮上限(`RoundMax` / `MaxTargets`),不占第三方预算 |
| 管理 | 节点详情「网络监测」新增「自建节点拨测」一块(`NodePeerPanel.vue`):多选来源、选入口、勾 Ping / TCPing(可两种都要)、周期检测开关;每条可「立即检测」(结果进历史、过告警状态机)、暂停 / 恢复周期检测(暂停后仍可手动测)、删除;来源筛选多一项「自建节点(入站)」 |
| 分开 | `List` / `ListAll` 只给主控的;PEER 由 `ListPeer` / `ListAllPeer` 给,接口单独的 `peer` 字段;主控引擎只取 `source = MASTER`;删节点时连它替别人测的序列一起删(`DeleteByNode` 加 `peer_node_id`) |
| 卡片 | PEER 进入站卡片候选;自动推荐按来源机器分覆盖键(`PEER:<id>`),排序在主控对外服务与 Boce 之后、管理通道之前 |
| 推送 | 说法单独一类:「从另一台自建机器连不上这个入口,不等于用户全部断线」,来源写机器名,不带地址 |

## 二、出站 HTTP(S)

| 项 | 做法 |
|---|---|
| 测法 | `protocol = HTTP`,目标是完整 URL(可带端口、路径、查询)。GET,不跟随跳转(`ErrUseLastResponse`),收到响应头即结束、立刻关 Body(不下载正文);HTTPS 校验证书与主机名;`Proxy: nil`(不读 `HTTP_PROXY` 之类);只用标准库 `net/http`,不调 curl / wget |
| 计时 | 从解析之前到收到完整响应头(含实际发生的 DNS、建连、TLS、发请求、等响应头),叫「HTTP 响应耗时」;总超时 200~10000 ms(默认 5000),超时不编 0 ms |
| 判定 | 取得任何 HTTP 响应都是 OK(200 / 204 / 3xx / 403 / 404 / 429 / 5xx),记耗时与状态码;**5xx 另外标出来**(点阵琥珀色 `HTTP5XX`、卡片状态 `HTTP_5XX`、历史异常列表写「HTTP 503(服务返回异常状态)」),不冒充正常也不算请求失败 |
| 错误分类 | DNS 失败 → `DNS_ERROR`(全站口径:不进分母);连接被拒 / 不可达 → `REFUSED` / `UNREACHABLE`;超时按阶段写「连接超时 / TLS 握手超时 / 等待响应头超时」;TLS → 「证书不受信任 / 与主机名不符 / 已过期 / 握手失败(对端不是 TLS)」;协议 → 「响应不是有效的 HTTP / 响应头之前断开 / 响应头超过 64 KB / 状态码不合法」。错误文本不带 URL |
| 口径 | `metric = HTTP`,「HTTP 请求失败率」= 没取得有效响应的次数 ÷ 实际发出的请求数;404 不算失败。小时汇总多 `http_2xx` / `http_3xx` / `http_4xx` / `http_5xx`,明细多 `http_status`;只对 HTTP 序列有值,ICMP / CONNECT / SYN 的数字一个不变 |
| 安全 | URL 只收 http / https,**不收账号密码**;主机与端口由 URL 推出来(表单上填的不算);受限地址与端口照旧拦,解析之后**只连查过的那个 IP**(`DialContext` 不看 URL 里的主机,防 DNS 重绑定);URL 的主机属于第三方后缀时归到那个来源(授权、限额照旧);查询串不进日志、推送与审计(`netprobe.RedactURL`,只写到路径);页面列表上也只显示到路径 |
| 数据 | `probe_public_targets.url`(唯一键加 URL:同一主机不同路径是不同目标);协议、地址族创建后不可改,**http 与 https 不能互换**(TLS 进不进耗时);改 URL(哪怕只是路径或查询)换代(`resolved_url`) |
| 其余沿用 | 目标库、来源授权、应用范围、节点覆盖、本机间隔、限额(HTTP 每轮算 1 次尝试)、试测(结果带状态码,5xx 写 WARN)、CSV 导入(多一列 `url`,填了就是 HTTP;名字默认用去掉查询串的 URL) |
| 辅助程序 | 协议升到 **v3**(`proto = HTTP`、`url`、`http_status`),仍认 v1 / v2 请求(v1 / v2 里的 HTTP 目标按不认识的协议拒绝,不按新语义跑);面板按 sha256 认出文件换过了自动重传 |
| 不动的 | V15 的部署拨测 `deployment/httpprobe.go` 一个字没改(仍要求 2xx / 3xx);新的「任何响应都计时」只用于出站 HTTP 网络质量检测 |

## 三、卡片显示名称

* `probe_card_prefs` 加 `ingress_aliases` / `outbound_aliases`(JSON:序列 id → 名称),按「被测节点 × 方向 × 序列 id」存;
* 保存时为 nil = 保持原样,空对象 = 全部清掉;键必须是这台节点那个方向的序列(属于别的节点 / 方向 400,已经删掉的序列静默丢掉);
  名称去首尾空白、最多 24 个字符、不收控制字符;空 = 原始名称;
* 与展示方式(自动 / 手动)与顺序解耦:切模式、调顺序、移除一项都不动别名;全部自动且没有别名时这一行删掉;
* `PickCards` 与引擎都不读别名(`CardPick` 只把还存在的那几个带出去),改名不建序列、不改挑选、不改历史与告警;
  推送里用的仍是原始名称;
* 前端:「卡片展示设置」每一项下面一行名称输入框(显示原始名称作占位、字数、恢复默认按钮),底部一块预览
  (直接用卡片的 `ProbeRow` 渲染,与仪表盘一致);卡片上显示别名,悬停说明以「显示名称 X,原始名称:…」开头,
  键盘聚焦时名字整段展开;协议、来源、口径名不被别名覆盖。

## 四、迁移 0045

`probe_public_targets`、`probe_node_bindings`、`probe_targets`、`probe_results`、`probe_hourly` 照 0043 的顺序重建一次
(SQLite 改不了 CHECK):先建新表、全量拷贝,先删子表、后删父表,最后改名、重建索引。改动:

* 公共目标:加 `url`;协议多 `HTTP`;超时上限对 HTTP 放宽到 10000(ICMP / TCP 仍 ≤ 3000);唯一键加 `url`;
* 序列:加 `peer_node_id`(引用 `nodes`,硬删连带删)与 `resolved_url`;CHECK 分四支(主控、Boce、PEER、出站),
  PEER 必须有来源且不等于被测机器、不挂 Boce / 公共目标;HTTP 只出现在出站;PEER 的唯一索引
  `(node_id, ref, family, peer_node_id, protocol)`,主控那条部分索引排除 PEER;
* 明细加 `http_status`(0 或 100~599);小时汇总加四个状态码分类计数;
* `probe_card_prefs` 只加两列(默认 `'{}'`)。

存量数据一行不少、含义不变;迁移不建任何 PEER 序列、不建任何 HTTP 目标、不打开任何开关
(`TestProbePeerHTTPUpgradeKeepsEverything` 钉着,连外键级联一起)。

## 六、兼容性

* **辅助程序**:v3 认 v1 / v2 / v3 请求,按请求的版本回话。体积从约 2.9 MB 涨到约 6.4 MB(amd64)/ 6.0 MB(arm64)——
  编进了 `net/http` 与 `crypto/tls`;只在第一次或换版本时上传一次,跑完就退出,不常驻。升级后各节点在下一轮出站探测时
  自动换成新文件(主控上要先跑一次 `scripts/build-probe.sh`;没换的话那一轮报「工具不可用 …… 请重新执行 build-probe.sh」,不记成丢包);
* **数据库**:旧二进制(master,V22.5)能直接打开 0045 的库(实测:master 建库 → 新二进制迁移 → master 再打开,一致性检查通过);
* **前端体积**:JS 2405.4 → 2426.5 KB(+0.9%),CSS 488.5 → 491.7 KB(+0.7%),没有新增依赖。

**回滚到 V22.6 之前要先做两件事**:

1. 暂停或删除全部 HTTP 公共目标:旧版本的出站引擎会把 HTTP 序列按 v2 请求交给辅助程序,结果记成 ERROR
   (算失败、会告警);
2. 删除全部自建节点拨测(或 `UPDATE probe_targets SET enabled = 0 WHERE source = 'PEER'`):旧版本的入站列表
   (`source != 'BOCE'`)会把它们混进主控的入口目标一起显示(旧的主控引擎只测 `source = 'MASTER'`,不会去连它们)。

别名两列旧版本不读,留着无害。

## 七、没做的

* PEER 不做每个来源独立的间隔与时间表(继承入口检测的全局间隔);只走 UDP 的入口(Mieru UDP)不在候选里 ——
  候选与主控入口检测、Boce 共用一份,Ping 虽然只测地址,也没有为它单独放开;
* HTTP 不做内容匹配、POST、自定义请求头与认证,也不做「必须 2xx」的健康规则(那是 V15 部署拨测的事);
  每个阶段(DNS / 建连 / TLS / 首字节)的分段耗时没有单独存,错误分类写在每次失败的说明里;
* 别名只在卡片上生效,节点详情的列表与推送里仍是原始名称;
* 没有在任何真实节点上跑过 PEER 与 HTTP 测法(全部是本机 httptest 与假执行器)。
