# Boce 外部拨测加 Ping · 方案与交付(V22.5)

V22.3 接入 Boce 时只做了 TCPing(需求文档 `docs/开发计划/v21/探针系统增强.md` 第 588 行把
「Boce ICMP Ping 或其他类型检测」留给了以后)。这一版加上 Ping:Boce 的拨测点从各地区 / 运营商对节点订阅入口的
**地址**做 ICMP ping。

## 一、接口事实

官方文档(2026-10-19 核对):

| 接口 | 要点 |
|---|---|
| `GET /v3/task/create/ping?key=&node_ids=31,32&host=域名或IP` | 与 TCPing 的创建接口同形,区别只在 `host` 不带端口;一次只测一个 host;另有可选的 `node_type`(1 机房 / 2 路由器),面板不传 |
| `GET /v3/task/ping/{id}?key=` | 与 TCPing 的取结果同形:顶层 `{done, id, max_node, list[]}`,每项字段完全相同 |

真实接口实测(2026-10-19,管理员授权的临时 Key,隔离的 scratch 面板,1 个拨测点):

- 每轮每个拨测点 **5 个包**,单个拨测点约 12 秒出结果;
- `report_source` 是 Linux ping 的原样输出,统计行是 `rtt min/avg/max/mdev = a/b/c/d ms`(比 TCPing 多一个 mdev);
- **Ping 的 `round_trip_avg` / `round_trip_max` 没有对调**(TCPing 的是对调的)—— 两种都以原始输出为准,一处规则;
- `packet_loss` 是百分数,与「0% packet loss」对得上;
- 每拨测点每次实扣 **1 波点**,与 TCPing 相同,估算不用分开。

## 二、设计

**测法是任务的属性,创建后不可改。** 换测法就是另一条测量,旧的点阵与丢包率与它不可比;要换就复制任务
(复制时可以选别的测法)。客户端 `internal/boce` 里测法是一个参数(`boce.Method`),不是两套代码 ——
两个接口形状一样,各写一份的话,脱敏、校验、RTT 那几条规矩迟早只在其中一套上生效。

**口径单列**:`metric = BOCE_PING`,叫「Ping 丢包率(Boce)」,按 Boce 报告的包数自己算。它与节点本机测公共目标的
ICMP 丢包率(`LOSS`)方向相反、测点不同,与 Boce TCPing(`BOCE`)也不是一回事 —— 三者名字不同、不相加。
很多机器或线路本来就不回 ICMP,**ping 不通不等于入口不可用**,界面与推送都写明这一点。

**Ping 只测地址**:提交给 Boce 的 host 只有地址;序列里记的端口一律是 0 —— 入口换了端口而地址没变时,
ping 测的还是同一个东西,不换代、不把历史切成两段。被测目标仍然只能是这台节点的订阅入口(与 TCPing 同一份白名单,
不含管理通道);IPv6 入口照旧列出来但选不了(两份文档都没有说明支持 IPv6,不改用 IPv4 去测)。

**迁移 0044**:

1. `boce_tasks.test_type`(`TCPING` / `PING`)。0043 那一列 `check_type` 的 CHECK 只收 `TCPING`,SQLite 改不了 CHECK,
   而重建 `boce_tasks` 要连带重建它的全部子表 —— 所以 `check_type` 冻结(恒为 `TCPING`,没有代码再读它);
2. `boce_runs.test_type`:每一轮提交时的测法。取结果按它选接口(拿 Ping 的任务 ID 去问 TCPing 的接口,上游只会说任务 ID
   失效);任务删了、执行记录还在结算时,也只有这一列说得清它是哪种;
3. 三张探测表照 0043 再重建一次,只放宽一条 CHECK:Boce 序列的 `protocol` 可以是 `ICMP`。Ping 的序列记 ICMP,
   口径由 `source + protocol` 一处推出来,不必去联任务表。顺序照 0043:先建新表、全量拷贝,先删两张子表、后删父表,最后改名。

存量的任务、执行记录、序列与历史一行不动,全是 TCPing。迁移不建任何任务、不打开任何开关。

**不变的**:预算、幂等、三种创建结局、结果只保留 5 分钟、拨测点缓存、自动暂停、费用估算(每拨测点每次 1 波点)、
卡片展示偏好 —— 两种测法走同一套。

## 三、界面

- 新建 / 复制任务的表单最上面多一栏「检测类型」(TCPing / Ping),下面一句说明;编辑时锁定并写明「创建后不能更换,要换请复制任务」;
  选 Ping 时被测入口只显示地址;
- 节点详情的 Boce 任务行标出测法;拨测点行的比例按口径起名(`24h TCPing 丢包` / `24h Ping 丢包`);
  历史区的统计、点阵与曲线的悬停说明分开写;
- 批量应用的模板多一栏检测类型;卡片展示设置、仪表盘卡片的入站说明、「需要处理」与推送都按测法写。

### 真实 Boce 接口验证(2026-10-19,管理员提供的临时 Key,用完由管理员作废)

隔离的 scratch 面板(独立库与主密钥,结束后连库一起删掉),被测目标是测试 VPS 上的一个入口(只 ping 地址),
拨测点 1 个(上海电信 #42),预算设成每日 3、每月 5、单次 2 波点。

| 步骤 | 结果 |
|---|---|
| 校验 Key、同步拨测点 | 通过;大陆 94、海外 123 |
| 新建 Ping 任务 | 任务与执行记录的测法都是 PING;提交的 host 只有地址 |
| 手动检测一次 | 12 秒完成,5/5 收到,平均约 215 ms;序列记 ICMP、端口 0,口径 `BOCE_PING`,结果名「全部收到」 |
| 原始结果对照 | `rtt min/avg/max/mdev` 一行与库里的平均 / 最小 / 最大一致;Ping 的字段没有对调 |
| 实际消耗 | 余额 9996 → **9995,共 1 波点**,与面板估算一致 |
| 收尾 | 清空 Key、停面板、删 scratch 目录;仓库、临时目录、记忆文件与提交历史里搜不到这把 Key |

## 五、升级与回滚

升级:迁移 0044 自动执行,存量数据含义不变,不发任何 Boce 请求。

**回滚到 V22.5 之前先把 Ping 任务归档或删除。** 旧版本不认识 `test_type`:它读的是冻结的 `check_type`(恒为 TCPING),
会把 Ping 任务当成 TCPing、提交「地址:端口」去测 —— 测的就不是同一件事了。TCPing 任务不受影响;
数据库不用回退,旧二进制照样能打开 0044 的库。
