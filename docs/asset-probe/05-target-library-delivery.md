# 公共探测目标库:交付说明(V22.2)

调研与方案见 `04-target-library-plan.md`。本文写清做了什么、怎么测的、真机上量到了什么,以及升级与兼容性。

## 一、做了什么

### 目标库与来源

* 迁移 0042:新表 `probe_sources`(自定义 / Zstatic / TcpQuality)与 `probe_node_settings`;
  `probe_public_targets` 加来源、上游标识、地区 / 省 / 市 / 运营商、TCP 方式、验证状态、上游快照、手工改过的字段;
  `probe_targets` 加 `tcp_mode`;`probe_results` 加 `rtt_n`。只加列、加表,已有目标的含义一字不差;
* 目标库上限从 32 提到 1000;单台节点同时生效的目标最多 64 个,其中第三方最多 12 个(可配);
* **门禁**(`OutboundGate`):目标暂停 > 来源暂停 > 第三方来源未确认授权 > 本机暂停 > 选择;全局总开关最先。
  主机属于已知第三方后缀的手工目标归到那个来源;
* **第三方来源**:授权确认(记录人与时间、写审计,只是声明,不替代来源方授权)、暂停、最小间隔
  (默认 300 秒,声明更高频率许可后最低 60 秒)、单目标全站限流;
* **Zstatic**:省级 `{省份}-{运营商}-v{4|6}.ip.zstaticcdn.com` 本地生成(端口 80,默认勾北京 / 上海 / 广东,可扩到全国);
  读目录得到市级节点,端口按记录;
* **TcpQuality**:手动拉一次 getNodes,只收 CDN 类(含备用节点),逐列重新校验;按域名或按上游 IP 导入;
  差异预览(新 / 已在库中 / 上游有改动 / 已存在 / 上游已消失 / 被拒绝),上游改动默认不勾、可疑改动标出、
  手工改过的字段不覆盖、消失只标记;上游不可用时目标库不动,只标记来源状态;不做定期同步;
* **批量**:暂停 / 恢复 / 删除 / 应用到节点(换成这个集合)、CSV / TSV 导入(预览后提交)、主控侧 DNS 验证、
  节点列表勾选多台批量应用、节点详情的目标选择器与试测(不进历史)。

### 调度

* 全站每分钟第三方预算(默认 120 次实际尝试:ICMP 按包、握手近似按次、建连按次)、单目标每分钟限流与每拍上限;
  按计划先占、按实际结算;**超出的延后执行,不记结果、不推进到期时间、不算失败**;
* 第三方目标首次探测在 min(间隔, 5 分钟) 里按(机器, 目标)错峰,之后每轮 ±5% 抖动;
* 同时执行的机器数(默认 4)与单台节点单次执行的目标上限(默认 16)可配;
* 单台节点:暂停本机、覆盖间隔(不能低于来源下限)。

### TCP 握手近似与辅助程序 v2

* `tcp_mode = SYN`:每次最多等 900 ms(早于内核 1 秒的首次 SYN 重发),每轮 1~10 次,普通 SOCK_STREAM 套接字,
  不需要 root / CAP_NET_RAW,不装任何依赖。Linux 上从 TCP_INFO 读内核重发次数照实计入;
* **它基于系统 TCP 建连,不是原始套接字的 SYN 探测**;比例叫「握手超时无应答率」,不叫丢包率;
* 四种口径按 `metric` 起名:ICMP 真实丢包率 / TCP 连接失败率 / TCP 握手超时无应答率 / DNS、SSH、工具异常(不进分母);
  RST 是应答,全是 RST 时记「端口拒绝」;
* 辅助程序协议 v2,同时认 v1 请求;上传后问一次版本。

### 界面

* 新页面「探测目标库」(侧栏「运维」):来源卡片(说明与授权、预置与目录 / 同步、限额、暂停)、调度与限额、
  筛选(来源 / 地区 / 省份 / 城市 / 运营商 / 方式 / 地址族 / 状态)、批量操作;系统设置里留一个入口;
* 节点详情「网络监测」:只列这台机器在测或设过开关的目标,「选择公共目标」从目标库里挑并可试测,
  本机暂停与间隔覆盖;
* 卡片、点阵、曲线、历史统计、仪表盘「需要处理」都按 `metric` 起名。

## 三、真机验证(测试 VPS djj-ph:Alpine 3.24 / aarch64 / NAT 容器,root 没有 CAP_NET_RAW)

全部经本机隔离的 scratch 面板(独立库、只听回环);主机密钥用 known_hosts 里核实过的那把预置,没有接受任何新密钥。
第三方目标只测了北京 / 上海 / 广东的省级节点,间隔 300 秒,全程约 25 分钟;测完删除了节点上的辅助程序与本机的库、密钥、日志。

### 内核行为(握手近似的前提)

| 检查 | 结果 |
|---|---|
| 本机回环:在听的端口 / 没人听的端口 | SYN-ACK / RST,内核重发 0 次 |
| 黑洞地址(TEST-NET-3,不对应任何机器),900 ms 截止 × 3 | 都是「无应答」,TCP_INFO 读到的重发 **0** 次 |
| 同一地址,1500 ms 截止 | TCP_INFO 读到重发 **1** 次 —— 证明读数是真的,900 ms 内确实没有重发 |
| 实现 | `syn_impl = tcpinfo`,普通套接字,容器里 root 没有 CAP_NET_RAW 照样能跑 |

### 直接跑辅助程序(单轮)

| 目标 | 建连 | 握手近似(4 次) |
|---|---|---|
| 自有测试机的端口(对 djj-ph 回 RST) | 连接被拒绝 0/1 | 端口拒绝 4/4 有应答(RST),22 ms —— RST 算应答、单列状态 |
| 黑洞 | 连接超时 | 全部握手无应答 0/4 |
| Zstatic 北京三网(:80) | 3/3,171~198 ms | 3/4、4/4、4/4 —— 丢的那个 SYN 建连看不出来 |
| v1 请求(带 SYN) | 按建连测,按 v1 回话 | —— |

### 经面板的端到端(12 个 Zstatic 目标 + 1 个自定义 ICMP)

* **门禁**:来源未确认授权时批量启用 → 400(原因写清楚);确认授权后启用 12 个 → 成功;第 13 个第三方 → 409
  「单台节点最多对 12 个第三方目标启用,以下节点会超出:测试机(13 个)」;把第三方目标改成 60 秒 → 400;
  自定义 ICMP 不受第三方名额与下限约束;
* **错峰**:第三方目标的首次探测散在约 4.5 分钟里,每拍 1~3 个,没有一拍把 12 个一起打;之后每个目标约 5 分钟一次
  (实测间隔 4 分 53 秒 ~ 5 分 09 秒,即 ±5% 的抖动);自定义 ICMP 第一拍就测、之后每 60 秒;
* **开销**:8 分钟里 20 次 SSH 执行(一拍最多一次),每次约 1 秒;第三方预算用量约 5 次 / 分钟(上限 120),
  没有延后、没有采集失败;
* **数字**:ICMP 12.0~13.1 ms;Zstatic 建连 163~274 ms,握手近似 167~260 ms。第一批建连目标用了默认 1000 ms 超时,
  17 次里 4 次「连接超时」,而同期握手近似 24 次里 22 次有应答 —— 丢一个 SYN、内核 1 秒后重发,在 1 秒超时下就变成
  「连接失败」。**据此把第三方来源导入的建连目标默认超时改成 2 秒**(容得下一次重发):改完之后的一轮建连 1208 ms
  成功(一次重发 + 往返),这正是建连与握手近似回答的不是同一个问题;
* **单目标限流**:对同一个第三方握手近似目标连续试测,前 3 次(12 个 SYN)执行,第 4 次 429、没有发包;
  试测结果没有进历史(明细 45 → 45 行),验证状态写回目标库;
* **本机暂停**:13 条序列全部停下、状态写「本机已暂停出站探测」,2 分多钟里 0 次执行;恢复后照常;
* **审计**:授权 / 暂停、导入、批量、节点开关与覆盖、试测都留了记录。

## 四、辅助程序升级与兼容性

| 场景 | 实测结果 |
|---|---|
| 节点上是 V22.1 的 v1 辅助程序,面板分发 v2 | 第一拍按哈希发现不一致 → 先传 `.new` 再改名 → 问版本得到 2 → 照常探测;节点上没有残留、没有常驻进程 |
| 主控 `assets/probe/` 里换成旧的 v1 文件 | 下一拍把节点换回 v1,这一拍的 4 个目标全记「工具不可用:主控分发的 arm64 辅助程序是 v1,面板需要 v2:请在主控上重新执行 scripts/build-probe.sh」,发 / 收都是 0,不进任何比例 |
| 把 v2 放回去 | 下一拍自动重传 v2 并恢复 |
| 回滚:V22.1 的面板程序 + 已迁移到 0042 的库 + 节点上的 v2 辅助程序 | 面板正常启动(不认识的迁移被忽略、登录会话照常);v2 辅助程序按 v1 回话,探测照常 |
| 回滚的已知代价(实测) | 旧程序**无视来源暂停**,照常测了第三方目标;握手近似的两个目标被它当成建连测、样本记进了那两条序列。所以升级说明要求回滚前先把第三方目标批量暂停(目标本身的暂停旧程序认) |
| 回到新版本 | 照常启动;来源暂停重新生效,第三方目标立刻停测,只剩自定义目标 |

历史数据一致性:0042 只加列;旧明细的 `rtt_n` 为 0(= 等于收到数),与新代码的约定一致;协议、TCP 方式、地址族是
序列的身份,创建后不可改,所以建连与握手近似的样本不会在新版本里混进同一条序列(只有回滚期间那一种例外,见上)。

## 五、刻意没做的

* 没有原始套接字的 SYN 探测(nping / mtr 那种):要 CAP_NET_RAW,而这类 NAT 容器里 root 也没有;收益只是能量到
  900 ms 以上的应答;
* 没有 TcpQuality 的定期同步:README 没有允许第三方程序调用 getNodes;
* 没有非 CDN 类的批量导入(教育网、对象存储、Telegram、Apple CDN):它们是第三方业务站点;
* 不为第三方节点生成 ICMP 预置:实测大多限速或不回;
* 没有自动启用任何第三方目标,也没有在升级时替任何机器开启探测。
