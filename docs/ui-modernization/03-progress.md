* 删掉 V18 的弹窗三栏头:它依赖「底栏恰好两枚按钮」切换版式,同一类弹窗会出现两种形态。

**构建**:`vue-tsc` 通过,`vite build` 通过。JS 2135.6 KB(基线 2128.2,+0.3%),CSS 441.5 KB(基线 431.2,+2.4%)。

**自检**:仪表盘、节点列表、节点详情(深色)、用户抽屉 + 编辑弹窗(深色)、节点列表(390)、门户概览都能正常渲染,
所有入口仍在。

**遗留 / 对下一批的影响**

* 页面自己 scoped 的卡片(节点详情的 `.nd__card` 等)还没有边框,第三批随页面一起改。
* 节点列表手机视图是「卡片里套卡片」;门户的指标条依赖旧 `.lb-metrics` 的卡片外观 —— 分别在第三、四批处理。

**修掉的既有问题**

* 仪表盘把代理源 / 外部代理的预警当成「节点」,点「查看节点」跳到 `/nodes/<源的 id>` —— 一台不相干的机器。现在跳到外部代理页。
* 节点详情在 390 宽的横向溢出(第一批记录的 423px):五个 Tab 逐一检查,`scrollWidth` 都是 390。
* 手机上页面头部的按钮组按内容宽度排成一行,把最后一颗推出屏幕(`.lb-page__actions` 在窄屏改为占满一行并换行)。

**关键决策**

* 仪表盘「需要处理」把商家到期也收进来:后端预警只管「可用截止时间」,商家账单到期(V20)此前只在列表的一列里能看到。
  数据全部来自现有接口,只读库,不触发 SSH。
* 节点健康表用 CSS 栅格而不是 `a-table`:它不需要排序、分页与选择,而手机上要换成完全不同的卡片结构。
* 运行状态与配置状态在仪表盘与列表上仍是两个独立标签(V3 规则),服务巡检的各种结论沿用 `healthSummary.ts` 一处判据。

**构建**:`vue-tsc` / `vite build` 通过。JS 2147.9 KB(基线 +0.9%),CSS 450.4 KB(基线 +4.5%)。

**自检**:1440 浅 / 深、768、390 下仪表盘、节点列表、节点详情五个 Tab;390 宽五个 Tab 无横向溢出。

**遗留**:节点详情里的各种操作弹窗(探测结果、配置比对、TCP 调优、引导)只换了全局规格,没有逐个重排。
