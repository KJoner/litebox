# LiteBox 升级说明

## V1 → V2

V2 增加了普通用户门户、三档节点访问等级与节点展示名称。**存量库可以直接
升级,不需要任何手工数据处理。**

### 升级前

```bash
# 备份数据库(升级脚本也会自动做一次,但自己留一份更稳)
sudo -u litebox /opt/litebox/litebox backup --config /etc/litebox/litebox.yaml

# 确认主密钥还在,并且你手上有一份
sudo cat /etc/litebox/litebox.env
```

主密钥丢失后用户 UUID 与节点 REALITY 私钥不可恢复,数据库备份救不回来。

### 执行升级

一键脚本部署的:

```bash
bash <(wget -qO- https://raw.githubusercontent.com/KJoner/litebox/master/scripts/litebox-install.sh)
```

手工部署的:

```bash
sudo ./scripts/upgrade.sh
```

两者都会先备份、再替换二进制、启动时自动执行迁移;失败自动回退。

### 升级做了什么

新增四个迁移(0007~0010):

| 迁移 | 做的事 |
| --- | --- |
| 0007 | 建 `access_tiers` 并写入 NORMAL/VIP/ROOT;给用户与节点加 `access_tier_id`;建 `user_effective_nodes` 视图 |
| 0008 | 给节点加 `display_name` 等对外字段,并把 `display_name` 从 `name` 复制过来 |
| 0009 | 建 `portal_accounts` / `portal_sessions` / `portal_login_attempts` |
| 0010 | 建 `user_adjustments` |

### 升级后会发生什么变化

**默认什么都不变。** 存量用户与存量节点全部落在普通组,而普通组用户本来
就能用到全部普通组节点 —— 升级后每个用户的可用节点集合与升级前完全一致。
`internal/database/upgrade_test.go` 逐条守着这一点。

具体地:

* 订阅内容不变。节点名沿用原来的名字(`display_name` 复制自 `name`),
  客户端不会把它当成新节点重复添加;
* 订阅地址不变,用户不需要重新导入;
* 流量、ledger、累计用量、部署记录一行不动;
* 管理员账号与已登录的会话不受影响;
* `user_nodes` 里的分配关系全部保留,继续作为"额外授权"生效;
* 没有任何用户拥有门户登录账号 —— 门户要由管理员逐个开通。

### 升级后建议做的三件事

**1. 给节点分组(可选)**

节点管理 → 编辑 → 访问等级。不改就是所有人都能用,与升级前一样。

改等级会**自动触发重新部署**(会重启该节点的 sing-box,断开在线连接),
因为等级调高后被移出的用户凭据还留在节点上,不重新部署等于权限没收回。
挑一个低峰时段做。

**2. 把内部名称与展示名称分开(可选)**

如果节点的内部名称里写了机房、供应商、到期日这类运维信息,现在可以把
`name` 改成运维视角的名字,`display_name` 留给用户看。改 `display_name`
不需要重新部署,但客户端要更新一次订阅才会看到新名字。

**3. 开通门户登录(可选)**

用户管理 → 详情 → 门户登录 → 开通。设一个账号名和初始密码,勾上
"要求用户首次登录后修改密码",然后把 `https://你的域名/user/login`
和初始密码通过安全渠道发给用户。

不开通也完全不影响使用 —— 用户照常用订阅地址。

### 回滚

升级脚本在替换前会备份数据库与旧二进制。若要回到 V1:

```bash
sudo ./scripts/restore.sh /var/backups/litebox/litebox-<时间戳>.db
```

注意 V2 迁移是**单向的**:V1 的二进制读 V2 的库会因为 `schema_migrations`
里有它不认识的版本而正常运行(迁移框架只跳过已应用的版本),但 V2 新增的
列与表对它没有意义。稳妥做法是二进制与数据库一起回滚。

## V2 → V2.1

V2.1 增加了节点的可选 IPv6 订阅地址,以及节点级的流量额度与重置周期。
**存量库直接升级,不需要任何手工数据处理,行为一个字节都不变。**

升级方式与下面的「日常升级」完全相同。

### 升级做了什么

新增一个迁移(0011),给 `nodes` 加四列:

| 列 | 默认值 | 含义 |
| --- | --- | --- |
| `ipv6_address` | `''` | 空串即 IPv4-only,与升级前一致 |
| `traffic_quota_bytes` | `0` | 0 即不限量 |
| `traffic_reset_cycle` | `'NONE'` | 不重置,统计创建以来的累计流量 |
| `traffic_reset_day` | `1` | `NONE` 时不起作用 |

`host` 的业务含义明确为「IPv4 地址及 SSH 管理地址」,列名没有改动,
所有存量数据原样保留。

### 升级后会发生什么变化

**默认什么都不变。** 存量节点全部是 IPv4-only、不限量、不重置:

* 订阅内容一条不多一条不少,用户不需要重新导入;
* SSH、探测、安装、部署、重启、流量同步、资源采集全部照旧走 `host`;
* 流量统计、ledger、每日汇总、部署记录一行不动;
* 节点列表多出一列「周期流量」,不限量节点显示为「已用量 / 不限量」。

一个例外值得知道:**用域名接入的存量节点**在编辑时,只要不改「IPv4 地址」
这一栏就照常保存;真要改这一栏时会要求填 IPv4 字面量。

### 升级后可以做的两件事

**1. 给双栈节点填上 IPv6(可选)**

节点管理 → 编辑 → IPv6 地址。填完保存即可,**不需要重新部署**,
也不会断开任何在线连接。订阅里随即多出一条 `展示名称-IPV6`,
用户的客户端下次更新订阅就能看到。

清空这一栏则把该条目撤下来,同样即时生效。

**2. 给节点设流量额度(可选)**

节点管理 → 编辑 → 节点流量限额 / 重置周期 / 每月重置日。
周期边界统一取 **UTC 00:00**,页面上标了出来。

额度只用于统计与预警:超额会在仪表盘和节点列表里标红,但**不会**
停掉 sing-box、禁用节点或把节点从订阅里摘掉 —— 流量同步存在时间间隔,
各家 VPS 的计量口径也不一致,自动关掉一个共享节点会同时打断全部用户。

设额度不影响任何历史数据。改重置日、改周期都只是换了统计起点,
`traffic_ledger` 一行都不会删,改回去也能还原。

## V2.1 → V3

V3 是一次整体 UI 改造。**没有数据库迁移,没有配置项变化,没有接口被删除或改名。**
升级方式与下面的「日常升级」完全相同,回滚也只是把二进制换回去。

### 升级做了什么

界面全部重写:统一的设计 Token、状态改成「形状 + 文案 + 颜色」三重编码、
每一页都区分加载 / 空 / 筛选为空 / 失败四种状态。三处接口是新增的,老接口一个没动:

| 接口 / 字段 | 说明 |
| --- | --- |
| `GET /api/traffic/daily` | 新增。全站每日流量,给仪表盘的趋势图 |
| `GET /api/nodes` 的 `config_state` / `needs_deploy` | 新增两个算出来的字段,纯查库,不连 SSH |
| `GET /api/users` 的 `next_reset_at` | 新增。与门户用的是同一份计算 |

有一处**行为**变化值得知道:每日流量序列(全站、按节点、按用户、门户)
不再把没有记录的日子补成 0,只返回确实有记录的那些天。库里没有某一天,
可能是那天真的没人用,也可能是同步任务没跑完 —— 补 0 等于替其中一种下了结论。
现在缺的日子在图上画成空心柱并标明「未知」。历史数据一个字节都没有改动。

### 升级后会看到什么变化

* 侧栏由深色改成白底 + 1px 边线,菜单分成「总览 / 资源 / 运维」三组并带计数;
* 节点列表把「状态」拆成**运行状态**与**配置状态**两列 ——
  一台在跑旧配置、上次部署失败的机器,原来只显示「部署失败」,
  看不出它其实还在正常服务用户;
* 节点详情原来是 12 个同样大小的按钮排成一排(只读的「探测」和会抹掉服务的
  「卸载服务」尺寸完全相同),现在分三层:只读检查在常驻工具条、部署是唯一主按钮、
  会改变节点的收进「⋯」且不可逆的四项在分隔线之下;
* 接口失败时指标卡显示「—」而不是 0。原来读不到和真的是零长得一模一样;
* 手机上打开管理后台,四张长表会换成卡片列表 —— 原来横向滚动会把最右边的
  「操作」列推到屏幕外;
* 用户门户的「订阅不可用」从一条 Alert 改成整块替换,并写清原因与恢复后的行为。

### 体积

前端产物从约 2MB 增加到约 7.3MB,增量全部是自托管的中文字体
(`Noto Sans SC` 两档,按 unicode-range 分片)。面板要 embed 进单个二进制、
也要能在断网内网里跑,所以不引 CDN。浏览器只下载页面上真正用到的那几片,
实际传输量远小于这个数字。

## 日常升级(V2 之后)

```bash
bash <(wget -qO- https://raw.githubusercontent.com/KJoner/litebox/master/scripts/litebox-install.sh)
```

再跑一遍就是升级:依赖不重装,数据库与主密钥不动,升级前自动备份。

升级后确认:

```bash
systemctl status litebox
journalctl -u litebox -n 30
curl -s http://127.0.0.1:8080/api/health
```

节点上的 sing-box **不会**因为主控升级而改变。需要重新下发节点二进制时,
在节点详情里点「安装」。
